# Feature Specification: 欠账集中清理轮（debt-cleanup）

**Created**: 2026-10-11  
**Status**: Draft  
**Input**: 用户决策合并轮：①删无图模式开关（尺寸分档+网络态降档已够，开关边际收益可忽略且覆盖不全致不一致）；②欠账 A：KI-3 首页左滑删除、KI-7 修 B4/B5（B3 保留登记，B7/B8/C2 无视）、KI-6 睡眠定时验证；③欠账 B：T013 降级走查、R9 US1-4 / R10 US1-3 验收、queue-redesign T031/T032、深浅色/主题色全页走查——全部模拟器验证（过即销项），测完关闭模拟器

## Overview

一轮清偿全部在册欠账。代码改动三项：删除无图模式开关及其全部分支（保留既有图片尺寸分档与网络态降档）、补齐 KI-3 最后一项（首页订阅列表左滑删除）、修复 KI-7 中方向明确的两项（B4 BV 全文扫描遮蔽复合 URL、B5 fav 弱启发式易误判）。验证欠账全部以模拟器执行：KI-6 睡眠定时、R9/R10 用户故事验收、queue-redesign T031/T032、T013 降级衔接走查、深浅色/主题色全页走查——验证通过即销项对应 PROJECT_NOTES 条目，测完关闭模拟器。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 删除无图模式开关 (Priority: P1)

用户打开设置页，「省流」分组中不再有「无图模式」开关；应用内封面照常按既有尺寸分档与网络态降档加载（缩略图 240 档、播放层大封面 Wi-Fi 大图档/非 Wi-Fi 省流档、系统播控同规则），开关与其全部生效分支从代码中移除。

**Why this priority**: 用户明确决策的产品删减；边际收益分析（图片占总流量 <2-5%，音频流主导）已确认开关价值不足，且当前覆盖不全（首页/源页不接开关）造成功能名不副实，删除即销项。

**Independent Test**: 设置页查看开关缺席 + 任意封面渲染正常 + 代码检索 `KEY_DATA_SAVER`/dataSaver 零残留，可独立验证。

**Acceptance Scenarios**:

1. **Given** 设置页打开, **When** 查看「省流」分组, **Then** 「无图模式」开关行不存在
2. **Given** 任意页面, **When** 查看封面渲染, **Then** 缩略图、播放层大封面、系统播控封面均正常加载，尺寸分档与网络态降档行为零回退
3. **Given** 代码全量检索, **When** 搜索无图模式相关键与分支, **Then** 存储键、开关状态、生效分支、随开关存在的重发方法全部零残留
4. **Given** 老版本用户升级, **When** 启动应用, **Then** 残留的旧持久化值不被读取、无任何异常（不主动清理）

### User Story 2 - 首页订阅列表左滑删除（KI-3 收尾） (Priority: P1)

用户在首页订阅列表左滑任一行，右侧露出「删除」按钮，点击后该订阅被退订（复用既有退订语义：清剧集缓存、持久化、刷新列表），列表即时移除该行。交互约定与播放历史/播放队列一致：左滑露出、点击执行、不做滑过阈值直删。

**Why this priority**: KI-3 三处清单的最后一处（播放历史/播放队列已完成），欠账在册最久的交互缺口；删除后 KI-3 整条可关闭。

**Independent Test**: 首页含 ≥2 个订阅，左滑一行点删除，可独立验证退订与列表刷新。

**Acceptance Scenarios**:

1. **Given** 首页订阅列表 ≥1 条, **When** 左滑任一行, **Then** 右侧露出「删除」按钮，样式对齐播放历史删除按钮
2. **Given** 左滑已露出删除按钮, **When** 点击删除, **Then** 该订阅退订（剧集缓存清理、持久化生效），列表即时移除该行
3. **Given** 左滑露出删除按钮后未点击, **When** 滚动列表或左滑其他行, **Then** 滑动状态自然复位，无半开按钮残留
4. **Given** 首页既有交互（点击行进源页、新集徽标静默刷新）, **When** 正常操作, **Then** 行为零回归

---

### User Story 3 - 链接识别修复：B4 调序 + B5 收紧（KI-7 部分） (Priority: P2)

用户粘贴含 BV 参数的合集/收藏夹复合链接时，识别为合集/收藏夹（不再被全文 BV 扫描遮蔽误判为单视频）；粘贴合法收藏夹链接仍正确识别，非收藏夹页面仅因文本含 fav 字样不再被误判为收藏夹。纯 BV 号文本、短链、av 号、UID 等既有识别零回归。

**Why this priority**: B4/B5 是 KI-7 中方向明确、可直接修复的两项误判缺陷；修后 KI-7 部分销项（B3/B7/B8/C2 按用户决策维持登记不动）。

**Independent Test**: 逐一输入复合链接、纯 BV、收藏夹链接、含 fav 字样的非收藏夹文本，可独立验证识别结果。

**Acceptance Scenarios**:

1. **Given** 含 BV 参数的合集/收藏夹 URL 输入, **When** 提交识别, **Then** 识别为合集/收藏夹，不再误判为单视频
2. **Given** 纯 BV 号文本输入, **When** 提交识别, **Then** 仍识别为单视频（零回归）
3. **Given** 合法收藏夹 URL, **When** 提交识别, **Then** 正确识别为收藏夹（合法形态不得因收紧而漏判）
4. **Given** 非收藏夹页面、但文本含 fav/collection/favlist 字样的输入, **When** 提交识别, **Then** 不再误判为收藏夹
5. **Given** 短链、av 号 URL、裸 UID 等既有识别输入, **When** 提交识别, **Then** 分类结果与现状一致（零回归）

### User Story 4 - 队列功能全量验证（R9 US1-4 + queue-redesign T032 US2/US4/US6） (Priority: P1)

在模拟器上逐场景验收播放队列既有实现：底部弹出形态与近实底可读性（R9 US1/US2）、双向过冲提示（R9 US3）、时长未知条目不显示 00:00（R9 US4）、左滑删除与手势共存（T032 US2）、清除已播两态语义（T032 US4）、单视频追加不打断与 toast 三型反馈（T032 US6）。验收场景逐条对齐各源 spec 的 Acceptance Scenarios。

**Why this priority**: R9/R10 为用户实机反馈产生的欠账，队列是其中改动最大的区域；queue-redesign T031/T032 挂账最久，用户已确认模拟器验证过即销项。

**Independent Test**: 模拟器部署后逐场景操作队列即可独立验收，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 播放页已打开, **When** 点队列按钮, **Then** 底部弹出全宽面板（约 65% 屏高、顶部圆角），点遮罩或返回键滑出关闭；首页打开行为一致（R9 US1）
2. **Given** 播放页封面高饱和, **When** 打开队列, **Then** 条目文字清晰可读，无封面色穿透（R9 US2）
3. **Given** 队列仅 1 条（未铺满）, **When** 按住列表向上/向下拖, **Then** 分别露出「已经到顶了」/「已经到底了」，松手回弹消失（R9 US3）
4. **Given** 条目 duration=0（合集/收藏夹入队未播过）, **When** 队列渲染, **Then** 第二行只显示 UP 主名，无 00:00；已播过条目显示「UP主名 · mm:ss」（R9 US4）
5. **Given** 队列 N≥2 条, **When** 左滑非播放中条目点删除, **Then** 该条目消失、计数减一、播放不中断；长按多选与竖向连选手势不误触发（T032 US2）
6. **Given** 播放中部某条（前有已播）, **When** 清除已播并在确认框点清除, **Then** 前缀移除、当前条目持续播放；当前条目处于播完未切状态时连同移除且播放器保持暂停；无可清条目时仅 toast 不弹框（T032 US4）
7. **Given** 队列非空且正在播放条目 A, **When** 添加订阅面板输入单视频 B 提交, **Then** B 追加队尾不打断、toast「已加入队列」；队列空时直接播放 toast「开始播放」；重复提交 toast「已在队列中」；输入框下方常驻「不打断」说明行存在（T032 US6）

### User Story 5 - 睡眠定时验证（KI-6 全量 + T032 US3） (Priority: P2)

在模拟器上验证睡眠定时全链路：倒计时模式（面板选时长→倒计时显示→归零暂停→按钮状态联动、后台节流后切回校准）与播完暂停模式（选播完暂停→当前条目播完停原条目暂停不切歌→手动续播从头重播/切歌恢复）、两模式单选互斥（后选取代先选）、触发时不弹「计时已结束」弹窗。验证通过则 KI-6 整条销项（含 SleepTimerController 文件头 `[UNVERIFIED]` 标注移除）。

**Why this priority**: KI-6 为在册「未经验证」欠账，播完暂停（T032 US3）与其同控制器同链路，合并一次验证覆盖两者。

**Independent Test**: 播放任一条目后操作定时面板，倒计时与播完暂停两条路径可各自独立验证。

**Acceptance Scenarios**:

1. **Given** 播放中且无定时, **When** 定时面板选倒计时时长, **Then** 倒计时开始并显示，归零后播放暂停
2. **Given** 倒计时进行中切后台再切回, **When** 查看倒计时, **Then** 时间按墙钟校准无漂移
3. **Given** 播放中, **When** 面板选「播完暂停」, **Then** 选项选中、当前条目播完时停原条目（不切下一首）、进度停末尾、播放器暂停
4. **Given** 播完暂停已触发暂停, **When** 手动点下一首/队列任一条目, **Then** 正常切歌继续播放，模式解除；手动点继续播放则当前条目从头重播
5. **Given** 倒计时进行中, **When** 改选「播完暂停」（或反向）, **Then** 后选取代先选，无双触发；任一模式触发时不弹「计时已结束」类弹窗

### User Story 6 - R10 沉浸/穿透/日志页验证 (Priority: P1)

在模拟器上验收 R10 三项修复：设置页/日志页内容沉浸绘制至小白条后方（末行可达）、隐藏迷你播放条不拦截下层触摸、日志页底部无大块空白（可见性标志反映真实显隐）。验收场景逐条对齐 R10 spec。

**Why this priority**: R10 为用户实机反馈产生的欠账，用户已确认模拟器验证过即销项。

**Independent Test**: 打开设置页/日志页滚动与点按即可独立验收。

**Acceptance Scenarios**:

1. **Given** 设置页打开, **When** 滚动到底部, **Then** 内容延伸绘制至小白条后方，「关于」等末行完整可达（R10 US1）
2. **Given** 日志页打开, **When** 查看页面底部, **Then** 列表延伸至小白条后方，底部无整块空白（R10 US1/US3）
3. **Given** 设置页在台（胶囊已隐藏）, **When** 点按原胶囊覆盖区域的设置项, **Then** 设置项正常响应，无误触唤起播放浮层（R10 US2）
4. **Given** 返回首页（胶囊重新显示）, **When** 点按胶囊, **Then** 正常唤起播放浮层（R10 US2）
5. **Given** 首页（胶囊可见）, **When** 列表渲染, **Then** 底部仍预留胶囊避让（现状不变）（R10 US3）

### User Story 7 - 降级衔接走查（T013 / KI-9 遗留） (Priority: P2)

在模拟器上对 UP 订阅执行「APP 签名链 → Web 链降级 → 回切」的翻页衔接走查：签名链正常翻页触底加载、模拟签名链故障触发降级后 Web 链衔接翻页、恢复后回切，确认全量条目无漏无重（bvid 去重兜底不触发为佳）。走查通过则 KI-9 遗留销项（KI-9 整条关闭）。

**Why this priority**: engineering-refactor T013 在册欠账；页界已统一（ps=20），走查是 KI-9 闭环的最后一环。

**Independent Test**: UP 订阅源页持续触底翻页贯穿降级事件，比对条目总数与去重情况即可独立验收。

**Acceptance Scenarios**:

1. **Given** UP 订阅打开（签名链正常）, **When** 触底翻页数页, **Then** 每页恰一请求、条目连续无重复
2. **Given** 模拟签名链故障（网络中断/恢复等手段）, **When** 继续触底翻页, **Then** 自动降级 Web 链衔接，页界处无漏条目、无重复条目
3. **Given** 网络恢复, **When** 继续翻页或刷新, **Then** 回切正常，列表状态一致
4. **Given** 模拟器环境无法稳定触发降级, **When** 走查受阻, **Then** 记录环境受限原因，T013 保留欠账不强行销项（诚实登记优于假 PASS）

### User Story 8 - 深浅色/主题色全页走查 (Priority: P3)

在模拟器上对全部页面（首页、设置页、源详情页、播放层、队列面板、添加订阅面板、日志页）做浅色/深色 × 默认主题色/切换主题色的视觉走查：对比度可读、无颜色残留异常、令牌化后观感一致。发现问题分级处理（小问题记录在案、大问题暂停报告）。

**Why this priority**: engineering-refactor US2 令牌化的收尾走查欠账；纯走查无代码改动，排在功能验证之后。

**Independent Test**: 切换深浅色与主题色逐页截图比对即可独立验收。

**Acceptance Scenarios**:

1. **Given** 浅色模式 + 默认主题色, **When** 逐页走查 7 个页面, **Then** 文字对比度可读、无颜色异常
2. **Given** 深色模式 + 默认主题色, **When** 逐页走查, **Then** 同上，无深色下对比度缺陷
3. **Given** 切换主题色后, **When** 逐页走查强调色应用点（高亮、按钮、进度条等）, **Then** 主题色全量生效无旧色残留

### Edge Cases

- 删开关误伤网络态分档：播放层大封面 Wi-Fi/非 Wi-Fi 取档、系统播控取档逻辑 MUST 保留，仅删「无图置空」分支
- 随开关存在的重发方法（refreshMediaSessionMetadata）删除前 MUST 核对无其他调用方（当前核实唯一调用方为开关回调）
- 首页左滑删除与 LazyForEach 键值（含 sub.id/latestTitle/newCount/cover 组合键）共存：删除操作不得破坏键值重建语义
- B5 收紧过度漏判：合法收藏夹 URL 形态（favlist/medialist 等）必须仍识别，收紧前须以真实 URL 形态（参考 biliRelay/PiliPlus）划定特征
- B4 调序后短链路径含 BV（b23.tv/BV…）零网络短路直达视频行为不变
- T032 US2 多选态下左滑删除的手势仲裁（横向 swipe 与竖向连选不同轴）回归确认
- 降级走查依赖真实 B 站 API 与风控状态，模拟器上降级触发手段（断网/恢复时机）可能不稳定——受阻时按 US7 场景 4 处理
- 深浅色走查发现的观感问题分级：小问题（不影响行为）记录在案继续；大问题（行为回归/需返工）暂停报告
- 模拟器验证窗口内应用数据（订阅/队列/历史）为测试构造数据，销项文档不涉及用户真实数据清理

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「无图模式」开关及其全链 MUST 移除——设置页开关行、开关状态、全部生效分支（迷你播放条/播放层/队列/系统播控的置空逻辑）、存储键定义、随开关存在的播控元数据重发方法；旧持久化值残留不清理不读取
- **FR-002**: 既有图片获取控制 MUST 零回退——CDN 尺寸后缀分档（缩略 240 档、大图/省流档）、网络态自动降档、缓存行为全部保留
- **FR-003**: 首页订阅列表 MUST 支持左滑露出「删除」按钮、点击执行退订（复用既有退订语义：清剧集缓存、持久化、列表刷新），交互与播放历史/播放队列一致（不做滑过阈值直删）
- **FR-004** (KI-7 B4): 链接识别中 URL 形态规则（合集/收藏夹/lists 等）MUST 优先于全文 BV 号扫描；纯 BV 文本、短链 path 含 BV 的直达行为零回归
