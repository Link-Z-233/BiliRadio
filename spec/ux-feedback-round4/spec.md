# Feature Specification: UX 反馈修复第 4 轮（播放与订阅体验批次）

**Created**: 2026-10-05  
**Status**: Draft  
**Input**: User description: "添加订阅的搜索时，自动收起键盘；把这个页面添加按钮换成载入；未登录态查询up投稿报352；设置页面不需要底部播放胶囊展示；播放胶囊左右两边留一点空，别紧贴边框；播放详情页无法打开播放列表；非首次切换剧集后进度条会卡住不动；播放页加载弧度 API24 不显示、API26 圆心错位，重做加载指示器"

## Overview

本批次集中修复用户反馈的 8 个体验问题并增强问题定位能力，覆盖三条主线：播放核心交互（播放列表打不开、切剧后进度条冻结、加载指示器跨 API 版本异常）、订阅获取链路（未登录查询 UP 投稿触发 B 站 352 风控、搜索键盘不收起、按钮文案语义）、以及底部播放胶囊的展示规则（设置页不应展示、左右应留边距）；同时将应用日志异步落盘（有硬上限），并为播放关键路径补充结构化诊断日志，支撑偶现问题的事后定位。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 播放详情页打开播放列表 (Priority: P1)

用户在全屏播放详情页点按底部"播放列表"按钮，预期从右侧滑出队列抽屉，展示当前播放队列并可点选切歌；当前按钮点击与状态开关实际生效（抽屉有挂载），但受层级 bug 影响抽屉未置顶展示，被其他内容遮挡而不可见，表现为"打不开"。**该问题仅在 API 24 的平板设备上复现**，其余设备/API 版本表现正常，属平台相关渲染层级行为差异。

**Why this priority**: 播放列表是播客类应用的核心操作入口，抽屉被遮挡不可见属于功能性阻断（根因为渲染层级问题，非按钮失效）。

**Independent Test**: 打开播放详情页 → 点按播放列表按钮 → 队列抽屉置顶滑出、不被遮挡，且可点选条目切歌。

**Acceptance Scenarios**:

1. **Given** 正在播放且已打开播放详情页，**When** 点按底部播放列表按钮，**Then** 队列抽屉从右侧滑出，展示队列条目，当前曲目高亮。
2. **Given** 队列抽屉已打开，**When** 点按遮罩或关闭，**Then** 抽屉收起，播放详情页其余功能不受影响。
3. **Given** 播放详情页内打开队列抽屉，**When** 点选任一队列条目，**Then** 切换到该曲目播放，抽屉内高亮与实际播放曲目一致。

### User Story 2 - 非首次切换剧集后进度条持续更新 (Priority: P1)

用户在播放中切换剧集（第二次及以后），新曲目开始播放后进度条与时间应持续走动；当前第二次起切换后进度条卡住不动，不再随播放推进。

**Why this priority**: 进度条冻结让用户误以为播放卡死，属于核心播放状态展示错误，且随使用时间加必定触发（与 PROJECT_NOTES KI-1/KI-5 已知问题相关）。

**Independent Test**: 连续切换 3 次以上剧集，每次切换后观察进度条是否随播放推进。

**Acceptance Scenarios**:

1. **Given** 正在播放曲目 A，**When** 切到曲目 B 再切到曲目 C，**Then** 曲目 C 播放中进度条持续前进、当前时间持续更新。
2. **Given** 连续多次（≥3 次）切换剧集，**When** 任一次切换完成进入播放态，**Then** 进度条均正常走动，无冻结。
3. **Given** 切换剧集后，**When** 拖动进度条，**Then** Seek 生效且进度条随后继续从新位置推进。

### User Story 3 - 未登录态查询 UP 投稿尽量可用，失败时友好提示 (Priority: P1)

未登录用户在添加订阅中输入 UP 主 ID/链接查询投稿时，系统应优先采用对未登录友好的 APP 端点（参考 PiliPlus：`app.bilibili.com` 的 space 投稿游标接口，无需 cookie/WBI、无 352 风控）完成查询；若需回退 Web WBI 端点，则补齐未登录风控所需的全套配方（本地 buvid3 + ExClimbWuzhi 激活 + dm_img 指纹参数 + WBI 签名 + 被动 cookie 收集）。若最终仍被风控拦截，应给出明确、可操作的提示（建议登录），而不是裸露的 352 错误。

**Why this priority**: 订阅 UP 主是应用最核心的内容获取路径，未登录即完全不可用且报错不友好，属于高频阻断。

**Independent Test**: 退出登录后查询一个 UP 主，观察是否成功返回投稿列表；若被风控，观察提示文案。

**Acceptance Scenarios**:

1. **Given** 未登录状态，**When** 查询 UP 主投稿，**Then** 系统优先经未登录友好的 APP 端点（PiliPlus 同款）返回投稿列表，不触发 352。
2. **Given** 未登录且回退 Web WBI 端点，**When** 发起请求，**Then** 请求携带 buvid3、ExClimbWuzhi 激活产物、dm_img 系列指纹参数与 WBI 签名，尽量成功返回。
3. **Given** 未登录且请求仍被 B 站风控拦截（352/412 类错误），**When** 查询失败，**Then** 用户看到友好提示（明确指出疑似风控、建议登录），无裸露错误码。
4. **Given** 已登录状态，**When** 查询 UP 主投稿，**Then** 行为不回退，登录态查询仍正常。

### User Story 4 - 播放页加载指示器重做（跨 API 版本一致） (Priority: P2)

播放缓冲中（准备且待播）时，播放键应以系统加载圈形态向用户反馈"正在加载"；废弃现有自绘 Path 旋转弧线（API 24 不显示、API 26 圆心错位），改用系统加载组件替换播放键图标，保证各 API 版本表现一致。

**Why this priority**: 加载反馈在两个主流 API 版本上分别缺失或错位，用户无法感知缓冲状态；已确认采用"系统加载圈替换播放键图标"方案。

**Independent Test**: 在缓冲触发场景（选歌后自动播放）观察播放键是否显示加载圈，缓冲结束后是否恢复播放/暂停图标。

**Acceptance Scenarios**:

1. **Given** 触发缓冲（进入 preparing 且待播），**When** 缓冲进行中，**Then** 播放键内显示系统加载圈（替代原自绘弧线），不依赖 Path 绘制，无圆心错位。
2. **Given** 缓冲完成进入播放，**When** 加载状态结束，**Then** 加载圈消失，播放键恢复为暂停图标。
3. **Given** 任意支持的 API 版本（含 24 与 26），**When** 触发缓冲，**Then** 加载指示表现一致。

---

### User Story 5 - 添加订阅搜索时自动收起键盘 (Priority: P2)

用户在添加订阅页输入内容后点按操作按钮提交查询时，软键盘应自动收起，避免键盘遮挡查询结果。

**Why this priority**: 键盘遮挡结果区直接影响查询结果可见性，属高频交互体验问题。

**Independent Test**: 打开添加订阅页 → 输入内容 → 点按提交 → 键盘收起且结果可见。

**Acceptance Scenarios**:

1. **Given** 添加订阅页输入框聚焦、键盘弹出，**When** 点按提交按钮发起查询，**Then** 软键盘收起，查询结果不被遮挡。
2. **Given** 输入框聚焦、键盘弹出，**When** 按输入法确认/搜索键，**Then** 同样触发查询并收起键盘。

---

### User Story 6 - 添加订阅页按钮文案改为"载入" (Priority: P2)

添加订阅页主输入行的操作按钮当前文案为"添加"，但实际行为是识别输入并载入查询结果（订阅动作在结果中进行），应将文案改为"载入"以准确表达语义。

**Why this priority**: 文案与行为不符造成理解成本，修复成本极低。

**Independent Test**: 打开添加订阅页，查看主输入行按钮文案为"载入"，点按后行为不变（载入识别结果）。

**Acceptance Scenarios**:

1. **Given** 打开添加订阅页，**When** 查看主输入行按钮，**Then** 文案显示为"载入"。
2. **Given** 输入合法内容，**When** 点按"载入"，**Then** 识别与查询行为与原先一致，结果区正常展示。

---

### User Story 7 - 设置页不展示底部播放胶囊 (Priority: P3)

进入设置页时，底部悬浮播放胶囊应隐藏；离开设置页返回其他页面后恢复原有展示规则。

**Why this priority**: 设置页是低频管理场景，胶囊遮挡内容且无操作价值；属展示规则修正。

**Independent Test**: 播放中导航到设置页观察胶囊消失，返回首页/源页观察胶囊恢复。

**Acceptance Scenarios**:

1. **Given** 正在播放且胶囊可见，**When** 导航进入设置页，**Then** 底部播放胶囊不展示。
2. **Given** 位于设置页（胶囊已隐藏），**When** 返回上一页，**Then** 胶囊按原有规则恢复展示。
3. **Given** 位于设置页，**When** 播放状态变化（切歌、暂停），**Then** 胶囊保持隐藏，返回后状态正确。

---

### User Story 8 - 播放胶囊左右留出边距 (Priority: P3)

底部播放胶囊当前水平方向紧贴屏幕左右边框，应左右各留出适当边距（与现有设计边距一致，约 16vp 量级），呈悬浮卡片形态。

**Why this priority**: 视觉打磨项，不影响功能。

**Independent Test**: 播放中观察首页/源页底部胶囊，左右两侧均有可见留白，不贴边。

**Acceptance Scenarios**:

1. **Given** 正在播放且胶囊可见（非设置页），**When** 查看胶囊布局，**Then** 胶囊左右两侧各留出约 16vp 边距，不与屏幕边缘相接。
2. **Given** 深浅色模式与不同屏宽，**When** 胶囊展示，**Then** 左右边距稳定存在，无布局溢出或贴边。

---

### User Story 9 - 日志落盘并限制最大占用，支撑播放问题定位 (Priority: P2)

应用日志当前仅存内存（重启即失），问题复现后无法事后分析。日志应异步写入应用沙箱文件，且文件占用有硬上限（超限滚动淘汰最旧）；同时，切剧/进度冻结相关的关键路径（播放状态切换、切剧重置、广播异常隔离、订阅生命周期）应记录结构化日志条目，使 US2 类问题可通过落盘日志定位。

**Why this priority**: US2 类"偶现、无法实时复现分析"的缺陷依赖事后日志定位；落盘是定位能力的前提，上限控制避免日志无限膨胀。

**Independent Test**: 触发若干操作后重启应用，检查沙箱内日志文件存在且含操作记录；构造超量日志验证文件大小不超过上限；设置页日志面板行为不回退。

**Acceptance Scenarios**:

1. **Given** 应用运行中产生日志，**When** 查看应用沙箱日志文件，**Then** 日志条目已异步写入文件，格式可读。
2. **Given** 日志文件持续增长，**When** 超过设定上限，**Then** 最旧日志被淘汰，文件大小保持在上限以内（滚动保留最新部分）。
3. **Given** 发生切剧、进度广播异常隔离、组件订阅/退订等事件，**When** 查看日志，**Then** 存在对应结构化条目（含必要上下文，不含敏感信息）。
4. **Given** 任意日志写入/落盘失败，**When** 播放与请求主流程运行，**Then** 主流程不受影响（静默降级）。

---

### Edge Cases

- 快速连续切换剧集（切歌请求未完成时再次切歌）：进度条不得冻结或回跳到旧曲目位置；旧曲目的定时 seek 不得作用到新曲目。
- 在队列抽屉（播放详情页内）切歌后立即拖动进度条：seek 目标基于新曲目时长，进度条不冻结。
- 未登录触发风控后用户紧接着登录：再次查询应使用登录态立即成功，无需杀进程。
- 添加订阅查询时输入为空或非法：点"载入"不发起请求，行为与原先一致（键盘仍收起）。
- 设置页隐藏胶囊期间，全屏播放层打开/关闭：胶囊可见性规则不冲突、不错乱。
- 缓冲中被用户点按播放键（暂停待播）：加载圈应消失，回到播放图标态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 播放详情页播放列表按钮触发后，队列抽屉 MUST 在播放浮层内**置顶展示**（不被浮层内其他内容遮挡，修复层级 bug），抽屉内 MUST 可点选切歌且当前曲目高亮。
- **FR-002**: 任意第 N 次（N≥2）切换剧集进入播放后，进度条与当前时间 MUST 持续更新，不得冻结。
- **FR-003**: 播放状态广播机制 MUST 保证单条监听器异常不阻断其余监听器收到更新（隔离异常），且组件销毁后 MUST 能退订，避免监听器无限累积。
- **FR-004**: 切换剧集时，与旧曲目相关的派生状态（秒级节流基准、挂起的定时 seek、seeking 标志）MUST 被重置，不得残留影响新曲目。
- **FR-005**: 未登录查询 UP 投稿 MUST 优先走未登录友好的 APP 端点（参考 PiliPlus：`app.bilibili.com` 投稿游标接口，APP UA，无需 cookie/WBI）；如实现涉及 Web WBI 端点，MUST 按 PiliPlus 配方补齐全套未登录风控要素：本地生成 buvid3、启动时 ExClimbWuzhi 激活、被动收集响应 Set-Cookie（b_nut/buvid4 等）、请求携带 dm_img 系列指纹参数与 WBI 签名。
- **FR-006**: UP 投稿查询最终失败且判定为风控（352/412 类）时，UI MUST 展示友好提示并建议登录，不得裸露错误码。
- **FR-007**: 播放页缓冲中 MUST 以系统加载组件（替换播放键图标）展示加载状态，废弃自绘 Path 旋转弧线；缓冲结束 MUST 恢复播放/暂停图标。
- **FR-008**: 添加订阅页发起查询（点按钮或输入法提交）时 MUST 自动收起软键盘。
- **FR-009**: 添加订阅页主输入行按钮文案 MUST 为"载入"，行为保持原识别/查询逻辑不变。
- **FR-010**: 位于设置页时底部播放胶囊 MUST 隐藏，离开设置页 MUST 恢复原有可见性规则。
- **FR-011**: 底部播放胶囊左右两侧 MUST 各留约 16vp 边距，不得紧贴屏幕边缘或布局溢出。
- **FR-012**: 上述修复 MUST NOT 回退现有登录态查询、全屏播放层、睡眠定时、播放模式等既有功能。
- **FR-013**: 应用日志 MUST 异步落盘至应用沙箱文件，文件大小 MUST 有硬上限（超限滚动淘汰最旧条目）；日志内容 MUST NOT 包含 cookie/token 等敏感信息；落盘失败 MUST 静默降级不影响主流程。
- **FR-014**: US2 相关关键路径（播放状态切换、切剧状态重置、广播异常隔离、订阅/退订生命周期）MUST 记录结构化日志条目，支撑进度冻结类问题的事后定位。

### Key Entities

- **PlayerController（既有）**: 播放队列单例，本批涉及其 UI 广播（订阅/退订/异常隔离）与切剧状态重置行为。
- **BiliSession / BiliService（既有）**: B 站会话与 API 层，本批涉及未登录风控参数补齐与 352 兜底提示。
- **MiniPlayer（既有）**: 底部播放胶囊组件，本批涉及其可见性规则与水平边距。
- **PlayerOverlay（既有）**: 全屏播放详情页，本批涉及队列抽屉打开、进度条刷新、加载指示器重做。
- **Logger（既有）**: 应用内日志服务，本批涉及落盘持久化、上限控制与播放路径诊断日志。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 播放详情页点按播放列表按钮 100% 置顶打开队列抽屉（不被遮挡），连续操作 10 次无失败。
- **SC-002**: 连续切换剧集 5 次以上，每次进入播放后进度条均在 2 秒内开始持续走动，零冻结。
- **SC-003**: 未登录查询 UP 投稿在常规网络环境下成功率显著恢复；仍失败时 100% 展示友好引导提示，无裸露 352 报错。
- **SC-004**: 缓冲触发时加载指示在 API 24 与 API 26 上均正常显示且形态一致。
- **SC-005**: 添加订阅页提交查询后键盘 100% 收起；按钮文案统一为"载入"。
- **SC-006**: 设置页全程无播放胶囊；其余页面胶囊左右各有可见留边。
- **SC-007**: 日志落盘后重启应用文件仍在且文件大小 100% 不超过设定上限；US2 关键路径事件 100% 有对应日志条目。

## Assumptions

- B 站未登录风控（352/412）的规避以 **PiliPlus 项目**（`D:\UsersFiles\Link_Z\Desktop\Code\PiliPlus`）为参考实现：其主路径为 APP 端点（无风控），Web 路径依赖 buvid3 本地生成 + ExClimbWuzhi 激活 + dm_img 指纹 + WBI 签名。本批优先采用 APP 端点方案，不承诺 Web 端点 100% 绕过；兜底为友好提示引导登录（用户已确认此方向）。
- 加载指示采用"系统加载圈替换播放键图标"方案（用户已确认）；原"常驻低透明装饰圆环"与缓冲弧线一并废弃，播放键区域简化。
- 胶囊左右边距采用与现有设计一致的约 16vp 量级。
- 本批不重构导航/状态管理框架，仅在既有 V1 装饰器与 AppStorage 瞬态键体系内修复。
