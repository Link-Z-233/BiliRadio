## Overview

两部分：**A. 订阅详情页（`SourcePage`）布局调整 7 项**——去除「播放全部」；刷新/退订收进顶栏「···」下拉菜单（顶栏=返回+标题+···）；页头头像旁多选按钮，多选模式行内勾选框+底部操作条（全选/取消+加入队列）批量入队；页头封面与文字等高；页头随列表滚动离屏、回顶再现；左右留白收窄。**追加项**：剧集行（v0.5-part1 交付的 B 站风格行）封面与文字列严格等高——封面收为 121×68、文字列固定同高、标题贴顶/附属行贴底（US7）。**B. 新建根目录 `BILI_API.md`**——汇总本项目全部 B 站 API 探索情况（端点清单/坑/实测结论），迁移 biliRelay 的 API 探索内容（试错实验/状态码速查/排查手册，剔除非 API 内容），本轮充电实测结论亦沉淀其中。上轮 `v0.5-part1-source-page-redesign` 既有功能语义保持不变（去除项除外）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 顶栏收纳与播放全部移除 (Priority: P1)

进入订阅详情页，顶栏为「返回 + 标题 + ···」；原页头的刷新/删除图标与「播放全部」按钮均消失。点 ··· 弹出系统下拉菜单（毛玻璃浮层），含「刷新」「取消订阅」两项：刷新触发原刷新逻辑（刷新中 ··· 位置显示转圈），取消订阅走原二次确认弹窗；标题超长时省略号截断。

**Why this priority**: 顶栏是页面骨架，其余故事都挂在新顶栏结构之上；「播放全部」去除是明确指令，须最先落地。

**Independent Test**: 打开任一订阅详情页，核对顶栏三项与页头无刷新/删除/播放全部；点 ··· 逐项执行刷新与退订，行为与旧入口一致。

**Acceptance Scenarios**:

1. **Given** 任一订阅详情页，**When** 页面渲染，**Then** 顶栏显示返回、标题、···；页面无「播放全部」按钮
2. **Given** 点击 ···，**When** 菜单弹出，**Then** 显示「刷新」「取消订阅」两项
3. **Given** 点击菜单「刷新」，**When** 刷新执行，**Then** 行为与原页头刷新一致，刷新中顶栏显示转圈，完成后列表回到顶部
4. **Given** 点击菜单「取消订阅」，**When** 确认弹窗出现，**Then** 二次确认流程与现状一致（确认后退订并返回）
5. **Given** 订阅标题超长，**When** 顶栏渲染，**Then** 标题省略号截断不换行

---

### User Story 2 - 多选批量加入队列 (Priority: P1)

页头头像旁有多选按钮；点击进入多选模式：剧集行左侧出现勾选框、点击行切换选中态（不再触发播放），底部出现操作条「全选/取消 + 加入队列 (N)」。点「加入队列」将选中剧集按列表序批量入队（队列为空则开始播放，非空则追加不打断），toast 反馈结果后退出多选恢复常规态。

**Why this priority**: 替代被移除的「播放全部」成为批量收听入口，是本轮唯一新增能力。

**Independent Test**: 进入任一有剧集的订阅详情页，进入多选，勾选若干集（含全选），加入队列后核对队列内容与 toast。

**Acceptance Scenarios**:

1. **Given** 页头渲染，**When** 查看头像旁，**Then** 显示多选按钮
2. **Given** 多选模式，**When** 点击剧集行，**Then** 该行切换选中态（勾选框同步），不触发播放
3. **Given** 多选模式，**When** 点击「全选」，**Then** 当前列表全部剧集选中，按钮变「取消全选」可反向
4. **Given** 已选中 N 集，**When** 点击「加入队列 (N)」，**Then** 选中剧集按列表序入队（空队列起播/非空追加不打断），toast 反馈，退出多选模式
5. **Given** 多选模式，**When** 点击底部「取消」，**Then** 退出多选，无任何入队副作用
6. **Given** 多选模式，**When** 系统返回，**Then** 先退出多选模式而非退出页面

---

### User Story 3 - 页头随滚动收起 (Priority: P2)

页头（头像+订阅信息+多选按钮）不固定在顶部，属列表的一部分：向下滚动时随内容离屏收起，向上滚回顶部时重新完整展现；列表顶部无重复占位、无跳动。

**Why this priority**: 版面行为调整，依赖 US1 顶栏骨架完成后叠加，独立可验。

**Independent Test**: 打开长列表订阅，上下滚动观察页头随内容滚动离屏/回顶再现，检查回顶后页头完整。

**Acceptance Scenarios**:

1. **Given** 列表在顶部，**When** 页面渲染，**Then** 页头完整显示在顶栏下方
2. **Given** 列表向下滚动，**When** 页头滚出视口，**Then** 页头离屏消失，列表正常滚动
3. **Given** 页头已离屏，**When** 滚回顶部，**Then** 页头完整再现，头像、订阅信息、多选按钮均正常
4. **Given** 页头离屏状态下刷新完成，**When** 列表回到顶部，**Then** 页头随之完整展现

### User Story 5 - 页头等高与留白收窄 (Priority: P3)

页头封面与右侧文字（订阅类型/UP 名 + 集数）高度一致，视觉对齐无错落；页面整体左右留白收窄一档，内容区更宽。

**Why this priority**: 纯视觉打磨项，不影响功能，最后叠加。

**Independent Test**: 打开任一订阅详情页，核对页头封面与文字块高度一致、页面左右留白较此前收窄。

**Acceptance Scenarios**:

1. **Given** 页头渲染，**When** 封面与文字并排，**Then** 两者高度一致（上下边缘对齐）
2. **Given** 页面渲染，**When** 观察左右边距，**Then** 留白较调整前收窄一档，列表与页头对齐一致

### User Story 6 - biliAPI 探索文档 (Priority: P1)

新建根目录 `BILI_API.md`：汇总本项目全部 B 站 API 探索情况（在用端点清单、鉴权/签名方式、风控坑与对策、历史实测结论），迁移 biliRelay 的 API 探索内容（试错实验 1-14/16-21、状态码速查、排查手册；剔除非 API 内容如 Docker 部署）。本轮充电实测结论（US4）写入该文档，作为后续唯一 API 探索沉淀点。

**Why this priority**: 本项目 API 知识目前散落 AGENTS.md/Constants 注释/各 spec，且依赖仓库外 biliRelay 的探索记录；统一沉淀是本轮充电实测的前置基建，与 US1-2 并行推进。

**Independent Test**: 核对文档存在且三部分内容齐全（本项目探索汇总、biliRelay 迁移、充电实测新结论）；文档内引用仓库内路径为相对路径。

**Acceptance Scenarios**:

1. **Given** 文档建成，**When** 查阅 `BILI_API.md`，**Then** 含本项目在用端点清单与已知坑（APP 端点 UA、WBI 签名、rcp 短链、风控冷却等）
2. **Given** biliRelay 探索内容迁移，**When** 对照原文，**Then** API 相关实验/状态码/排查手册内容在档（非 API 内容未迁入），语义无失真
3. **Given** 本轮充电实测完成，**When** 查阅文档，**Then** 四类接口带/不带充电标记字段的实测结论在档
4. **Given** 文档内引用，**When** 提及仓库内文件，**Then** 使用相对路径（禁绝对路径）

---

### User Story 7 - 剧集行封面与文字等高（追加） (Priority: P3)

剧集行封面与右侧文字列严格等高：封面显示尺寸由 140×79 收为 121×68（≈16:9），文字列固定同高（68）——标题贴顶、日期/NEW/已播行贴底（`justifyContent(SpaceBetween)` 分布）；单行标题行中间留白为预期形态（对齐 B 站/PiliPlus 横版卡「标题顶、统计底」结构，参考 `../bili/PiliPlus/lib/common/widgets/video_card/video_card_h.dart`）。修复此前「封面固定 79 高、文字列自适应 ≤63 高、垂直居中无法弥补不相等高度」导致的封面上下出头。缩略请求档（480×270）不变。

**Why this priority**: 纯视觉对齐修正，独立可验。

**Independent Test**: 打开任一有剧集的订阅详情页，核对两行标题行文字列上下边缘与封面对齐、单行标题行标题贴顶/附属行贴底、多选勾选框垂直居中。

**Acceptance Scenarios**:

1. **Given** 两行标题剧集行，**When** 渲染，**Then** 文字列与封面上下边缘对齐（同为 68 高）
2. **Given** 单行标题剧集行，**When** 渲染，**Then** 标题贴顶、日期/NEW/已播行贴底，中间留白（非缺陷）
3. **Given** 多选模式，**When** 行首勾选框渲染，**Then** 垂直居中不跑偏

---

### Edge Cases

- **多选与加载更早**：多选模式下触底加载更早仍可用，新载入剧集默认未选中，「全选」只选当前列表全部条目
- **多选与空列表**：无剧集时不进入无意义的多选态（多选按钮隐藏或禁用）
- **多选与 NEW/已播标记**：选中态与 NEW/已播标记并存时行布局稳定
- **刷新中禁止重复刷新**：刷新进行中再次点 ···→刷新无副作用（沿用原 refreshing 守卫）
- **退订后返回**：菜单退订确认后页面 pop，不残留菜单/多选状态
- **单行标题剧集行**：标题贴顶、附属行贴底，中间留白为 B 站同款预期形态（非缺陷）
- **长标题页头**：订阅名超长时页头文字省略号截断，不撑破等高布局
- **biliRelay 迁移保真**：原文中 Python/服务端语境的实验记录按原文迁移，不做面向本项目的改写（避免语义失真）；文档标注来源

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 订阅详情页 MUST NOT 显示「播放全部」按钮（相关死代码一并移除）
- **FR-002**: 顶栏 MUST 为「返回 + 标题 + ···」结构；刷新与取消订阅 MUST 收进 ··· 的系统下拉菜单，行为与原页头入口一致
- **FR-003**: 刷新中状态 MUST 在顶栏可见（转圈动画），期间禁止重复触发
- **FR-004**: 页头头像旁 MUST 提供多选按钮；多选模式下剧集行 MUST 显示勾选框且点击行仅切换选中（不播放）（已由后续多选交互重构 spec 取代入口设计，勾选框与点击仅切换语义保留）
- **FR-005**: 多选模式底部操作条 MUST 提供「全选/取消全选」「加入队列 (N)」「取消」；加入队列 MUST 复用现有入队语义（空队列起播、非空追加不打断、去重），完成后 toast 反馈并退出多选（已由后续多选交互重构 spec 取代操作条设计，入队语义与 toast 反馈保留）
- **FR-006**: 多选模式 MUST 可被系统返回键退出（优先于页面返回）
- **FR-007**: 页头 MUST 随列表滚动（不固定），滚回顶部完整再现
- **FR-008**: 页头封面与右侧文字块高度 MUST 一致
- **FR-009**:（已移出：见 spec/charging-archive.md）
- **FR-010**: 页面左右留白 MUST 较现状收窄一档（数值统一经 Constants 令牌，禁裸数字）
- **FR-011**: 上轮既有功能 MUST 全部回归：NEW 徽标、已播标记、触底加载更早（四类翻页链路）、退订二次确认、空态、按压态、行封面与时长角标
- **FR-012**: 根目录 MUST 新建 `BILI_API.md`，含三部分：本项目 API 探索汇总（在用端点/坑/对策）、biliRelay API 探索内容迁移（剔除非 API 内容）、本轮充电实测结论
- **FR-013**: `BILI_API.md` 内引用仓库内路径 MUST 为相对路径，引用仓库外项目路径相对仓库根上级
- **FR-014**: 剧集行封面与文字列 MUST 严格等高——封面 `EPISODE_THUMB_W/H` 收为 121×68，文字列 `.height(EPISODE_THUMB_H)` + SpaceBetween 分布（标题贴顶、日期/NEW/已播行贴底）；缩略请求档 `EPISODE_THUMB_REQ_*`（480×270）不变

### Key Entities

- **多选会话（页面内瞬态）**：是否处于多选模式、已选 bvid 集合、全选状态；仅存在于 SourcePage 生命周期，不持久化
- **BILI_API.md（文档实体）**：B 站 API 探索的唯一沉淀点；结构=本项目探索汇总 + biliRelay 迁移 + 后续新增实测（含本轮充电实测）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 顶栏收纳后页面常驻操作元素只剩「···」一个，页头无任何图标按钮（多选按钮除外）
- **SC-002**: 用户从进入多选到完成批量入队 ≤ 4 步（多选→选集→全选可选→加入队列）
- **SC-003**: 7 项调整全部落地且 FR-011 回归清单零缺失（构建验证 + 真机自查）
- **SC-004**:（已移出：见 spec/charging-archive.md）
- **SC-005**: `BILI_API.md` 三部分内容齐全（FR-012），biliRelay API 相关内容迁移无遗漏

## Assumptions

- 「移除」沿用现有「取消订阅」文案与二次确认流程，仅位置变化
- 多选按钮覆盖四类订阅（UP/收藏夹/合集/系列），非仅 UP 主订阅
- 「加入播放列表」语义=加入应用内播放队列（现有歌单），非 B 站收藏夹
- 留白收窄幅度=现有间距令牌降一档，具体档位在 plan 阶段定
- 上轮 `v0.5-part1-source-page-redesign` 已实施完毕，本轮在其代码基础上调整
- `BILI_API.md` 为纯文档交付物，不改动任何应用行为；AGENTS.md 既有「B 站 API 坑」摘要保留（面向代理的速查），详细记录以 `BILI_API.md` 为准
- biliRelay 仓库本身不改动（只读迁移）
