# Feature Specification: 音质选择与默认音质设置

**Created**: 2026-10-06  
**Status**: Draft  
**Input**: User description: "准备音频选择设置项吧，在播放页添加选项的同时，在设置页准备一个默认音质，wifi和流量不同，可参考 PiliPlus 与 biliRelay（不署名）；别忘了非登录态音质限制"

## Overview

BiliRadio 当前取流为固定规格：在线播放按「优先低码率」开关在 DASH 音轨里取最高/最低带宽，没有音质档位概念。本功能引入 B 站真实音质档位（最高 / 192K / 132K / 64K），提供两处入口：设置页新增「Wi-Fi 默认音质」与「蜂窝默认音质」两个独立档位；播放页底部面板展示当前曲目可用音轨并支持即时切换（保持进度换流，写回当前网络对应的默认值）。同时删除被档位取代的「优先低码率音频流」开关并做存量迁移。

音质档位受 B 站登录态硬性限制：**未登录时 B 站仅下发 64K 音轨**；登录（非大会员）可取 132K；192K 及 Hi-Res/杜比通常需大会员。系统须按实际可用性静默回落，并在 UI 上提示该限制。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 设置页双默认音质 (Priority: P1)

用户在设置页分别设置 Wi-Fi 环境与蜂窝（流量）环境下的默认音质，各为四选一档位：最高（最高可用）/ 192K / 132K / 64K。默认值：Wi-Fi=最高、蜂窝=132K。原「优先低码率音频流」开关从设置页移除。

**Why this priority**: 双默认设置是整个功能的基础与价值核心（流量场景省钱、Wi-Fi 场景听高音质），独立于播放页切换可用。

**Independent Test**: 进入设置页，能看到两个音质设置项并可各自修改档位，修改后持久化（重启应用仍保留）；设置页不再出现「优先低码率音频流」开关。

**Acceptance Scenarios**:

1. **Given** 全新安装（或未开启过低码率开关），**When** 进入设置页，**Then** 「Wi-Fi 默认音质」显示"最高"、「蜂窝默认音质」显示"132K"。
2. **Given** 旧版本用户曾开启「优先低码率音频流」，**When** 升级后首次进入设置页，**Then** 蜂窝默认音质显示"64K"（迁移生效），Wi-Fi 默认音质为"最高"。
3. **Given** 任一默认音质被改为"192K"，**When** 杀进程重启应用再看设置页，**Then** 显示仍为"192K"。
4. **Given** 未登录状态，**When** 查看音质设置项，**Then** 项内有可见提示说明当前登录态下实际可用的最高档位（未登录=64K），引导登录以解锁更高音质；打开任一默认音质选择器时，仅显示「最高」与「64K」两个可选档位（132K/192K 不显示为可选项）。
5. **Given** 原设置页的三个省流量开关，**When** 本功能上线后进入设置页，**Then** 「省流量模式」（封面/头像不加载）与「仅在 Wi-Fi 环境播放」两个开关原样保留且行为不变，仅「优先低码率音频流」消失；封面/头像按「省流量模式」开关的既有逻辑加载或隐藏，不受音质档位任何影响。

### User Story 2 - 播放自动套用对应网络的默认音质 (Priority: P1)

在线流播放开始时，按当前网络类型（Wi-Fi / 蜂窝）自动套用对应的默认音质档位取流。

**Why this priority**: 不套用默认则设置项无实际效果，与 US1 共同构成 MVP。

**Independent Test**: 蜂窝网络下（模拟器可模拟）播放在线流，取流为蜂窝默认档位（回落规则见 US4）；Wi-Fi 下同理。可通过播放页音质面板的当前档位指示验证。播放中切换网络类型（模拟器切换 Wi-Fi/蜂窝），稳定后当前曲目立即换流为新网络默认档且进度保持。

**Acceptance Scenarios**:

1. **Given** Wi-Fi 网络且 Wi-Fi 默认音质=192K，**When** 播放一首无缓存的歌，**Then** 取流档位为 192K（该曲目可用时）。
2. **Given** 蜂窝网络且蜂窝默认音质=64K，**When** 播放一首无缓存的歌，**Then** 取流档位为 64K。
3. **Given** 正在 Wi-Fi 下在线流播放（192K），**When** 网络切换到蜂窝且已稳定（防抖确认，非瞬时抖动），**Then** 当前曲目立即按蜂窝默认档（如 64K）换流，从当前进度继续播放，不打断；播放页面板当前档指示随之更新。
4. **Given** 网络出现短时抖动（快速断连/类型快速往返），**When** 网络在防抖窗口内恢复原类型，**Then** 不触发换流，播放不受影响。
5. **Given** 网络切换触发的自动换流失败（解析/网络错误），**When** 换流未成功，**Then** 保持原流继续播放，不中断、不报错弹窗（记录日志）。
6. **Given** 本地缓存曲目播放中或当前流为 durl 降级流，**When** 网络类型稳定切换，**Then** 不触发换流。

### User Story 3 - 播放页音质面板与即时切换 (Priority: P2)

播放页（PlayerOverlay）底部弹层新增「音质」面板：列出当前曲目实际可用的音轨档位并标示当前生效档；点选其他档位后立即换流并保持播放进度继续播放；同时把所选档位写回当前网络对应的默认音质设置。

**Why this priority**: 提升单曲场景灵活性（参考 PiliPlus 的播放页切换+写回交互），依赖 US1 的设置项存在。

**Independent Test**: 播放中打开音质面板，可见可用档位列表与当前档高亮；切换到另一档后音乐不打断（短暂缓冲后从原进度继续），再进设置页可见对应网络默认值已同步更新。

**Acceptance Scenarios**:

1. **Given** 正在在线流播放 192K，**When** 打开音质面板，**Then** 列表显示该曲目可用档位且"192K"标示为当前。
2. **Given** 面板中点选"64K"，**When** 换流完成，**Then** 从切换前进度继续播放，面板与面板外指示更新为 64K；设置页「蜂窝默认音质」（若当前为蜂窝）显示"64K"。
3. **Given** 当前为 Wi-Fi 环境，**When** 面板切档，**Then** 写回的是「Wi-Fi 默认音质」而非蜂窝项。
4. **Given** 未登录状态播放（B 站仅下发 64K 音轨），**When** 打开音质面板，**Then** 列表仅显示"64K"为可用档，其余档位不显示为可选项（或显示为不可选并注明需登录），不可误切换。

### User Story 4 - 档位回落、登录态限制与降级保护 (Priority: P2)

音质档位受登录态硬性限制，系统按下表矩阵处理，并在期望档不可用时静默回落：

| 档位 | 未登录 | 登录（非大会员） | 大会员 |
|---|---|---|---|
| 64K | ✅ | ✅ | ✅ |
| 132K | ❌ 仅 64K 下发 | ✅ | ✅ |
| 192K | ❌ | ❌ 通常拿不到 | ✅ |
| Hi-Res/杜比 | ❌ | ❌ | ✅ 存在时优先 |

回落算法：期望档存在→取之；不存在→取**不高于期望档**的最高可用档；「最高」→取最高可用档并在存在时升级 Hi-Res/杜比音轨；playurl 请求失败→以 64K 档重试一次；仍失败→走既有 DURL 降级链。

**Why this priority**: 保证功能在未登录、非大会员、部分老视频等场景下稳健可用，且用户能理解为什么实际档位与设置不符。

**Independent Test**: 未登录播放任意视频，选择 192K 默认档，播放正常且实际取 64K，无错误弹窗；登录后同设置下自动取到更高档。

**Acceptance Scenarios**:

1. **Given** 未登录且默认档=192K，**When** playurl 只下发 64K 音轨，**Then** 自动取 64K 正常播放，无错误提示中断。
2. **Given** 已登录（非大会员）且默认档=192K，**When** 音轨仅含 64K/132K，**Then** 取 132K。
3. **Given** 默认档=最高且账号为大会员，**When** 曲目提供 Hi-Res（flac）或杜比音轨，**Then** 最高档升级到该音轨；无此类音轨时取最高常规档。
4. **Given** playurl 请求失败，**When** 按所选档重试失败，**Then** 以 64K 档再重试一次，成功则播放，仍失败走既有降级链并提示既有错误文案。
5. **Given** 播放列表切到下一首，**When** 该首不支持所选档位，**Then** 按回落规则取流，播放不中断。
6. **Given** 播放中途登录态过期（下发音轨变少），**When** 下一首取流，**Then** 按当前实际登录态回落，不报错。

---

### Edge Cases

- **本地缓存曲目播放中**：曲目来自本地缓存文件（固定音质），音质面板显示"本地缓存"来源，不提供切换（切换会破坏缓存秒播的价值）。
- **DURL 降级流**：DASH 不可用降级到 durl 整段流时无音质档位概念，音质面板显示"不可用"或"默认"占位，不提供切换。
- **网络类型无法判定**（如以太网/未知）：按 Wi-Fi 默认档处理。
- **同一曲目反复切档**：连续快速切换以最后一次为准，不产生叠加的换流请求；网络切换自动换流与用户面板手动切档并发时，以最后触发者为准。
- **切剧中网络切换**：曲目正在解析/缓冲（切剧中）时网络类型变化，不叠加触发换流，新曲目直接按新网络默认档取流。
- **「仅在 Wi-Fi 环境播放」门控**：与既有确认弹窗逻辑不冲突，切档发生在已放行的播放会话内，不重新触发门控。
- **未登录但默认档为高档**：不做"强制要求登录"的阻断，仅静默回落 + 设置项/面板提示；登录后无需改设置自动取到高档。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 设置页 MUST 提供「Wi-Fi 默认音质」与「蜂窝默认音质」两个独立设置项，各支持四档：最高 / 192K / 132K / 64K，默认值分别为「最高」「132K」，选择后立即持久化。
- **FR-002**: 在线流取流时系统 MUST 按当前网络类型（Wi-Fi / 蜂窝，无法判定按 Wi-Fi）套用对应默认档位。
- **FR-003**: 系统 MUST 按回落算法选择实际音轨：期望档存在→取之；不存在→取不高于期望档的最高可用档；「最高」→最高可用档并在存在时升级 Hi-Res/杜比音轨；仍无可用→既有降级链（durl）兜底。
- **FR-004**: 播放页音质面板 MUST 列出当前曲目可用音轨档位、标示当前生效档；点选后立即换流保持进度；并 MUST 将所选档位写回当前网络对应的默认音质设置。
- **FR-005**: 系统 MUST 移除既有省流调音质链路——「优先低码率音频流」开关（设置页）、其存储键读取（播放控制）及取流函数的布尔低码率参数（服务层）——由档位选择机制整体重构取代，不得与新档位逻辑并存叠加；存量迁移：曾开启低码率开关→蜂窝默认音质置为 64K，未开启→保持默认值。
- **FR-011**: 「省流量模式」开关及其封面/头像不加载消费逻辑（迷你条、播放层等处按开关决定是否加载封面与 UP 主头像）MUST 完全保持原样，不随音质档位重构改动；「仅在 Wi-Fi 环境播放」门控逻辑亦保持原样。
- **FR-012**: 相关描述 MUST 随功能改动同步更新：设置页新增「音质」分组承载两项默认音质设置（分组标题、副标题、登录态提示文案与新结构一致），「省流量设置」分组保留剩余开关且其说明文案自洽；项目文档（PROJECT_NOTES 第三章本条目、ui-testing-playbook 设置页区块顺序描述等）涉及低码率开关/设置页结构的过期描述一并更新，不留陈旧文案。
- **FR-006**: 取流失败时系统 MUST 以 64K 档重试一次；期望档因登录态/会员权限缺失而不可用时 MUST 按回落算法静默降级，不中断播放。
- **FR-007**: 本地缓存播放与 durl 降级流场景，音质面板 MUST 显示不可切换的来源标识。
- **FR-008**: 设置项变更 MUST 对后续取流生效，不影响正在播放的曲目。
- **FR-010**: 播放中网络类型发生**稳定切换**（防抖确认，排除瞬时抖动）时，系统 MUST 对正在播放的在线流曲目立即按新网络默认档换流（保持进度、不打断）；本地缓存曲目、durl 降级流、正在切剧中的会话 MUST NOT 触发换流；换流失败 MUST 保持原流不中断（静默记录日志）。
- **FR-009**: 音质可用性 MUST 遵循登录态矩阵（未登录仅 64K；登录非大会员至多 132K；192K/Hi-Res/杜比需大会员）：设置页音质项 MUST 按当前登录态展示实际可用最高档提示（未登录时引导登录），且档位选择器在未登录时 MUST 仅显示「最高」与「64K」（132K/192K 不支持的档位不显示）；播放页面板 MUST 仅提供当前曲目实际可用的档位为可选项。

### Key Entities

- **音质档位（QualityTier）**: 四个用户可选项——最高 / 192K / 132K / 64K；后三档对应 B 站音频 qn 码（30280 / 30232 / 30216），「最高」无固定 qn（取最高可用，含 Hi-Res/杜比升级）。
- **可用音轨（AudioTrack）**: playurl DASH 响应中的单条音轨，含 B 站档位码、带宽、直链候选（base + backup）；Hi-Res（flac）与杜比音轨在响应的独立节点中、不带档位码。
- **默认音质偏好（DefaultQualityPrefs）**: 按网络环境（Wi-Fi / 蜂窝）各存一个档位值，持久化于应用设置存储。
- **登录态音质上限（LoginQualityCeiling）**: 由登录态与会员状态决定的实际可取最高档（匿名=64K、登录=132K、大会员=192K/Hi-Res），用于 UI 提示与面板可选项过滤。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户修改任一默认音质后，无需重启即可在下一首在线播放中按新档位取流（100% 生效）。
- **SC-002**: 播放页切换音质后进度保持误差在 ±2 秒内，播放不中断超过 5 秒。
- **SC-003**: 全部 4 档在有空档曲目、未登录账号、非大会员账号、无 Hi-Res/杜比音轨曲目上测试，均能正常出声，无错误弹窗（回落覆盖率 100%）。
- **SC-004**: 旧版本「优先低码率」开启用户升级后，蜂窝默认音质 100% 迁移为 64K。
- **SC-005**: 未登录状态下，设置项与播放面板 100% 展示登录限制提示/仅可用档位，不存在可点但必然失败的档位入口。

## Assumptions

- 既有「省流调音质」代码（存储键「优先低码率音频流」→ 播放控制读取 → 取流函数按带宽取最低/最高音轨的布尔参数链路）是本功能的前身：关闭开关时"取最高带宽"的现行为与新「最高」档语义一致，重构后该链路整体退役，存量用户（开关关闭）的 Wi-Fi 听感不回退。
- 「省流量模式」（仅控制封面/头像加载）与音质无关，保持不动。
- 复用现有网络类型判定（NetUtil.isWifi）与设置持久化机制（AppStore），不引入新存储层。
- 播放页音质面板复用现有底部弹层交互形态（与倍速/播放模式/睡眠定时面板同级入口）。
- Hi-Res/杜比音轨不作为独立可选档位，仅在「最高」档内升级；其可用性取决于登录态与大会员状态（登录态信息沿用现有 BiliSession/nav 接口能力，不新增鉴权链路），未登录时选择器隐藏 132K/192K（不支持的档位不显示，已存值登录后自动生效）。
- 登录态、请求头、风控参数沿用现有 BiliService 链路；登录态音质上限按「响应实际下发的音轨」为准（矩阵用于 UI 提示与预期管理），不做本地硬校验拦截。
- 播放中网络切换不自动换流（下一首生效），避免频繁重解析。

## Open Questions

- （已按默认处理，无阻塞项）播放页切档写回默认值采用 PiliPlus 交互；若后续希望"只临时生效不写回"，可在面板加开关位，不在本期范围。
