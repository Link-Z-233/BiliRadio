# Feature Specification: v0.4-Part1 UX 修复轮

**Created**: 2026-10-13  
**Status**: Draft  
**Input**: 用户反馈 12 项（播放层收起失效、详情页视觉、历史多选、MiniPlayer 闪现、音质档位不符、关于页重做等）

## Overview

针对 v0.4.0 浮层视觉重设计验证轮及日常使用中发现的 12 项体验问题做一次集中修复：3 项功能性 bug（收起按钮失效、MiniPlayer 闪现、按压态方角溢出）、2 项音质体系补全（会员态检测与档位过滤、档位显示与实际一致）、3 项浮层视觉对齐（视频详情页、关于页、展开指示按钮）、2 项历史面板交互升级（多选管理、移除清空按钮）、1 项用户身份展示（账号行头像）、1 项关于页内容重写（用户提供确切文案 + 项目地址）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 播放层收起按钮修复 (Priority: P1)

用户在播放层点左上角「▼」收起按钮，播放层必须关闭。现状：按钮渲染正常但点击无反应（滚动区手势仲裁吞掉点击，基线 69d8c7f 引入），用户只能靠下滑手势关闭。

**Why this priority**: 播放层是核心界面，返回路径断裂是最影响使用的缺陷。

**Independent Test**: 打开播放层 → 点击 (94,216) 附近收起按钮 → 播放层关闭。可用 hilog 命中链验证识别器参战。

**Acceptance Scenarios**:

1. **Given** 播放层展开（内容在顶部），**When** 点击收起按钮，**Then** 播放层关闭回到下层页面
2. **Given** 播放层内容滚动过，**When** 先滚回顶部再点收起按钮，**Then** 播放层关闭
3. **Given** 深色或浅色模式，**When** 点击收起按钮，**Then** 行为一致（与颜色无关）

---

### User Story 2 - 音质档位与实际一致 (Priority: P1)

音质选择页只提供当前账号状态实际可用的档位；因未登录/非大会员不可用的档位不出现，并给出对应提示。现状：已登录用户（含非会员）可选 192K，实际播放回落 132K——设置页显示 192K、播放层显示 132K，不符。192K（30280）为大会员专属档（biliRelay 实测）。

**Why this priority**: 音质档位显示与实际播放不符直接误导用户，且涉及付费权益边界。

**Independent Test**: 未登录/非会员/大会员三种状态下打开音质选择页，核对可选项与提示。

**Acceptance Scenarios**:

1. **Given** 未登录，**When** 打开音质选择页，**Then** 仅有「最高」「64K」选项，提示「未登录时最高 64K，登录后可用更高音质」
2. **Given** 已登录非大会员，**When** 打开音质选择页，**Then** 仅有「最高」「132K」「64K」选项，提示 192K 需大会员
3. **Given** 大会员，**When** 打开音质选择页，**Then** 「最高」「192K」「132K」「64K」全档可选
4. **Given** 会员过期后已存的 192K 档位，**When** 打开音质选择页，**Then** 选项中无 192K，显示收敛至可用档，不出现「挂着不可用档」

---

### User Story 3 - 设置页返回 MiniPlayer 平滑重现 (Priority: P1)

从设置页返回首页时，MiniPlayer 必须以单次连续动画平滑重现。现状：先消失、后突现（闪现）。

**Why this priority**: 设置页是高频访问页面，每次返回都出现视觉跳变。

**Independent Test**: 进入设置页 → 返回 → 观察 MiniPlayer 重现过程无闪现；快速往返多次验证无竞态回归。

**Acceptance Scenarios**:

1. **Given** MiniPlayer 有播放内容且在设置页（胶囊隐藏），**When** 返回首页，**Then** MiniPlayer 平滑滑入，无消失-突现序列
2. **Given** 快速连续进出设置页，**When** 停止操作，**Then** MiniPlayer 最终状态正确（首页可见、设置页隐藏），无卡死状态

---

### User Story 4 - 播放历史多选管理 (Priority: P2)

播放历史面板新增多选功能，交互与播放队列完全一致；同时移除头部「清空」按钮（全选+删除所选可清全部）。

**Why this priority**: 历史条目只能逐条左滑删除，批量管理缺失；清空按钮与多选语义重复。

**Independent Test**: 打开播放历史 → 多选若干条 → 删除所选 → 核对剩余列表。

**Acceptance Scenarios**:

1. **Given** 播放历史面板打开且有条目，**When** 查看头部，**Then** 有队列同款玻璃图标多选按钮，无「清空」按钮
2. **Given** 多选模式，**When** 点行勾选/取消，**Then** 勾选状态正确，操作行显示全选/删除所选(计数)/返回
3. **Given** 已勾选条目，**When** 点删除所选，**Then** 二次确认后批量删除，列表正确刷新
4. **Given** 面板关闭，**When** 重新打开，**Then** 多选状态已复位（不残留选中）
5. **Given** 历史为空，**When** 打开面板，**Then** 不显示多选按钮（对齐队列空态逻辑）

---

### User Story 5 - 多选态禁用左滑删除 (Priority: P2)

队列与历史进入多选模式后，左滑删除手势禁用，避免与勾选手势冲突。

**Why this priority**: 多选态下左滑仍会露出删除按钮，与滑动勾选手势冲突，易误删。

**Independent Test**: 进入队列/历史多选模式 → 左滑任意行 → 无删除动作。

**Acceptance Scenarios**:

1. **Given** 播放队列多选模式，**When** 左滑任一行，**Then** 不出现删除按钮/不触发删除
2. **Given** 播放历史多选模式，**When** 左滑任一行，**Then** 同上
3. **Given** 退出多选模式，**When** 左滑任一行，**Then** 左滑删除恢复正常

---

### User Story 6 - 视频详情页视觉对齐 (Priority: P2)

视频详情 sheet 的背景采用与播放队列面板相同的玻璃公式视觉（面板色、顶部分隔线）；标题旁展开指示按钮从裸「▼」文字字符换为系统图标（SymbolGlyph），旋转动画保留。保留系统 sheet 交互（拖拽条、下滑关闭）。

**Why this priority**: 详情 sheet 与重设计后的队列面板视觉割裂；裸文字字符与全应用系统图标语言不一致。

**Independent Test**: 播放层点标题区打开详情 sheet → 深浅两模式核对背景公式与指示按钮样式。

**Acceptance Scenarios**:

1. **Given** 播放层（浅色），**When** 打开视频详情 sheet，**Then** 面板背景与队列面板同款玻璃公式（同一令牌），顶部有同款分隔线
2. **Given** 深色模式，**When** 打开详情 sheet，**Then** 同样对齐（深色令牌）
3. **Given** 详情 sheet 关闭态，**When** 查看标题旁指示按钮，**Then** 为系统图标而非「▼」字符；打开/关闭时旋转动画正常
4. **Given** 详情 sheet 打开，**When** 下滑或点拖拽条，**Then** 系统 sheet 关闭行为保留

---

### User Story 7 - 关于页重做 (Priority: P2)

关于弹窗视觉与队列面板对齐（玻璃公式）；内容采用用户提供的确切文案（见 FR-009）；新增项目地址（点击二次确认后跳转浏览器）。

**Why this priority**: 关于页内容陈旧且不完整；系统 bindSheet 投影与玻璃浮层体系不一致。

**Independent Test**: 设置页 → 关于 → 核对新内容结构与项目地址交互。

**Acceptance Scenarios**:

1. **Given** 打开关于弹窗，**Then** 面板视觉为玻璃公式，与队列/详情面板一致
2. **Given** 阅读关于内容，**Then** 展示文案与 FR-009 引用的确切文案一致：简介一段、五条核心功能、关于本项目声明、项目地址，不含部署/运行/签名等开发向内容
3. **Given** 项目地址行（GitCode / GitHub 两条），或「关于本项目」声明中的 BiliMusic / PiliPlus 项目名，**When** 点击，**Then** 弹二次确认框；确认后拉起系统浏览器打开对应仓库页，取消则不跳转（四处交互一致）
4. **Given** 调试模式开启，**When** 查看关于面板，**Then** 原有调试模式开关与隐藏入口逻辑不受影响

---

### User Story 8 - 按压态方角修复 (Priority: P2)

设置页分组卡片首尾行按压时，按压背景必须跟随卡片圆角（现为方形按压背景盖过圆角，出现「方框阴影」）。日志页同模式一并修复。

**Why this priority**: 每次按压分组首尾行都出现视觉破损，深浅模式均存在。

**Independent Test**: 设置页按压任一分组第一行/最后一行 → 观察按压区域圆角无方角溢出。

**Acceptance Scenarios**:

1. **Given** 设置页任一分组，**When** 按压第一行，**Then** 按压背景顶部两角为圆角，与卡片轮廓一致
2. **Given** 任一分组，**When** 按压最后一行，**Then** 底部两角同样圆角无溢出
3. **Given** 日志页列表首尾条目，**When** 按压，**Then** 同样无方角溢出
4. **Given** 分组中间行按压，**When** 观察，**Then** 行为不回归（原有按压效果保留）

---

### User Story 9 - 账号行用户头像 (Priority: P3)

设置页账号行已登录时显示 B 站用户头像（圆形裁切），未登录保持原图标。

**Why this priority**: 身份可视化增强，非功能性。

**Independent Test**: 登录后打开设置页 → 账号行显示头像；登出 → 恢复原图标。

**Acceptance Scenarios**:

1. **Given** 已登录且 nav 返回头像 URL，**When** 打开设置页，**Then** 账号行显示圆形头像 + 昵称
2. **Given** 头像加载失败或 URL 为空，**When** 打开设置页，**Then** 回退原 person 图标（不显示空白）
3. **Given** 未登录，**When** 打开设置页，**Then** 账号行保持原 person 图标 + 「未登录」

---

### User Story 10 - 调试模式启动提醒 (Priority: P3)

app 启动时若调试模式已开启，toast 提醒「调试模式运行中」。

**Why this priority**: 开启调试后无全局可见状态，重启后用户不知日志仍在写入。

**Independent Test**: 开启调试模式 → 重启 app → 观察 toast；关闭调试 → 重启 → 无 toast。

**Acceptance Scenarios**:

1. **Given** 调试模式开启，**When** app 冷启动完成，**Then** toast「调试模式运行中」出现一次
2. **Given** 调试模式关闭，**When** app 冷启动，**Then** 无提醒

### Edge Cases

- nav 接口获取失败（网络异常）：按未登录/非会员处理（不给高档位选项），登录行显示不崩溃
- 会员过期后已存高档位：显示收敛至可用档（见 US2 场景 4）
- 快速往返设置页：MiniPlayer 隐显竞态不得回归（T021/R4 定时器逻辑保留）
- 头像 URL 失效：回退原图标
- 历史多选进行中面板被关闭：选中状态复位，重开不残留
- 队列/历史多选态系统返回：先退多选（现有语义保留）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 播放层收起按钮点击必须关闭播放层；修复方案按「先最小容器重构（对齐已知可用的同类按钮结构）、不生效再顶栏移出滚动区」两级推进
- **FR-002**: 视频详情 sheet（系统 bindSheet 保留）背景必须采用 GlassSheet 同款玻璃公式视觉（sheet_panel 令牌族 + 顶部分隔线），拖拽条与下滑关闭行为不变
- **FR-003**: 详情展开指示按钮必须为 SymbolGlyph 系统图标（替换「▼」文字字符），打开/关闭旋转动画保留
- **FR-004**: 播放历史面板头部必须提供多选按钮（队列同款 36×36 玻璃图标按钮），并移除「清空」按钮
- **FR-005**: 历史多选交互必须与队列一致：长按进入、点行勾选、全选/删除所选(计数)/返回操作行、批量删除二次确认、面板关闭自动复位
- **FR-006**: 队列与历史在多选模式下必须禁用左滑删除手势；退出多选后恢复
- **FR-007**: 设置页返回时 MiniPlayer 必须以连续动画平滑重现；实施时定位「消失-突现」根因并修复，不得引入快速往返竞态回归
- **FR-008**: 关于弹窗视觉必须与队列面板对齐（玻璃公式令牌族）
- **FR-009**: 关于页内容必须采用以下确切文案（用户提供），按「简介 → 核心功能 → 关于本项目 → 项目地址」排布，排除部署/运行/签名内容：

  > 把 B 站视频当播客听的鸿蒙音频应用：只取声音，不亮屏幕。订阅 UP 主、收藏夹、合集、系列，新视频自动标 NEW，一键入队；亦可通过粘贴链接或 BV 号手动添加。
  >
  > **核心功能**
  > - 订阅追更：UP 主 / 收藏夹 / 合集 / 系列四类源，新视频自动标 NEW
  > - 即点即听：粘贴链接或 BV 号，立即播放音频
  > - 随心播控：倍速、随机循环、睡眠定时、断点续播
  > - 后台不断：锁屏、控制中心、实况窗都能控制播放
  > - 听得讲究：四档音质可选，深浅色主题随心换
  >
  > **关于本项目**
  > 代码完全由 AI 生成（Vibecoding 作品），参考开源项目 BiliMusic（Apache 2.0）、PiliPlus（GPL-3.0）开发。个人学习自用作品，与哔哩哔哩官方无关。
- **FR-010**: 关于页必须提供四个可点击跳转项，交互统一为「点击弹二次确认 → 确认后拉起系统浏览器 → 取消不跳转」：
  - 项目地址（GitCode）：`https://gitcode.com/Link-Z-233/BiliRadio`
  - 项目地址（GitHub）：`https://github.com/Link-Z-233/BiliRadio`
  - 「关于本项目」声明中的 BiliMusic：`https://github.com/taotie256/BiliMusic`
  - 「关于本项目」声明中的 PiliPlus：`https://github.com/bggRGjQaUbCoE/PiliPlus`
- **FR-011**: app 冷启动时若调试模式已开启，必须 toast「调试模式运行中」
- **FR-012**: 设置分组卡片容器必须裁剪子内容（clip），使按压背景跟随圆角；日志页列表同修
- **FR-013**: nav 解析必须新增 `vipStatus` 与 `face` 字段并存入会话（内存态，随现有「启动+登录」链路刷新，登出清空，不落盘）
- **FR-014**: 音质选择页档位必须按登录+会员态过滤：未登录→[最高,64K]+登录提示；非会员→[最高,132K,64K]+192K 需大会员提示；大会员→全档；已存不可用档位显示收敛
- **FR-015**: 账号行已登录时必须显示用户头像（圆形裁切），未登录或头像不可用时保持原 person 图标

### Key Entities

- **BiliSession（扩展）**: 新增 `vipStatus: number`、`face: string` 内存字段；刷新链路沿用现有 nav 调用（启动 + 登录 + 懒触发兜底）；`clear()` 一并清零
- **音质档位可用矩阵**: 64K=全员；132K=登录；192K=大会员；「最高」=语义档（取当前可用最高）
- **多选状态（历史）**: 选中集合 + 选择模式标志，交互语义复制队列现实现

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 收起按钮点击关闭成功率 100%（模拟器多点采样 ≥10 次，hilog 命中链含新容器识别器）
- **SC-002**: 三种账号状态下音质选择页可选项与 FR-014 矩阵完全一致，零「显示档位 ≠ 实际播放档位」场景
- **SC-003**: 设置页往返 10 次零 MiniPlayer 闪现
- **SC-004**: 历史多选全选+删除所选等价完成原「清空」能力
- **SC-005**: 多选态左滑零删除触发（队列+历史各 5 次采样）
- **SC-006**: 分组首/尾/中行按压方角溢出零出现（深浅模式各验）
- **SC-007**: 详情/关于面板背景与队列面板像素级同公式（深浅模式）
- **SC-008**: 构建零错误零警告回归，全部既有功能不回归（验证轮回归清单）

## Assumptions

- VIP 判定以 nav 接口 `vipStatus` 为准；获取失败按非会员（保守：宁可少给档位不产生不符）
- vipStatus/face 刷新时机=启动+登录（与 uname/mid 同链路），不轮询不落盘
- 历史多选删除需二次确认（对齐队列「移除所选」语义）
- 「清空播放历史」能力由「全选+删除所选」承接，不再提供一键清空
- debug 启动提醒为冷启动一次性 toast，不含重复提醒
- 玻璃公式复用 GlassSheet 现有令牌，不新造色值
- 项目地址展示形式为 URL 文本行（gitcode 仓库页）
- 深浅两套视觉均纳入验证范围
