# Feature Specification: v0.5-part5 播放态数据源异常标记

**Input**: User description: "把这个和充电视频的简单判断一起做：未充电的用户点开充电视频时，拉取的音频时长一定会短于标识的视频时长，这样简单的判断能排除没充过电的视频" + 澄清轮：「根据设置项执行，默认跳过，并加一个X标记」「不需要持久化充电角标，同上加个X标记就行」「X标记代表获取的数据源异常，其中包括充电视频」「X不是会话级标记，是和播放完成标记等同的获取到的播放时长与音频时长不等的标记」+ 本轮修订：「先不做判别互动视频的功能，接口风控做不出来；先只根据时长做异常标记」+ 追加：「X 标记改成外围带圆圈（与 ✓ 一致）；播放列表清除已播也移除被 X 掉的视频」

## Overview

播放链路检测数据源异常并避雷：拉流后比较流时长与视频元数据时长，差异超阈值判定为异常（充电视频未充电仅得试听流，流时长显著短于元数据时长）。判定为异常的条目持久化 X 标记（与播放完成标记 ✓ 同级的持久化标记），在源页剧集行、队列条目、历史条目显示；播放到异常条目时按设置项处理（默认跳过并自动连播下一首，可设为照常播放试听流）。X 仅记确定性异常，瞬时拉流失败（网络错误/风控）不标。互动视频判定本轮不做。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 播放态充电视频检测与跳过 (Priority: P1)

用户播放队列中的充电视频（用户未对该 UP 充电）：拉流后发现流时长明显短于视频元数据时长，判定为试听流，该条目持久化标 X；按「异常源处理」设置执行（默认 toast 提示 + 跳过自动连播下一首）。

**Why this priority**: 用户实际遭遇（充电稿混入队列只得试听流），是本功能的核心避雷价值；时长比较是唯一可用判据（充电状态 API 被风控不可用）。

**Independent Test**: 真机播放队列中存量充电稿（如 BV12RYx6TE9r），观察 X 标记出现、跳过行为与连播。

**Acceptance Scenarios**:

1. **Given** 设置为「跳过」（默认），**When** 队列播放到充电稿，**Then** toast 提示 + 自动切下一首 + 该条目标 X（持久化）
2. **Given** 设置为「照常播放」，**When** 队列播放到充电稿，**Then** 试听流照常播放 + toast 提示 + 标 X
3. **Given** 正常视频，**When** 播放，**Then** 流时长≈元数据时长，不标 X 不跳过
4. **Given** 已标 X 条目，**When** 用户已充电后重播且拉到完整流，**Then** 清除 X 恢复正常

---

### User Story 2 - X 标记显示与持久化 (Priority: P2)

X 标记跨会话持久化（重启保留），与播放完成标记 ✓ 同级显示；显示范围：源页剧集行、队列条目、历史条目。异常条目试听播完不写播放完成哨兵（✓ 不因试听完成而产生）。

**Why this priority**: 标记的价值在跨会话可见；核心检测（US1）先行可用，显示与持久化让价值完整。

**Independent Test**: 播放异常条目产生 X 后重启应用，三处界面 X 仍在。

**Acceptance Scenarios**:

1. **Given** 某视频已标 X，**When** 重启应用查看源页/队列/历史，**Then** X 仍在
2. **Given** 异常条目在「照常播放」设置下试听播完，**When** 播放完成，**Then** 不产生 ✓（不写播放完成哨兵）、X 显示
3. **Given** 用户手动「标记已看完」一个 X 条目，**When** 操作完成，**Then** 用户主动行为优先，✓ 与 X 共存显示

---

### User Story 3 - 「异常源处理」设置项 (Priority: P2)

设置页新增「异常源处理」行：跳过（默认）/ 照常播放。本地持久化，切换即时生效。

**Why this priority**: 行为开关的 UI 入口；默认值内置，行本身不阻塞核心检测逻辑。

**Independent Test**: 切换设置后播放异常条目，行为随之变化；重启后保持。

**Acceptance Scenarios**:

1. **Given** 全新安装/未改动，**When** 查看设置页，**Then** 显示「跳过」
2. **When** 切换为「照常播放」，**Then** 重启后仍保持
3. **When** 切换设置，**Then** 下一次播放立即按新设置执行（无需重启）

---

### Edge Cases

- 多个异常条目连续出现在队列：逐个跳过自动连播，toast 沿用既有去重窗防刷屏，队列线性推进到队尾正常结束
- 整个队列均为异常条目：逐个跳过至队尾后停止（队列线性推进，无循环风险）
- 视频元数据时长缺失（duration=0/未知）：跳过时长检测，条目照常播放（宁可漏判不误判）
- 瞬时拉流失败（网络错误/风控 -412 等）：不标 X（仅既有 toast/日志），重试可恢复；防止弱网把好视频永久标异常
- 多P 视频单P 异常：X 以 bvid 为粒度（视频级标记）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 播放链路 MUST 在拉流后比较流时长与视频元数据时长，差异超阈值判定为数据源异常（试听流/充电视频）；阈值待真机实施校准
- **FR-002**: 判定为异常的条目 MUST 持久化 X 标记（重启保留），显示于源页剧集行、队列条目、历史条目
- **FR-003**: 设置页 MUST 提供「异常源处理」设置（跳过=默认 / 照常播放），本地持久化且切换即时生效
- **FR-004**: 「跳过」下播放到异常条目 MUST toast 提示并自动连播下一首；「照常播放」下 MUST 播放试听流并 toast 提示；两种模式均标 X
- **FR-005**: 异常条目试听播完 MUST NOT 写播放完成哨兵（不产生 ✓、不写入播放历史/云同步）
- **FR-006**: 瞬时拉流失败（网络错误/风控）MUST NOT 标 X
- **FR-007**: 已标 X 条目重播拉到完整流时 MUST 清除 X（用户充电后的恢复路径）
- **FR-008**: 连续跳过的 toast MUST 按既有去重窗去重，不刷屏
- **FR-009**: 时长比较 MUST 在元数据时长缺失（0/未知）时跳过检测，不误判

### Key Entities

- **数据源异常标记（X）**: per-bvid 持久化布尔标记，语义=「该视频拉到的流时长与元数据时长不等（试听流）」；与播放完成标记 ✓ 同级、独立存储、本地持久化（不云同步）
- **异常源处理设置**: 枚举（跳过 / 照常播放），默认「跳过」，本地持久化

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 真机播放队列存量充电稿（如 BV12RYx6TE9r），一次播放内完成 X 标记与跳过，自动连播下一首无人工干预
- **SC-002**: 重启应用后 X 标记保留，源页剧集行/队列条目/历史条目三处可见
- **SC-003**: 正常视频全流程零误标（刷新+播放大样本无 X 出现）
- **SC-004**: 「异常源处理」设置切换即时生效且重启保持

## Assumptions

- 未充电用户拉充电视频得试听流，流时长显著短于元数据时长（用户领域知识；真机日志佐证 DASH 缺失→durl 试听兜底；试听流确切时长未实测，阈值实施时校准）
- 流时长与元数据时长的取值点在 playurl 响应与 view 接口（具体字段名与单位实施时确定，如 timelength 口径）
- X 仅本地持久化，不云同步（云端无对应概念）
- 用户手动「标记已看完」不受 X 影响（用户主动行为优先，✓ 与 X 可共存）
- 充电视频检测依赖播放态（拉流后）判定，浏览列表阶段无法识别充电稿（列表数据无充电标记字段）
- 互动视频判定本轮不做（用户指示：接口风控做不出来）；若未来发现可靠免费判据可另开轮次
- 被跳过的异常条目不产生历史条目（历史 upsert 仅在 AVPlayer 真实出声的 playing 状态触发，跳过发生在 prepared 出声前）；「照常播放」的试听条目正常入历史

### User Story 4 - X 视觉统一与队列清理（追加）

X 标记图标改为外围带圆圈样式（`sys.symbol.xmark_circle`），与 ✓（`sys.symbol.checkmark_circle`）视觉档一致；播放列表「清除已播」将数据源异常（X 标记）条目一并纳入移除范围。

**Why this priority**: 三处显示点（源页剧集行/队列条目/历史行尾）的裸 X 与 ✓ 视觉不同档；队列中被 X 的条目对用户无收听价值，随「清除已播」一键清理。

**Independent Test**: 触发异常标记后查看三处图标为带圈 X；队列含 X 条目时点「清除已播」，X 条目随已播条目一并移除（当前播放条目保留）。

**Acceptance Scenarios**:

1. **Given** 异常条目已标 X，**When** 查看源页/队列/历史三处，**Then** 显示带圆圈红色 X（`xmark_circle`），字号/边距对齐 ✓ 视觉档
2. **Given** 队列含已播（✓）与异常（X）条目，**When** 点「清除已播」，**Then** 两类条目一并移除，确认弹窗计数含 X 条目
3. **Given** 当前正在播放的条目（含照常播放的试听条目），**When** 点「清除已播」，**Then** 当前播放条目保留不清

**追加 Functional Requirements**:

- **FR-010**: X 标记图标 MUST 使用带圆圈样式（`sys.symbol.xmark_circle`），三处显示点视觉档与 ✓（`checkmark_circle`）一致
- **FR-011**: 播放列表「清除已播」MUST 将 X 标记条目与已听完条目一并纳入移除范围（可清计数、确认弹窗、实际移除三处口径一致）；当前播放条目保留语义不变
