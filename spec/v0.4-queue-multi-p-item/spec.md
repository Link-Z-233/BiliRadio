# Feature Specification: 队列多P 视频条目化重写（v0.4-queue-multi-p-item）

**Created**: 2026-10-15  
**Status**: Draft（队列多P 条目化重写轮，独立目录）  
**Input**: 真机反馈三 bug——①队列视频头行无按压反馈、长按不进多选；②多选中多P 视频被计为多条；③横划删除只有第一P 跟着头行滑动。用户定案：重写播放列表多P 逻辑，「将多P 视频视为一个条目」；横划整组一起滑；计数全部按视频级；随机播放视频级抽取；存储保持分P 扁平不动。

## Overview

前三轮（`spec/v0.4-fix-multi-part`）把多P 视频展开为扁平分P 队列条目并在渲染时派生分组：组头被塞进组首分P 的列表条目里。该结构导致三个 bug 同根：头行交互缺失、多选按分P 计数、横划只动一个列表条目。本轮把队列的渲染与交互模型从「分P 条目」重写为「**展示条目**」：相邻同视频分P（≥2 条）构成一个组条目（头行 + 全部分P 窄行同属一个列表条目，一体滑动），单P 与孤立分P 保持整行条目。选择、计数、横划、按压反馈全部以条目为单位；随机播放抽取粒度升级为条目级（视频不被拆散）。队列存储、持久化格式、身份键（bvid+页号）、历史/续播/去重全部不动——纯展示层与播控语义层改造。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 组条目一体渲染与整组横划 (Priority: P1)

队列列表以条目为渲染单位：多P 视频相邻分P 构成一个组条目——视频头行与全部分P 窄行同属一个列表条目，左滑组内任意位置（头行或任一分P 行）时整组一起滑出，露出删除按钮；点击删除按钮或滑过阈值进入确认弹窗（标注整组分P 数），确认后整组移除（走既有批量移除链路，含当前条目自动切播）。单P 条目与孤立分P 条目保持原有整行形态与单条左滑删除。多选态不挂横划（现状保持）。

**Why this priority**: 直接修 bug ③（横划只有第一P 跟着动）——三个 bug 中视觉割裂最严重的一个；组条目模型是本轮重写的地基，其余故事都建立在它之上。

**Independent Test**: 队列含一个 10P 视频全部条目：左滑其头行或任意分P 行，头行+全部分P 应作为一个整体滑出；确认后整组消失；单P 条目左滑行为与改造前一致。

**Acceptance Scenarios**:

1. **Given** 队列含某 10P 视频全部条目（相邻），**When** 左滑其头行，**Then** 头行与全部分P 一起滑出，露出删除按钮
2. **Given** 已滑出删除按钮，**When** 点击删除按钮或滑过阈值，**Then** 弹出确认弹窗，文案标注整组分P 数；确认后该视频全部分P 移除，其余条目不受影响
3. **Given** 左滑对象是组内分P 行（非头行），**When** 左滑，**Then** 同样整组滑出（组为最小管理粒度不变，仅触发面扩大到组内任意行）
4. **Given** 单P 条目或孤立分P 条目，**When** 左滑，**Then** 单条滑出删除，行为与本轮改造前一致
5. **Given** 多选模式，**When** 查看列表，**Then** 不挂横划删除动作（现状保持）

---

### User Story 2 - 头行交互补全：按压反馈与长按多选 (Priority: P1)

视频头行获得与条目一致的交互能力：按下高亮、抬起/取消恢复（按压反馈）；长按头行进入多选模式且该组整组选中。非多选态点头行保持既有整组续播语义（两段判定：有历史播最新播放的分P 并从其进度续播，无历史播最小页从头起）；多选态点头行为整组切换。长按分P 行进多选（整组选中）为现状行为，保持。

**Why this priority**: 直接修 bug ①（头行无按压反馈、长按不进多选）——头行是组条目的主交互面，缺反馈与缺入口都是硬伤。

**Independent Test**: 队列含多P 组：按下头行立即高亮、抬起恢复；长按头行进入多选且该组选中；点头行按两段判定续播整组。

**Acceptance Scenarios**:

1. **Given** 队列含多P 组，**When** 手指按下头行，**Then** 头行高亮；抬起或滑出取消时恢复
2. **Given** 非多选态，**When** 长按头行，**Then** 进入多选模式，该组整组选中，徽标计 1
3. **Given** 该视频 P2 有历史进度，**When** 非多选态点击头行，**Then** 跳播组内 P2 条目并从历史进度续播
4. **Given** 该视频无任何历史，**When** 非多选态点击头行，**Then** 跳播组内最小页条目从头播放
5. **Given** 多选态，**When** 点击头行，**Then** 整组切换选中/取消

---

### User Story 3 - 组级选择与条目级计数 (Priority: P1)

多选以条目为最小选择单位：一个多P 组 = 1 个选择单位（头行 Checkbox 整组切换，组内分P 无独立勾选，现状 D15-Trim 语义保持），孤立分P = 1 个单位。队列全部计数面统一按条目口径：标题「播放队列 (N)」、多选删除徽标、全选、清空队列确认文案、清除已播计数——一个 10P 视频一律计 1。长按拖动范围选以条目为单位，拖过的组整组选中。确认移除后按分P 粒度删除存储条目（选中组 = 删该组全部分P）。

**Why this priority**: 直接修 bug ②（多选中被计为多条）——「视为一个条目」的核心落点；计数口径不统一会让组条目模型在多选场景立刻露馅。

**Independent Test**: 队列 = 一个 10P 视频 + 4 首单曲：标题显示 (5)；多选勾选该组，徽标显示 1；确认移除仅删该组分P，4 首单曲不受影响。

**Acceptance Scenarios**:

1. **Given** 队列 = 10P 视频全部条目 + 4 首单曲，**When** 打开队列面板，**Then** 标题显示「播放队列 (5)」
2. **Given** 多选模式，**When** 勾选 10P 组头行 Checkbox，**Then** 徽标显示 1（非 10）
3. **Given** 多选模式，**When** 点击全选，**Then** 全部条目选中（组算 1），徽标 = 条目数
4. **Given** 已勾选 10P 组并确认移除，**When** 移除完成，**Then** 该视频全部分P 从队列消失，4 首单曲保留
5. **Given** 多选模式长按某条目拖动，**When** 拖动经过多个条目，**Then** 拖过的组整组选中、单曲单独选中
6. **Given** 多选模式，**When** 点击清除已播/清空入口，**Then** 确认文案计数按条目（组算 1）

---

### User Story 4 - 随机播放视频级抽取 (Priority: P1)

随机播放模式的抽取单位从分P 升级为条目：抽中多P 组时从组内最小页条目起播，P1→Pn 顺序连播至组尾（各分P 独立断点续播语义自然继承），组播完后抽取下一个条目；抽中单P/孤立分P 条目直接播放。组内连播优先：随机模式下当前组还有下一分P 时，下一曲（手动与自然完播一致）先播组内下一分P。上一曲回溯轨迹保持分P 粒度，回溯回到上一个实际播放的分P。

**Why this priority**: 「视为一个条目」在播控层的对齐——随机模式若仍按分P 抽取，专辑/课程会被播放轨迹拆散，与条目化心智矛盾。

**Independent Test**: 随机模式，队列 = 10P 视频 + 4 首单曲：完播当前分P 后连播组内下一分P；组播完后随机抽取的对象是 5 个条目之一（组算 1），抽中组从最小页起播。

**Acceptance Scenarios**:

1. **Given** 随机模式，正在播放某 10P 组的 P3，**When** P3 自然完播或手动点下一曲，**Then** 播放组内下一分P P4（组内连播优先）
2. **Given** 随机模式，某组已播至组尾（最后一P），**When** 下一曲，**Then** 随机抽取下一个条目（该组与其余 4 首共 5 个单位），抽中组从组内最小页起播
3. **Given** 随机模式，抽中的组内某分P 有历史断点，**When** 起播该分P，**Then** 从断点续播（既有续播语义继承）
4. **Given** 随机模式，**When** 点上一曲，**Then** 回溯到上一个实际播放的分P（轨迹分P 粒度保持）
5. **Given** 队列仅含单P 条目，**When** 随机播放，**Then** 行为与本轮改造前一致（回归约束）

---

### Edge Cases

- **孤立分P 与完整组并存**（`?p=3` 先单独入队、整视频后入队）：P3 为独立条目（整行），其余 9 分P 构成组；随机抽取各自为独立单位；互不影响
- **组被外部途径打散**：清除已播按 bvid 整组删（组全删或全留）；重复入队去重按分P 跳过——不存在「组被删到剩 1 条」的新增路径，孤立分P 退化为独立条目（现状回退行为保持）
- **多选期间队列变化**（播放推进/其他入口删除导致条目变化）：选中集按现存条目收敛，队列清空自动退出多选（现状语义保持）
- **旧持久化数据与占位条目展开**（前三轮 D8 就地展开）：展开后分P 相邻即自动成组，无组时整行，读取/展示/播放不崩溃
- **随机抽中组且组内最小页分P 有断点**：经既有起播路径自动断点续播，不强制从头
- **拖选高度换算**：组条目高度可变（头行+分P 窄行），拖选换算按条目为单位，允许保守估算（拖选偏保守只影响效率不影响正确性，现状口径延续）
- **组内分P 数极大**（百级）：单组条目整体渲染与整组横划的流畅度留真机验证，不预设上限
- **面板关闭/系统返回退出多选**：现状语义保持（关闭即复位多选与选中集）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 队列列表 MUST 以展示条目为渲染单位：相邻（≥2 条）同视频分P 条目构成一个组条目（视频头行与全部分P 窄行同属一个列表条目、一体滑动）；单P 条目与孤立分P 条目保持原有整行形态；随机打散、插入等导致的非相邻分P 不成组
- **FR-002**: 组条目 MUST 整体响应横划：左滑组内任意行整组滑出删除动作，确认弹窗标注整组分P 数，确认后走既有批量移除链路（含当前条目自动切播）；单P/孤立条目保持单条左滑；多选态 MUST NOT 挂横划
- **FR-003**: 视频头行 MUST 具备按压反馈（按下高亮、抬起/滑出取消恢复）并支持长按进入多选（整组选中）；非多选态点击头行 MUST 保持整组续播两段判定（有历史播最新分P 从其进度续播，无历史播组内最小页）
- **FR-004**: 多选选择单位 MUST 为展示条目：组 = 1 个选择单位（头行 Checkbox 整组切换，组内分P 无独立勾选），孤立分P = 1 个单位；选中集在条目变化时 MUST 按现存条目收敛
- **FR-005**: 队列全部计数面 MUST 统一条目口径：标题计数、多选删除徽标、全选、清空确认文案、清除已播确认计数（组一律算 1）
- **FR-006**: 多选移除与整组移除 MUST 按分P 粒度删除存储条目（移除组 = 删该组全部分P），移除链路与当前条目自动切播语义与既有行为一致
- **FR-007**: 长按拖动范围选 MUST 以条目为单位：拖过的组整组选中、孤立条目单独选中；高度换算允许保守估算
- **FR-008**: 随机播放抽取粒度 MUST 为条目：抽中组从组内最小页条目起播并顺序连播至组尾，组播完抽取下一个条目；当前组还有下一分P 时下一曲 MUST 优先组内连播（手动与自然完播一致）；上一曲回溯轨迹保持分P 粒度
- **FR-009**: 队列存储、持久化格式、身份键（bvid+页号）、入队去重、历史/续播/完播逻辑 MUST 保持既有形态不变（纯展示层与播控语义层改造，回归约束）
- **FR-010**: 单P 视频全链路行为 MUST 与改造前一致；旧持久化数据与占位条目展开路径 MUST 继续正常工作（回归约束）
- **FR-011**: 组内各分P 的独立进度、断点续播、完播标记语义在组内连播路径下 MUST 保持不变（自然继承既有机制，不引入新播放语义）

### Key Entities *(include if feature involves data)*

- **展示条目（组条目/单条目）**: 队列面板渲染与交互的最小单位，纯展示层派生（自扁平分P 队列按相邻性分组），不落持久化；组条目含视频头行与分P 窄行，单条目为原有整行
- **选择单位**: 多选、计数、批量移除的最小单位 = 展示条目（组算 1）；存储删除仍按分P 粒度展开
- **随机抽取单位**: 随机播放的抽取单位 = 展示条目；抽取结果为组时起播组内最小页

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 左滑多P 组任意行，头行与全部分P 作为一个整体滑出并可确认移除，无「只有第一P 跟着动」现象
- **SC-002**: 头行按下即高亮、抬起/滑出恢复；长按头行进入多选且整组选中
- **SC-003**: 勾选一个 10P 组徽标显示 1；标题计数、全选、清空确认、清除已播计数全部按条目口径（10P 视频 + 4 单曲 = 5）
- **SC-004**: 随机模式下多P 组不被拆散抽取：组内顺序连播至组尾，组播完才抽取下一个条目；上一曲回溯分P 粒度正常
- **SC-005**: 既有分P 展开、连播、独立进度、历史归并、去重、占位展开全部回归通过（存储与身份零变化）
- **SC-006**: 构建 + 部署通过（验证范围默认 build-only）

## Assumptions

- 基线 master（v0.4），前序轮次（`spec/v0.4-fix-multi-part` 第一至四轮）已交付，本轮在其基础上重写
- 组为最小管理粒度维持（D15-Trim）：单分P 不可单独删/勾，绕行 = 整组移除后重新入队 `?p=N`
- 已播标记口径维持 bvid 级宽松口径（D7）；头行不加已播标记（维持现状）
- 「首」计数文案在组语境下指条目（视频）数；组内「共 nP」标注保持
- 随机抽取的条目单位与展示条目一致（孤立的分P 独立抽取）；随机模式不重排队列列表顺序（现状保持，随机只影响播放轨迹）
- 手动下一曲与自然完播在组内连播语义上一致，不提供「跳过整组」专用操作（跳过 = 横划移除或逐分P 前进）
- 多选态头行 Checkbox 沿用「无半选态，部分选中显示未选」口径（管理收敛头行后组勾选恒全选/全不选）

## Open Questions

- 组内分P 数极大（百级）时单列表条目整体渲染、整组横划、拖选高度换算的流畅度与手感需真机校准（实施后登记待验）
- 清除已播在「组已播但组内仅部分分P 在队列」的混合场景下的计数口径（按现存条目算 1）是否直觉，留真机反馈
