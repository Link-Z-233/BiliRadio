## Overview

本特性针对第 6 轮实机反馈集中修复 15 项（另含 README 版本信息移除），覆盖四个区域：

1. **首页订阅列表与存储实时同步**：修复退订后条目复活、添加后封面/最新条目不刷新的陈旧缓存缺陷，磁盘存储成为渲染唯一真相源。
2. **源详情页**：触底加载恢复常规触发（删除 endArmed 手势武装机制，惯性滚动也能加载）；剧集行信息重排（标题占满整行、NEW/已播标识移至时间行最右端、时间补时刻）；已播标记改为听完才显示且绿色醒目。
3. **列表边缘提醒**：三个列表（首页订阅/源详情/播放历史）触顶/触底时呈现对齐鸿蒙设置风格的回弹过冲提醒（内容跟手拉出边缘、空隙内显示提示文字、松手回弹后消失），源详情页与触底加载联动。播放队列暂不接入（后续整体大改时一并处理）——已于 queue-redesign 轮（2026-10-10）接入底部「已经到底了」提醒，销项。
4. **播放历史与设置页**：从历史发起播放后返回先只关历史面板（播放浮层保持）；移除历史面板底部的全局状态文案；封面全场景按显示尺寸取图且非 Wi-Fi 降档省流；设置页六项调整（日志二级页、退出登录二次确认、分组与文案更名、播放历史入口位置）。
5. **文档与版本号**：README 移除版本号信息（「版本」小节与起版说明行）；应用版本号本轮不动（保持 0.1.0），待播放列表重做完成后统一更新（登记入 PROJECT_NOTES 规划）。
6. **系统播控进度条修复（补录 bug）**：播放历史重播的曲目在锁屏/控制中心进度条完全不显示——历史重播重建曲目时时长置 0，且播放器取得真实时长后不回推系统会话；修复时长传递与回推。

另有 3 项登记入 PROJECT_NOTES 规划不实现：订阅源导出导入、关于页文案优化、版本号更新（待播放列表重做后统一更新）。播放队列的边缘提醒本轮不接入，待队列整体大改时一并处理——已于 queue-redesign 轮（2026-10-10）接入销项。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首页订阅列表与存储实时同步 (Priority: P1)

用户删除订阅源（源详情页退订或首页长按删除）后返回首页，被删条目立即消失；添加新订阅后，行立即出现在列表中，首次刷新完成后封面与最新条目标题随即显示；刷新失败时有可见提示，行保留不损坏。后台静默刷新进行中发生的删除不会被刷新回调"复活"。

**Why this priority**: 首页是应用主入口，列表与实际数据不一致直接摧毁信任，属数据正确性缺陷。

**Independent Test**: 添加一个订阅→删除它→观察首页，全程不重启应用即可验证。

**Acceptance Scenarios**:

1. **Given** 已订阅多个源, **When** 进入源详情页退订并返回首页, **Then** 被删条目立即从首页消失
2. **Given** 首页, **When** 长按条目选择删除订阅, **Then** 条目立即消失（现状不回归）
3. **Given** 添加订阅面板完成订阅, **When** 面板关闭回到首页, **Then** 新行立即出现在列表中
4. **Given** 新订阅行刚出现, **When** 首次刷新完成, **Then** 行内封面与最新条目标题更新显示（无图模式时封面占位不变）
5. **Given** 新订阅首次刷新失败, **When** 失败发生, **Then** 用户获得可见提示，行保留可正常进入源页
6. **Given** 静默刷新进行中, **When** 用户删除某一订阅, **Then** 该订阅不会因刷新回调被写回存储或复活于列表

### User Story 2 - 源详情页触底加载恢复常规触发 (Priority: P1)

用户在源详情页用惯性滚动（甩动后手指离开屏幕）滚到底部时，加载更早内容被正常触发；按住底端不会连发请求（并发护栏保留）；已到最早内容时停止加载。endArmed 手势武装机制（上轮防 403 风暴的临时防御，APP 签名链已真机验证可靠）删除。

**Why this priority**: "拖到底不能刷新"是用户明确反馈的功能回归，且删除 endArmed 是既定规划（PROJECT_NOTES 下轮候选 #1）。

**Independent Test**: 源页甩动一次不触碰屏幕，列表滚到底后自动加载更早一页。

**Acceptance Scenarios**:

1. **Given** 源详情页列表较长, **When** 惯性滚动到底（手指已抬离）, **Then** 自动触发加载更早一页并无缝追加
2. **Given** 正在加载更早一页, **When** 再次触底, **Then** 不重复发起请求（护栏保留）
3. **Given** 已到最早内容, **When** 触底, **Then** 不再发起请求
4. **Given** 加载失败, **When** 用户再次滚到底, **Then** 可重试（失败不再永久没收触发权）
5. **Given** 翻页追加, **Then** 既有去重、页界与到底判定语义不回归

---

### User Story 3 - 源详情页剧集行信息重排与已播标记 (Priority: P1)

用户查看源详情页剧集列表：标题占据整行宽度可完整展示；NEW 徽标与已播标识移到时间行（日期·时长行）的最右端；发布时间显示到时刻（如 2026-10-08 14:30）；已播标识仅对已听完的条目显示（听了一半不算已播），且为醒目的绿色，与未播条目明确区分。

**Why this priority**: 源详情页是最高频浏览页，信息行布局与已播语义直接影响日常可用性。

**Independent Test**: 打开任一有播放记录的订阅源即可完整验证布局、时间粒度与已播标记。

**Acceptance Scenarios**:

1. **Given** 任一剧集行, **When** 渲染, **Then** 标题独占一行（不被右侧徽标挤压）
2. **Given** 时间行, **When** 渲染, **Then** 发布时间显示日期＋时刻（YYYY-MM-DD HH:mm）
3. **Given** 未看过的最新条目, **When** 渲染, **Then** NEW 徽标位于时间行最右端
4. **Given** 已听完的条目, **When** 渲染, **Then** 显示绿色已播标识（位于时间行最右端）
5. **Given** 听了一半（有进度未听完）或从未播放的条目, **When** 渲染, **Then** 不显示已播标识
6. **Given** NEW 与已播同时成立的条目, **When** 渲染, **Then** 两标识均在时间行右端且不互相遮挡
7. **Given** 触底加载的更早条目, **When** 渲染, **Then** 布局与时间格式一致

---

### User Story 4 - 播放历史返回层级与底部文案修复 (Priority: P1)

用户从播放历史点击条目开始播放（全屏播放浮层弹出）后：按系统返回键仅关闭底部的历史面板，播放浮层保持打开、播放不中断；再次按返回才收起播放浮层、回到设置页。播放历史面板底部不再显示"在首页添加订阅，或在播放队列中粘贴BV号开始收听"等全局状态文案。

**Why this priority**: 返回层级违背用户直觉（用户按返回预期收起历史面板而非播放页）＋错误文案，均为明确行为缺陷。

**Independent Test**: 设置页→播放历史→点条目播放→连按返回验证层级；观察面板底部无引导文案。

**Acceptance Scenarios**:

1. **Given** 历史面板打开且播放浮层在其上层, **When** 按系统返回键, **Then** 仅历史面板关闭，播放浮层保持打开、播放继续
2. **Given** 历史面板已关、播放浮层打开, **When** 再按返回, **Then** 浮层收起，回到设置页
3. **Given** 历史面板打开, **When** 查看面板底部, **Then** 无全局状态/引导文案
4. **Given** 浮层内下滑或点收起按钮退出（历史面板未先关）, **When** 浮层收起, **Then** 维持现状回到历史面板（不回归）
5. **Given** 其他入口（首页胶囊、队列）打开的浮层, **When** 按返回, **Then** 既有关闭行为不回归
6. **Given** 历史面板打开, **When** 点击条目播放失败, **Then** 用户仍能获得可见错误反馈

---

### User Story 5 - 列表触顶/触底回弹过冲提醒 (Priority: P2)

用户在首页订阅列表、源详情页、播放历史三个列表中滚动到顶部或底部边缘后继续拉动时，内容跟手拉出边缘、边缘空隙内显示提示文字（对齐鸿蒙系统设置的回弹过冲行为），松手后内容回弹归位、提示随之消失，明确告知已到边缘，不再误判"还能刷新"。源详情页的底部提示与触底加载联动：可加载时提示加载中，到底时提示没有更多。播放队列暂不接入（后续整体大改时一并处理）。

**Why this priority**: 体验打磨项，消除"到底没反应"的困惑，但依赖 US2 的触发机制先恢复。

**Independent Test**: 在三个列表分别滚到顶/底边缘后继续拉动，观察内容跟手拉出、空隙提示出现与松手回弹消失。

**Acceptance Scenarios**:

1. **Given** 任一列表滚动到顶部边缘, **When** 继续下拉, **Then** 内容跟手拉出、顶部空隙显示"已经到顶了"，松手回弹后提示消失
2. **Given** 首页订阅/历史列表滚动到底部边缘, **When** 继续上拉, **Then** 底部空隙显示"已经到底了"，松手回弹后消失
3. **Given** 源详情页可加载更早, **When** 触底, **Then** 触发加载且提示加载中
4. **Given** 源详情页已到最早内容, **When** 触底, **Then** 提示没有更多，不重复刷屏
5. **Given** 过冲提示显示期间, **When** 再次过冲, **Then** 同一边缘仅一条提示，不叠加
6. **Given** 列表内容不足一屏, **When** 打开页面, **Then** 无过冲、不触发提示

### User Story 6 - 封面按显示尺寸取图与非 Wi-Fi 省流 (Priority: P2)

应用内所有封面按显示场景请求合适尺寸的缩略图：列表缩略图沿用小图；播放页大封面与系统播控（锁屏/控制中心）封面从原图改为按显示尺寸取缩略图。非 Wi-Fi 网络下封面进一步降档省流；无图模式行为不变（不加载）。

**Why this priority**: 流量与内存优化，用户点名"能控制图片质量"，确认采用固定优化＋非 Wi-Fi 降档方案。

**Independent Test**: 播放任一内容，检查播放页大封面与锁屏播控封面的加载请求为带尺寸后缀的缩略图；切换 Wi-Fi/移动网络对比尺寸。

**Acceptance Scenarios**:

1. **Given** Wi-Fi 网络播放内容, **When** 打开播放页, **Then** 大封面请求带尺寸后缀的缩略图（非原图）
2. **Given** Wi-Fi 网络播放内容, **When** 查看锁屏/系统播控, **Then** 播控封面请求缩略图且显示清晰
3. **Given** 非 Wi-Fi 网络, **When** 各场景加载封面, **Then** 请求尺寸低于 Wi-Fi 档（省流档）
4. **Given** 无图模式开启, **When** 任意场景, **Then** 封面不加载（现状不回归）
5. **Given** CDN 不支持尺寸后缀的封面 URL（如 UP 头像/合集封面原链）, **When** 加载, **Then** 不拼后缀直接加载（现状 raw 逻辑不回归）

### User Story 7 - 设置页六项调整 (Priority: P2)

用户在设置页看到：播放历史入口紧邻登录区（账号分组下方）；「日志查询」点击后进入独立二级页（系统返回回设置页），不再是悬浮面板；「退出登录」点击弹出二次确认对话框，取消则不登出；「音质」分组更名为「默认音质」；「蜂窝默认音质」文案改为「移动网络默认音质」（含选择器标题）；「无图与网络设置」分组更名为「省流」。

**Why this priority**: 纯设置页局部调整，风险低但涉及新二级页路由，排 P2。

**Independent Test**: 逐项点检设置页文案、位置、日志页进出与登出确认。

**Acceptance Scenarios**:

1. **Given** 设置页, **When** 查看, **Then** 播放历史入口位于登录区正下方
2. **Given** 设置页, **When** 点击「日志查询」, **Then** 以二级页形式进入日志页，系统返回回到设置页
3. **Given** 日志二级页, **When** 使用, **Then** 既有日志查看/清空/导出能力不回归
4. **Given** 已登录, **When** 点击「退出登录」, **Then** 弹出二次确认；确认后登出，取消则保持登录
5. **Given** 设置页, **When** 查看, **Then** 分组名显示「默认音质」，无「蜂窝」字样（移动网络默认音质），分组「无图与网络设置」更名为「省流」
6. **Given** 设置页其他功能（登录、开关、外观、关于）, **When** 操作, **Then** 均不回归

### User Story 9 - 系统播控进度条为空修复（历史重播链路） (Priority: P1)

用户从播放历史重播任意条目时，锁屏/控制中心等系统播控组件的进度条正常显示：有总时长、随播放走动、可拖动；不再出现进度条完全不显示的情况。订阅源等其余链路现状保持不回归。

**Why this priority**: 系统播控是后台收听的核心控制入口，进度条缺失直接阻塞「锁屏拖进度」主流程；根因明确（历史重播重建曲目时时长置 0，播放器取得真实时长后不回推系统会话），一行根因修复＋一处兜底回推即全链路可靠。

**Independent Test**: 从播放历史重播任一条目，查看锁屏/控制中心进度条出现且总时长正确、随播放走动；应用内进度条不回归。

**Acceptance Scenarios**:

1. **Given** 播放历史中含时长的条目, **When** 点击重播, **Then** 系统播控组件显示进度条、总时长正确且随播放走动
2. **Given** 任意链路起播时曲目时长未知（推送系统会话的时长为 0）, **When** 播放器 prepared 取得真实时长, **Then** 系统会话时长被回推修正，进度条出现
3. **Given** 订阅源链路播放, **When** 查看系统播控, **Then** 进度条行为不回归
4. **Given** 系统播控进度条, **When** 拖动, **Then** 播放位置跳转正常（既有 seek 链路不回归）

### Edge Cases

- 静默刷新进行中删除订阅：刷新回调持有旧数组引用，写盘/渲染不得使已删订阅复活（并发一致性）
- 添加订阅后立即退订（刷新未完成）：行出现与消失均即时，无残留
- 源页触底加载失败后：下次触底可重试；按住底端不产生连发请求
- NEW 与已播同时成立（看完后又出新集判定）：两标识同行右端共存不遮挡
- 听完判定沿用既有「已听完」进度语义（听完 = 播放历史中该条为已完成状态）
- 历史面板先经返回关闭后，播放浮层下滑退出直接回设置页（不再出现历史面板）
- 非Wi-Fi 省流档下封面清晰度下降属预期；网络类型不可得时按显示尺寸档处理
- 触顶/触底提示在快速连续滚动时只保留单例，不叠加、不闪烁
- 日志二级页进出不产生日志数据丢失（内存环形缓冲语义不变）
- 退出登录确认弹窗期间轮询中的登录流程须先停止再执行登出
- 历史条目时长为 0（旧版本写入的记录）：prepared 兜底回推后系统播控进度条仍可显示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 首页订阅列表渲染 MUST 以订阅存储为单一真相源：任何入口删除订阅后，首页条目立即消失，刷新进行中亦不得复活
- **FR-002**: 添加订阅后新行 MUST 立即出现在首页；首次刷新成功后封面与最新条目标题 MUST 随即显示
- **FR-003**: 添加订阅首次刷新失败 MUST 给用户可见提示，且不损坏已添加的行
- **FR-004**: 源详情页触底加载 MUST 恢复常规触发（删除 endArmed 手势武装机制），惯性滚动触底可触发；加载中并发护栏与到底终止语义 MUST 保留
- **FR-005**: 触底加载失败后 MUST 允许下次触底重试
- **FR-006**: 源详情页剧集行：标题 MUST 独占整行；NEW 徽标与已播标识 MUST 位于时间行最右端
- **FR-007**: 剧集发布时间 MUST 显示日期＋时刻（YYYY-MM-DD HH:mm）
- **FR-008**: 已播标识 MUST 仅对已听完条目显示；未听完/未播条目 MUST NOT 显示已播标识；标识样式 MUST 醒目（绿色）
- **FR-009**: 首页订阅、源详情、播放历史三个列表滚动到顶/底边缘后继续拉动时 MUST 呈现回弹过冲（内容跟手拉出、松手回弹归位），过冲空隙内 MUST 显示边缘提示文字（对齐系统设置行为）；播放队列本轮不接入
- **FR-010**: 源详情页底部提示 MUST 与触底加载联动：加载中提示加载、到底提示没有更多
- **FR-011**: 从播放历史发起播放后按系统返回 MUST 仅关闭历史面板，播放浮层保持打开且播放不中断；再次返回收起浮层回到设置页
- **FR-012**: 播放历史面板底部 MUST NOT 显示全局状态/引导文案
- **FR-013**: 播放页大封面与系统播控封面 MUST 按显示尺寸请求缩略图（CDN 尺寸后缀），不再加载原图
- **FR-014**: 非 Wi-Fi 网络下封面请求 MUST 降档省流（低于 Wi-Fi 档尺寸）；无图模式与 raw URL 逻辑 MUST NOT 回归
- **FR-015**: 日志 MUST 改为独立二级页（自设置页跳转进入，系统返回回设置页），移除悬浮面板形态
- **FR-016**: 退出登录 MUST 弹出二次确认对话框，取消不登出
- **FR-017**: 设置分组「音质」MUST 更名为「默认音质」
- **FR-018**: 「蜂窝默认音质」文案 MUST 更改为「移动网络默认音质」（含选择器标题）
- **FR-019**: 设置分组「无图与网络设置」MUST 更名为「省流」
- **FR-020**: 播放历史入口 MUST 位于登录区正下方
- **FR-021**: README MUST 补充 PiliPlus 项目引用
- **FR-022**: 订阅源导出导入、关于页文案优化、版本号更新（待播放列表重做后统一更新）MUST 登记入 PROJECT_NOTES 规划章节，本轮不实现
- **FR-023**: 既有功能（无图模式、队列操作、NEW 计数、订阅刷新、其余返回路径、登录流程）MUST NOT 回归
- **FR-024**: README MUST NOT 含版本号信息——「版本」小节与起版说明行**直接删除**，原位置不补任何替代表述；AppScope/app.json5 版本号 MUST 保持 0.1.0/1000 不动
- **FR-025**: 播放历史重播重建曲目时 MUST 传入历史条目已存时长（秒），不得置 0
- **FR-026**: 播放器 prepared 取得真实时长后，若此前推送系统会话的时长为 0，MUST 回推修正（force 重推 AVMetadata）；播放态上报 MUST 含时长字段（AVPlaybackState.duration），保证系统播控进度条全链路可用

### Key Entities *(include if feature involves data)*

- **首页订阅列表数据源**: 渲染与磁盘订阅存储实时一致；内存副本仅为派生视图，变更后须从存储重载
- **封面尺寸档**: 列表缩略档 / 大封面档（播放页与播控）/ 非Wi-Fi 省流档——同一 CDN 尺寸后缀机制的不同取值
- **已播判定**: 沿用播放历史「已听完」进度语义（听完才入已播集合）
- **列表边缘提示**: 回弹过冲空隙内文字、随回弹归位消失（无独立计时器）；源详情页底部与加载状态联动的三态（可加载/加载中/没有更多）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 退订后返回首页，被删条目 100% 消失；添加订阅后行即时出现、刷新完成后 2 秒内封面与最新条目可见
- **SC-002**: 惯性滚动（无后续触摸）触底即触发加载更早一页；按住底端期间请求数不超过 1 个/页
- **SC-003**: 三个列表触顶/触底过冲均出现空隙提示文字，松手回弹后消失，连续过冲不叠加
- **SC-004**: 从播放历史播放后：第一次返回仅历史面板关闭、播放页保持；第二次返回回到设置页
- **SC-005**: 播放页与系统播控封面请求均为带尺寸后缀的缩略图；非 Wi-Fi 下请求尺寸低于 Wi-Fi 档
- **SC-006**: 已播标识仅出现在听完条目且为绿色；标题占满整行、时间显示到分钟
- **SC-007**: 历史重播曲目的系统播控进度条 100% 显示，总时长与应用内一致

## Assumptions

- 过冲提示的视觉细节（位置/字号/回弹曲线）对齐鸿蒙系统设置的观感，具体取值实现时定
- 非Wi-Fi 省流档与各显示档的具体尺寸由实现时定（省流档低于对应显示档）
- 网络类型不可得时按显示尺寸档处理（等同 Wi-Fi 档）
- 「返回先关历史面板」仅改变系统返回路径；浮层内下滑/收起按钮路径维持现状（历史面板未关时回面板）
- 历史面板移除底部状态行后，点击条目播放失败的反馈路径实现时确保可见（如 toast）
- 未听完条目不显示任何进度类标识（不做"听到一半"中间态）
- 日志二级页复用现有日志列表与清空/导出能力，仅改承载形态（sheet → 路由页）
- 绿色已播标识的具体色值沿用应用色彩资源体系，实现时定
- README 的 PiliPlus 引用作为参考项目说明，置于现有致谢/引用段落附近
- 时间格式统一为 YYYY-MM-DD HH:mm（24 小时制，分钟粒度）
