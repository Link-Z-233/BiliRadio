# Feature Specification: 第三轮实机反馈批次（ux-feedback-round3）

**Created**: 2026-10-05
**Status**: Draft
**Input**: 用户实机运行第二轮产物后反馈的 13 项问题/需求 + 8 项决策问答

## Overview

用户在实机验证第二轮（ux-feedback-round2，含流式播放）后提出第三批体验反馈：1 个视觉 bug（加载圆弧未贴合播放按钮）、6 项 UI/UX 调整（封面下移、队列标题独占一行、无任务占位提示、详情完整标题、更多按钮回设置页、下拉刷新禁用）、4 项功能（应用内日志页、播控中心 ±15 秒微调、播完列表即停、单击条目仅入队单条）、1 项文档治理（KNOWN_ISSUES.md 改名 PROJECT_NOTES.md 并重构结构、登记已移除/禁用功能），另附 2 项 roadmap 记录（列表添加逻辑后续重构预告、403 根因修复延后——本轮仅以日志观察）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 加载圆弧贴合播放按钮（Priority: P1）

播放页缓冲时，加载圆弧应紧贴播放按钮边缘、与按钮同心，而不是悬浮在按钮外围的固定尺寸区域里。当前实现中圆弧位于 88×88 的外圈容器内，与按钮尺寸不匹配导致视觉上"不贴"。

**Why this priority**: 用户点名的视觉 bug，影响播放页核心控件观感；改动小、风险低。

**Independent Test**: 触发缓冲状态（播放无缓存歌曲），观察圆弧与播放按钮的相对位置。

**Acceptance Scenarios**:

1. **Given** 正在缓冲一首无缓存的歌曲, **When** 播放按钮上方出现加载圆弧, **Then** 圆弧紧贴按钮边缘（同心圆、间隙均匀且尽量小），不再出现"圆弧远大于按钮"的悬浮感
2. **Given** 缓冲完成, **When** 圆弧消失转为常驻低透明度圆环, **Then** 该圆环同样贴合按钮边缘

---

### User Story 2 - 无播放任务时播放器显示占位提示（Priority: P1）

当前无任何播放任务时播放器区域显示异常/空白。用户要求：无播放任务时显示明确的占位提示（如"暂无播放内容"）。

**Why this priority**: 首次使用/清空队列后的空态体验，影响应用可用性观感。

**Independent Test**: 清空播放队列（或新装应用首次进入），查看播放器相关区域。

**Acceptance Scenarios**:

1. **Given** 播放队列为空且无历史播放任务, **When** 用户查看播放器（迷你条与播放层）, **Then** 显示占位提示文案（如"暂无播放内容"），不显示残留的旧歌曲信息或空白控件
2. **Given** 从空态添加歌曲并播放, **When** 播放任务建立, **Then** 占位提示消失，正常显示歌曲信息

---

### User Story 3 - 首页下拉刷新注释禁用（Priority: P2）

首页的下拉刷新功能暂时禁用：将相关代码注释保留（不删除），并加注释标记指向 PROJECT_NOTES.md 登记条目。

**Why this priority**: 用户明确指令的临时禁用，保留代码以便将来恢复。

**Independent Test**: 在首页执行下拉手势，刷新不再触发。

**Acceptance Scenarios**:

1. **Given** 首页处于任意滚动位置, **When** 用户执行下拉手势, **Then** 不出现刷新指示器、不触发刷新逻辑
2. **Given** 代码审查, **When** 查看下拉刷新相关代码, **Then** 代码以注释形式保留并带有指向 PROJECT_NOTES.md 的标记，未删除

---

### User Story 4 - 更多按钮直达设置页并删除 MorePage（Priority: P2）

首页右上角"更多"按钮改回直接打开原设置页（播放历史、关于本就是设置页中的选项）；上一轮新建的 MorePage 及其路由注册整体删除，不留死代码。

**Why this priority**: 用户实机体验后认为独立更多页多余，回退上一轮的设计决策。

**Independent Test**: 点击首页右上角按钮，直达设置页；全局搜索 MorePage 无残留。

**Acceptance Scenarios**:

1. **Given** 首页, **When** 点击右上角"更多"按钮, **Then** 直接打开设置页，可访问播放历史与关于
2. **Given** 代码库, **When** 检索 MorePage 相关文件与路由注册, **Then** MorePage.ets 已删除、router_map 中对应条目已移除，无死代码残留

---

### User Story 5 - 播放队列标题独占一行（Priority: P2）

队列面板头部改为两行结构：第一行为"播放队列"标题（可带"共 N 首"计数），第二行为操作按钮（定位/搜索/多选/清空）。多选模式行（全选/移除所选/返回）保持独立。

**Why this priority**: 纯布局优化，缓解标题与按钮挤在一行的局促感。

**Independent Test**: 打开播放队列半模态，检查头部布局。

**Acceptance Scenarios**:

1. **Given** 播放队列含多首歌曲, **When** 打开队列面板, **Then** "播放队列"标题独占第一行，定位/搜索/多选/清空按钮位于第二行
2. **Given** 头部高度变化, **When** 列表滚动, **Then** 列表 contentStartOffset 随头部实际高度自动跟随，顶部渐变模糊正常

---

### User Story 6 - 单击订阅源条目仅入队该条目（Priority: P2）

在订阅源节目列表中单击单个条目时，只将该条目加入播放队列并播放，不再将整个订阅源的所有条目入队。

**Why this priority**: 用户明确的行为修正；同时用户预告"后续列表添加逻辑还会改"，需在 PROJECT_NOTES.md 登记。

**Independent Test**: 进入某订阅源详情，单击其中一个视频条目，检查队列只新增该条。

**Acceptance Scenarios**:

1. **Given** 订阅源详情页含多个视频条目, **When** 单击其中一条, **Then** 播放队列仅新增该条目并立即播放
2. **Given** 用户需要整源入队, **When** 使用"播放全部"类按钮, **Then** 整源入队行为保留（本故事不移除该入口，如有）

---

### User Story 7 - 播完列表即停（Priority: P2）

顺序/倒序模式下播放到队列末尾后停止（不回绕到第一首），显示"播放结束"类状态；随机模式与单曲循环不受影响。用户手动点"下一首"仍可回绕（主动行为不限制）。

**Why this priority**: 用户期望的自然听单结束行为；当前 next() 取模回绕导致无限循环播放。

**Independent Test**: 建立含 2 首歌的队列，顺序播完第二首，确认停止。

**Acceptance Scenarios**:

1. **Given** 顺序模式播放队列最后一首, **When** 该首播放完成, **Then** 播放停止（不回绕第一首），状态提示"播放结束"
2. **Given** 倒序模式播放到队列第一首（倒序的末尾）, **When** 播放完成, **Then** 同样停止不回绕
3. **Given** 随机模式或单曲循环, **When** 播放完成, **Then** 行为保持现状（随机续播/单曲重播）
4. **Given** 任意模式停在列表末尾, **When** 用户手动点"下一首"按钮, **Then** 回绕到第一首继续播放（主动操作不受限）

---

### User Story 8 - 播控中心/通知栏 ±15 秒时间微调（Priority: P3）

系统播控中心（通知/锁屏媒体控件）增加 ±15 秒快进快退微调按钮，并默认展示；若系统 API 不支持自定义按钮默认展示，则实现 API 能力范围内的最优方案并在 PROJECT_NOTES.md 记录限制。

**Why this priority**: 后台/锁屏听单时的常用操作；API 支持度需设计阶段查证，存在降级风险。

**Independent Test**: 播放中拉下播控中心，使用 ±15 秒按钮，确认进度前后跳 15 秒。

**Acceptance Scenarios**:

1. **Given** 应用正在后台播放, **When** 打开系统播控中心, **Then** 展示 ±15 秒微调按钮（或 API 限制下的最优等价物）
2. **Given** 播放中, **When** 点击 +15 秒按钮, **Then** 播放进度后跳 15 秒；点击 -15 秒按钮前跳 15 秒（与播放页内 seek 行为一致，含防抖）
3. **Given** 系统 API 不支持, **When** 设计阶段查证后, **Then** 采用降级方案并在 PROJECT_NOTES.md 登记系统限制与原因

---

### User Story 9 - 应用内日志页（Priority: P3）

设置页新增"日志查询"入口，打开应用内日志页：记录网络请求（URL 摘要、响应码）、关键错误（含 403 等风控/网络失败）与时间戳，内存保留最近数百条，用于排查"首次添加 UP 报 403、重启后正常"这类问题。本轮仅观察不修根因。

**Why this priority**: 问题排查基础设施；403 根因修复已明确延后（roadmap），日志先行。

**Independent Test**: 触发一次失败的订阅添加，进设置 → 日志查询，能看到对应记录。

**Acceptance Scenarios**:

1. **Given** 设置页, **When** 打开"日志查询", **Then** 显示日志列表（时间、类别、摘要），按时间倒序
2. **Given** 发生一次网络请求（含失败）, **When** 重新打开日志页, **Then** 该请求的 URL 摘要与响应码/错误信息出现在列表中
3. **Given** 日志累计超过保留上限, **When** 新日志写入, **Then** 最旧的日志被淘汰（环形淘汰），应用内存占用稳定
4. **Given** 首次添加 UP 报 403 的场景复现, **When** 查看日志, **Then** 能看到 403 发生的接口、时间与上下文，足以辅助定位

---

### User Story 10 - 播放页封面下移与详情完整标题（Priority: P3）

播放页封面图整体下移一点（增加顶部呼吸感）；点击箭头展开详情时显示完整标题（当前被截断）。

**Why this priority**: 纯视觉微调，放低优先级批量处理。

**Independent Test**: 打开播放页观察封面位置；展开详情查看标题。

**Acceptance Scenarios**:

1. **Given** 播放页, **When** 查看封面区域, **Then** 封面相对现状明显下移，顶部留白增加，整体布局不失衡
2. **Given** 当前歌曲标题较长, **When** 点击箭头展开详情, **Then** 完整标题逐行显示不被截断（可换行/滚动），收起后仍保持单行省略样式

---

### User Story 11 - PROJECT_NOTES.md 文档治理（Priority: P3）

KNOWN_ISSUES.md 改名为 PROJECT_NOTES.md 并重构为三章结构：①已知问题（迁移 KI-1~KI-4）②已移除与禁用功能（登记：下载页、folders 页、列表同步、封面染色、首页下拉刷新禁用）③规划与预告（列表添加逻辑后续重构、403 根因修复、音质选择、点赞/投币/收藏、历史云端同步等延后项统一归档）。

**Why this priority**: 文档治理不阻塞功能，但为后续迭代建立统一登记处。

**Independent Test**: 文档改名生效、旧文件不存在、三章结构完整、各条目可追溯。

**Acceptance Scenarios**:

1. **Given** 仓库根目录, **When** 查看文档, **Then** 存在 PROJECT_NOTES.md，KNOWN_ISSUES.md 不再存在（git mv 保留历史）
2. **Given** PROJECT_NOTES.md, **When** 检查内容, **Then** 三章结构完整：已知问题（KI-1~KI-4 原样迁移）、已移除与禁用功能（含移除原因/位置/恢复线索）、规划与预告（含用户预告的列表添加逻辑重构、403 根因修复等）
3. **Given** 本轮其他故事的代码改动, **When** 涉及禁用/移除, **Then** 均在 PROJECT_NOTES.md 有对应登记条目

---

### Edge Cases

- 无播放任务时用户点击播放/上一首/下一首：占位态下这些操作应安全无副作用（不崩溃、不播放残留）
- 播完即停发生在流式播放中段报错后跳下一首的场景：错误重试链路仍按现状工作，仅"自然播完"触发即停
- 队列为空时播控中心/通知栏控件：系统侧不应显示可用的微调按钮（无活动会话）
- 日志记录本身抛异常（极端内存压力）：日志失败不得影响播放主流程（静默丢弃）
- 封面下移后在窄屏/小字号下：详情展开与收起时布局不溢出、不遮挡
- MorePage 删除后：曾通过更多页访问的入口（播放历史、关于）在设置页中完整可用，无功能丢失

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 播放按钮的加载圆弧与常驻圆环 MUST 紧贴按钮边缘（同心、间隙均匀），随按钮实际尺寸适配，不再使用与按钮脱节的固定外圈容器
- **FR-002**: 无播放任务时，播放器（迷你条与播放层）MUST 显示占位提示文案，不显示残留歌曲信息或空白控件；播放任务建立后占位提示 MUST 消失
- **FR-003**: 首页下拉刷新功能 MUST 以注释方式禁用（代码保留、带 PROJECT_NOTES.md 指向标记），下拉手势不触发刷新
- **FR-004**: 首页右上角"更多"按钮 MUST 直接打开设置页；MorePage.ets 文件与 router_map 中 morePage 路由注册 MUST 删除，不留死代码
- **FR-005**: 播放队列面板头部 MUST 为两行结构：标题行（含计数）与操作按钮行；多选操作行保持独立；列表偏移 MUST 随头部实际高度自动适配
- **FR-006**: 订阅源详情页单击单个条目 MUST 仅将该条目加入播放队列并播放；整源入队入口（如有）行为保留
- **FR-007**: 顺序/倒序模式播放到队列末尾 MUST 停止并提示"播放结束"，不回绕；随机模式与单曲循环 MUST 保持现状；手动点击"下一首" MUST 仍可回绕
- **FR-008**: 系统播控中心 MUST 尽力展示 ±15 秒微调按钮并默认展示；若系统 API 不支持，MUST 采用能力范围内最优降级方案并在 PROJECT_NOTES.md 登记限制
- **FR-009**: 设置页 MUST 提供"日志查询"入口，展示应用内日志（时间、类别、URL 摘要、响应码/错误摘要），按时间倒序
- **FR-010**: 网络层（BiliService 请求链路）MUST 记录请求与响应码/错误到内存日志缓冲，含 403 等失败场景；缓冲 MUST 环形淘汰（保留上限数百条级）；日志写入失败 MUST 静默处理不影响主流程
- **FR-011**: 播放页封面 MUST 相对现状下移，顶部留白增加且布局不失衡
- **FR-012**: 详情展开视图 MUST 显示完整标题（不截断）；收起视图保持单行省略
- **FR-013**: KNOWN_ISSUES.md MUST 改名为 PROJECT_NOTES.md（git mv 保留历史）并重构为三章：已知问题、已移除与禁用功能、规划与预告
- **FR-014**: PROJECT_NOTES.md 的"已移除与禁用功能"MUST 登记：下载页（DownloadsPage/DownloadManager/DownloadedSong）、folders 页、列表同步、封面染色、首页下拉刷新禁用（本轮）
- **FR-015**: PROJECT_NOTES.md 的"规划与预告"MUST 登记：列表添加逻辑后续重构（用户预告）、403 首次添加根因修复（本轮仅日志观察）、音质选择/默认音质、点赞/投币/收藏、历史云端同步

### Key Entities *(include if feature involves data)*

- **LogEntry（日志条目）**: 一条应用内日志记录，属性：时间戳、类别（网络/错误/其他）、URL 或来源摘要、响应码或错误摘要；仅内存存储、环形淘汰，不落盘
- **占位提示态（EmptyPlayerState）**: 播放器无任务时的显示状态，覆盖迷你条与播放层两个展示位置，随播放任务建立/销毁自动切换

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 缓冲状态下圆弧与播放按钮边缘目视贴合（同心、无明显悬浮间隙），缓冲完成后的常驻圆环同样贴合
- **SC-002**: 清空队列后播放器显示占位提示，添加歌曲后占位消失——空态与播放态切换 100% 正确
- **SC-003**: 首页下拉手势 100% 不触发刷新；队列面板标题独占一行且列表滚动无遮挡
- **SC-004**: 含 2 首歌的队列顺序播完：100% 停止不回绕；随机/单曲循环行为与改动前一致
- **SC-005**: 播控中心微调按钮可用（或降级方案落地且限制已登记），点击 ±15 秒进度变化误差 ≤ 1 秒
- **SC-006**: 复现一次失败请求后，日志页 100% 可查到对应记录（含 403 场景）；日志缓冲内存占用有上限、不随时间无限增长
- **SC-007**: 全局检索 MorePage 零残留；设置页功能入口完整（播放历史、关于可达）
- **SC-008**: PROJECT_NOTES.md 三章结构完整，KNOWN_ISSUES.md 不存在，git 历史保留

## Assumptions

- "封面下移一点"取适度增量（视觉呼吸感明显、布局不失衡为准），具体数值由实现阶段以多尺寸目测确定
- 占位提示文案默认"暂无播放内容"，实现时可按上下文微调措辞
- 日志保留上限默认数百条（如 500 条），类别先做网络/错误两类，后续可扩展
- 播控中心自定义按钮的系统 API 支持度未知，设计阶段查证；HarmonyOS AVSession 若不支持自定义按钮默认展示，接受"仅通知栏控件/仅部分场景展示"类降级
- 手动"下一首"在列表末尾回绕到第一首属预期行为（用户主动操作）
- 用户手工注释的代码：工作区与历史提交中未发现（已扫描），本轮登记以可追溯的历史移除项为准；若用户后续指出具体位置再补录
- 403 根因（疑首次启动 buvid/风控初始化时序）本轮不修，日志功能先行观察

## Open Questions

- 播控中心自定义按钮的 API 支持度与降级方案边界（设计阶段查证，不阻塞需求确认）
