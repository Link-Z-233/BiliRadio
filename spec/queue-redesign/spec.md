# Feature Specification: 播放列表重做（队列抽屉精简重构 + 睡眠定时播完暂停）

**Created**: 2026-10-09  
**Status**: Draft  
**Input**: User description: "规划一下播放列表的修改吧，风格和播放历史一样……保留多选和边缘渐变模糊，但所有按钮改成图标……全砍（搜索/定位/BV 添加行），这些按钮和标题计数放一行……再加个清除已看完；清除已播不含播放中条目，但播完未切状态的要清；定时播放中添加一个播完暂停"

## Overview

播放队列抽屉（QueueSheet/QueueDrawer）从「两行文字按钮 + 输入行 + 搜索浮层」的重形态，重构为与播放历史面板同款的简洁风格：单行头部（标题计数 + 图标按钮组）+ 纯列表 + 左滑删除。同时收编三项既定暂缓规划（KI-3 队列左滑删除、队列 EdgeHint 边缘提醒、新增「清除已播」），并为睡眠定时新增「播完暂停」模式——当前条目播完停原条目暂停，其产生的「播完状态」纳入清除已播的判定。搜索浮层、定位按钮、BV 添加输入行整体移除；添加订阅面板成为唯一单视频入口，其入队行为与订阅源详情页「点单集」统一收敛为「追加不打断」，两条入队路径补 toast 反馈与常驻提醒文案。

**本轮仅产出规划工件，不实施代码**——实现轮待另一会话 bug 修完后启动。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 队列头部精简为单行图标（Priority: P1）

用户打开队列抽屉，看到与播放历史面板同构的单行头部：「播放队列 (N)」标题计数在左，右侧一排图标按钮（清除已播 / 多选 / 清空）。搜索浮层、定位按钮、BV 添加输入行不复存在；列表条目仍保留当前播放高亮与上下边缘渐变模糊。非多选态下列表滚动行为、点击切歌行为与现状一致。

**Why this priority**: 「风格和播放历史一样」是本轮核心诉求；头部与布局定型是其余故事（左滑删除、清除已播、EdgeHint）的宿主，不定型则后续故事无处挂载。

**Independent Test**: 打开队列抽屉即可完整验证头部形态、图标按钮、被移除功能的缺席、保留项（渐变模糊/当前高亮/点击切歌）的无回归。

**Acceptance Scenarios**:

1. **Given** 队列有 N≥1 首歌，**When** 打开队列抽屉，**Then** 头部为单行：左侧「播放队列 (N)」粗体标题，右侧依次为清除已播、多选、清空三个图标按钮，无文字按钮
2. **Given** 队列抽屉已打开，**When** 查看界面，**Then** 搜索按钮、搜索浮层、定位按钮、BV 号输入行、「添加并播放」按钮均不存在
3. **Given** 队列非空且正在播放某一首，**When** 滚动列表，**Then** 当前播放条目标题为强调色高亮，列表上下边缘保留渐变模糊过渡
4. **Given** 非多选态，**When** 点击任一条目，**Then** 切换播放该条目（不跳转播放页，行为同现状）
5. **Given** 队列为空，**When** 打开抽屉，**Then** 显示空态文案，引导语不再提「输入BV号」，改为引导前往订阅源
6. **Given** 队列为空，**When** 查看头部，**Then** 清除已播、多选、清空按钮不可用或隐藏（对齐播放历史空态处理）

---

### User Story 2 - 左滑删除单条（Priority: P1）

用户在队列列表上左滑任一条目，右侧露出「删除」按钮，点击后该条目从队列移除；正在播放的条目不受其他条目删除影响。左滑删除与长按进入多选、竖向滑动连选的手势互不干扰（横向滑动 vs 长按+竖向）。

**Why this priority**: KI-3 既定暂缓项，明确挂到本轮队列大改；是队列管理最高频的轻量操作，与多选批量删除互补。

**Independent Test**: 在含 2 条以上队列上左滑任一条目点删除，可独立验证；与长按多选交叉操作可验证手势共存。

**Acceptance Scenarios**:

1. **Given** 队列有 N≥2 首，**When** 左滑非播放中条目并点击删除，**Then** 该条目消失、计数减一、其余条目与播放状态不变
2. **Given** 多选模式，**When** 左滑条目并删除，**Then** 删除生效且多选模式不退出（或按实现定义一致行为），已勾选集合同步剔除该条目
3. **Given** 队列列表，**When** 长按条目后竖向滑动，**Then** 进入多选并连选（现状保留），左滑手势不误触发
4. **Given** 正在播放条目 A，**When** 左滑删除另一条目 B，**Then** A 播放不中断、进度不回退
5. **Given** 左滑删除当前正在播放的条目，**When** 点击删除，**Then** 沿用现有移除语义（与多选删除当前条目行为一致），不新增第三种行为

---

### User Story 3 - 睡眠定时「播完暂停」（Priority: P2）

用户打开播放层定时按钮面板，在既有倒计时时长选项外看到「播完暂停」选项；选中后取代倒计时（单选互斥）。当前条目播放至末尾时，播放器停在原条目（不切下一首）、进度停在末尾、进入暂停态；用户手动切歌/点选条目即解除该模式继续正常播放。

**Why this priority**: 用户新增诉求；「播完状态」是 US4 清除已播判定的一类输入，但清除已播的状态判定同时涵盖队列末尾自然播完，故两者互不强依赖、同优先级。注意：睡眠定时功能整体为 KI-6 未实机验证项，本故事与其同链路。

**Independent Test**: 播放任一条目，选「播完暂停」后拖进度至末尾附近等其播完，可独立验证停原条目、暂停、手动解除三步。

**Acceptance Scenarios**:

1. **Given** 播放中且无定时，**When** 在定时面板点选「播完暂停」，**Then** 该选项呈选中态，无倒计时进行
2. **Given** 倒计时进行中，**When** 点选「播完暂停」，**Then** 倒计时取消、播完暂停生效（单选互斥，后者取代前者）
3. **Given** 播完暂停已选、条目 A 播放中，**When** A 播至末尾，**Then** 不切换下一首、进度停在末尾、播放器暂停
4. **Given** 播完暂停已触发暂停，**When** 手动点下一首（或点队列任一条目），**Then** 正常切歌并继续播放，播完暂停解除
5. **Given** 播完暂停已选尚未触发，**When** 再次打开面板点击「播完暂停」，**Then** 取消选中、恢复无定时状态
6. **Given** 播完暂停触发暂停后，**When** 手动点播放/继续按钮，**Then** 当前条目从头重播（进度已在末尾，不空转）

---

### User Story 4 - 清除已播（Priority: P2）

用户点击头部「清除已播」图标，弹二次确认对话框；确认后移除队列中当前播放条目**之前**的全部条目。当前条目本身：播放中（含未播完的暂停）则保留、继续播放；处于「播完未切下一首」状态（播完暂停触发、或队列末尾自然播完停止）则一并移除，播放器保持暂停、不自动续播。无可清条目时 toast 提示，不弹确认框。

**Why this priority**: 用户新增诉求；听播客/歌单场景下清理已听内容高频，但依赖头部定型（US1）与移除链路（US2）先就位。

**Independent Test**: 播放队列中部某条后点清除已播（分别在播放中/播完暂停两态下），可独立验证移除范围、播放连续性、空结果 toast。

**Acceptance Scenarios**:

1. **Given** 当前播放第 5 条且播放中（前 4 条已播），**When** 点清除已播图标并在确认框点「清除」，**Then** 前 4 条移除、第 5 条保留且持续播放不中断，计数更新
2. **Given** 当前条目处于播完未切状态（播完暂停触发，或队列末尾自然播完），**When** 清除已播，**Then** 前缀条目与当前条目全部移除；队列仍有剩余时播放器保持暂停、无当前播放条目，队列清空时为空态
3. **Given** 当前播放队首第 1 条且播放中，**When** 点清除已播图标，**Then** toast 提示无可清条目，不弹确认框、队列不变
4. **Given** 队列为空，**When** 查看头部，**Then** 清除已播按钮不可用或隐藏（与多选/清空同步处理）
5. **Given** 清除已播确认框已弹出，**When** 点「取消」或点遮罩，**Then** 队列原样不变
6. **Given** 清除已播移除了播完状态的当前条目且队列有剩余，**When** 点任一条目，**Then** 从该条目正常开始播放

---

### User Story 5 - 队列边缘提醒接入（Priority: P3）

用户在队列列表滚动到底后继续上拉，列表过冲露出的空隙显示「已经到底了」提示，松手回弹后提示消失——与首页订阅、源详情、播放历史三列表行为一致（复用 EdgeHint 组件）。

**Why this priority**: round6 既定暂缓项（「播放队列后续整体大改时一并处理」），纯体验补齐，依赖列表容器定型（US1）。

**Independent Test**: 队列条目多于一屏时滚到底继续上拉即可独立验证。

**Acceptance Scenarios**:

1. **Given** 队列条目超过一屏，**When** 滚到底后继续上拉，**Then** 底部空隙显示「已经到底了」，松手回弹后提示消失
2. **Given** 队列条目不足一屏，**When** 查看列表，**Then** 无可滚动过冲，不显示提示（无需额外处理）

---

### User Story 6 - 单视频入队统一收敛与入队反馈（Priority: P2）

用户在添加订阅面板输入单视频（BV 号/av 号/视频链接/短链）提交后，该视频**追加**到播放队列尾部，**不打断**当前播放（队列空时直接开始播放）；入队结果以 toast 反馈（已追加/开始播放/已在队列）。订阅源详情页「点单集」现状已是追加不打断，本轮仅补同款 toast 反馈——两条单视频入队路径行为与反馈完全一致。面板输入框下方补常驻提醒文案说明该行为。

**Why this priority**: 队列 BV 输入行移除后添加订阅面板成为唯一单视频入口，原「addByBv 追加不打断」规划（US6 后续）落到此入口收敛；无反馈的静默追加会被误判为点击无效（同源页刷新无反馈假象教训）。

**Independent Test**: 播放任一歌曲状态下，在添加订阅面板输入另一个 BV 号提交，可独立验证不打断 + toast；到源详情页点单集交叉验证行为一致。

**Acceptance Scenarios**:

1. **Given** 队列非空且正在播放条目 A，**When** 在添加订阅面板输入单视频 B 提交，**Then** B 追加到队尾、A 持续播放不中断，toast 提示「已加入队列」
2. **Given** 队列为空，**When** 面板输入单视频 B 提交，**Then** B 开始播放，toast 提示「开始播放」
3. **Given** 单视频 B 已在队列中，**When** 面板再次输入 B 提交，**Then** 不重复入队、不跳播，toast 提示「已在队列中」
4. **Given** 队列非空且正在播放条目 A，**When** 在源详情页点单集 B，**Then** B 追加到队尾、A 不中断（现状保持），toast 提示「已加入队列」
5. **Given** 添加订阅面板打开，**When** 查看输入框下方，**Then** 常驻说明行含「单视频将加入播放列表，不打断当前播放」语义文案
6. **Given** 面板提交单视频成功，**When** 观察页面，**Then** 面板关闭、toast 反馈入队结果，不再自动唤起播放层（不打断场景跳转到正在播放的旧曲目会造成困惑）

### User Story 7 - 登记收尾与版本号更新（Priority: P3）

本轮实现完成后：PROJECT_NOTES 中 KI-3 队列左滑删除销项、队列边缘提醒暂缓项销项、「addByBv 追加不打断」规划标记已实现（经添加订阅面板入口统一收敛，见 US6）、「版本号更新待播放列表重做完成后统一执行」按既定安排执行；睡眠定时新增播完暂停模式入 KI-6 登记更新（播完暂停实机验证时顺带覆盖 KI-6 既有待验证点，通过则一并销项）。

**Why this priority**: 多条既定规划锚点在「播放列表重做」，本轮是销项时点；不销项则登记与现状漂移。

**Independent Test**: 检查 PROJECT_NOTES 相应条目状态与版本号即可独立验证。

**Acceptance Scenarios**:

1. **Given** 本轮实现完成，**When** 查看 PROJECT_NOTES，**Then** KI-3 中队列左滑删除标记完成、round6 边缘提醒队列接入标记完成、addByBv 追加不打断规划标记已实现（经添加订阅面板入口收敛）、KI-6 补充播完暂停模式与验证状态、版本号条目按新版本号更新
2. **Given** 本轮实现完成，**When** 查看应用版本信息，**Then** 版本号不再为 0.1.0/1000（具体数值见 Assumptions）

### Edge Cases

- **删除后 LazyForEach 同步**：单条左滑删除与批量清除已播必须增量刷新懒加载列表，长队列不得整表闪烁回顶（对齐播放历史 notifyDataDelete 增量语义）
- **清除已播的当前索引换算**：移除前缀后播放中条目的索引必须正确前移；移除播完当前条目后当前索引置空（无当前条目态），不得错位自动切歌
- **播完暂停与手动操作竞争**：条目播完瞬间用户同时点下一首/上一首，不得既切歌又触发暂停残留
- **播完暂停后手动继续播放**：进度已在末尾，继续播放须从头重播当前条目，不得空转或静默无响应
- **定时模式互斥切换**：倒计时进行中切「播完暂停」（及反向）须干净取代，不得双重触发或双双失效
- **多选态下队列被外部改变**（播放完成自动移除/其他入口入队）：已勾选集合须同步剔除失效条目（沿用现状过滤逻辑）
- **确认框与抽屉关闭竞争**：清除已播确认框弹出时关闭抽屉，不得残留悬空确认框或对已卸载组件回调
- **左滑未点删除即滚走/收起**：滑动状态自然复位，不残留半开的删除按钮
- **KI-6 链路风险**：睡眠定时整体未经实机验证（倒计时归零暂停、后台节流校准），播完暂停与其同控制器，实现轮须一并实机验证

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 队列头部 MUST 为单行布局——左侧「播放队列 (N)」标题计数（样式对齐播放历史面板标题），右侧图标按钮组，删除现有两行头部（标题行+操作行）结构
- **FR-002**: 搜索浮层、定位按钮（含定位闪烁高亮）、BV 号输入行、「添加并播放」按钮及相关 UI 链路 MUST 全部移除
- **FR-003**: 头部与多选操作行的全部按钮 MUST 改为图标按钮（无文字标签），删除/清空类按钮使用危险色；图标须可辨识其语义
- **FR-004**: 队列条目 MUST 支持左滑露出「删除」按钮、点击执行删除的交互（对齐播放历史约定，不做滑过阈值直删）
- **FR-005**: 左滑删除 MUST 与长按进入多选、竖向滑动连选手势共存，互不误触发
- **FR-006**: 多选模式 MUST 保留——长按进入、勾选/连选/全选/移除所选/返回能力不回退，操作行按钮改图标
- **FR-007**: 列表上下边缘渐变模糊 MUST 保留，模糊分区 MUST 随精简后的头部高度自适应
- **FR-008**: 队列列表 MUST 接入底部边缘提醒——拉过底显示「已经到底了」、回弹归位消失，行为与既有三列表一致（复用 EdgeHint 组件）
- **FR-009**: 「清除已播」MUST 移除当前播放条目之前的全部条目；当前条目 MUST 按状态区分——播放中（含未播完暂停）保留，处于播完未切下一首状态则一并移除；入口为头部图标；执行前 MUST 弹 AlertDialog 二次确认；无可清条目时 MUST toast 提示且不弹确认框
- **FR-010**: 删除类操作执行后计数与列表 MUST 即时刷新；删除/清空**非当前**条目时正在播放内容 MUST 不受影响；左滑删除、多选删除、清空**涉及当前播放条目**时按现有移除语义处理（条目被移除，不新增行为、不做特殊豁免）；清除已播移除播完状态当前条目后播放器 MUST 保持暂停、不自动续播
- **FR-011**: 非多选态点击条目切歌、多选态点击勾选的既有行为 MUST 保持不变
- **FR-012**: 当前播放条目的强调色标题高亮 MUST 保留
- **FR-013**: 空队列空态文案 MUST 调整——移除「输入BV号添加歌曲」引导，保留前往订阅源引导；空态下清除已播/多选/清空入口 MUST 不可用或隐藏
- **FR-014**: 本轮实现完成时 MUST 更新 PROJECT_NOTES 登记（KI-3 队列左滑删除销项、队列边缘提醒销项、addByBv 追加不打断规划标记已实现、KI-6 补充播完暂停）并按既定安排更新应用版本号
- **FR-015**: 移除输入行/搜索/定位后遗留的死代码（含 PlayerController 侧专属方法与存储键）MUST 一并清理，不留不可达路径；仍被其他入口使用的方法（如添加订阅面板单视频入队所用的 addToPlaylist）MUST NOT 误删，清理前须逐一核对调用方

- **FR-021**: 两条单视频入队路径（添加订阅面板、源详情页点单集）入队后 MUST 给 toast 反馈，按结果分型：加入队列（追加成功）/ 开始播放（队列空首播）/ 已在队列中（去重跳过）
- **FR-016**: 睡眠定时面板 MUST 新增「播完暂停」选项，与既有倒计时时长选项并列、单选互斥（后选取代先选），再次点击已选项取消、恢复无定时
- **FR-017**: 播完暂停触发时 MUST 停在原条目——当前条目播完后不切换下一首、进度停在末尾、播放器暂停；用户手动切歌/点选条目 MUST 解除该模式恢复正常播放；暂停后手动继续播放 MUST 从头重播当前条目
- **FR-018**: 「播完状态」判定 MUST 基于播放器状态（当前条目播完且未切下一首），MUST NOT 区分产生来源（定时播完暂停与队列末尾自然播完同等待待）

### Key Entities *(include if feature involves data)*

- **队列条目（BiliVideo）**: bvid（唯一键）、标题、UP 主名、时长、封面 URL；列表渲染与删除操作的目标
- **播放队列（PlayerController.playlist + currentIndex）**: 有序条目集合与当前播放下标；「已播区」= currentIndex 之前的前缀区间，清除已播的操作对象；播完状态当前条目随清除已播一并移除后 currentIndex 置空
- **多选集（selectedBvids）**: 多选模式下已勾选的 bvid 集合；队列变动时须过滤失效项
- **睡眠定时（SleepTimerController）**: 定时模式 = 无 / 倒计时归零暂停 / 播完当前条目暂停；模式间单选互斥；维持内存态不持久化现状
- **边缘提醒状态（EdgeHint）**: 底部提示文字的显隐状态，由列表过冲滚动驱动

## Assumptions

- 「已播」仅按队列内位置定义（当前播放条目之前），不与本地播放历史/看完标记交叉比对——用户已确认
- 「播完状态」由播放器内部状态判定（当前条目播完未切），实现轮自行选择判定信号（播放完成回调/进度达末尾且暂停等）
- 「清除已播」按钮图标与「清空」视觉区分开（如已播清理用带对勾/扫帚语义图标），具体 symbol 由实现轮在既有 sys.symbol 体系内选定
- 删除当前正在播放的条目沿用现有 removeSelectedFromPlaylist 语义，本轮不定义新行为
- 多选模式下左滑删除可用（与勾选并存）；若实现中发现手势冲突，降级为多选态禁用左滑并在实现报告中说明
- 睡眠定时维持内存态不持久化现状——应用重启后播完暂停与倒计时均失效，可接受
- 版本号升至 0.2.0/2000（「待播放列表重做完成后统一更新」的合理落点，实现轮可调整）
- 本轮仅产出 spec/plan/tasks 规划工件，不触碰 `entry/` 代码；实现轮待 bug 修复会话完成后启动
- 清空队列的二次确认交互沿用现状，不在本轮改动范围
