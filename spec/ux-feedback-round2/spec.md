# Feature Specification: 第二轮体验反馈批次（ux-feedback-round2）

**Created**: 2026-10-04
**Status**: Completed（T001-T024 实现完成并经用户实机验证；非流式基线 ee0d70f、流式补提交 382e789；Phase 5 验证 T025-T027 已取消，验证并入 Round 3 ux-feedback-round3）
**Input**: 用户实测反馈：订阅 UP 主报错（文案"查询UP主失败，请稍后重试"）；音频动态加载诉求（经 PiliPlus 调研后决策本轮实现流式边下边播）；播放页 8 项 UI/UX 优化；首页/历史页/设置 3 项优化。

## Overview

本轮解决用户实测后暴露的两类问题：**功能缺陷**（订阅 UP 主被 B 站风控拦截且错误信息被吞、播放首播延迟过大）与**体验打磨**（播放页主题色未接入、留白过大、文字按钮不统一、详情交互延迟、加载动画缺乏质感、首页入口层级冗余、历史页背景不一致、启动自动播放默认值不合理、恢复进度文案多余）。核心价值：让订阅可靠、让播放"秒开"、让播放页视觉完整跟随主题色并达到参考应用（PiliPlus）的品质水准。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 可靠订阅 UP 主（Priority: P1）🎯 MVP

用户在添加订阅面板输入 UP 主 mid（如 278761367）或空间链接后，应用应可靠完成"查询 UP 主信息 → 添加订阅 → 拉取最新投稿"全流程；即使遭遇 B 站风控（-352/-412/风控页），也应通过重试与降级尽量成功；确实失败时提示真实错误码而非模糊文案。

**Why this priority**: 订阅是应用内容供给的入口，当前对部分 mid 直接报错且错误被掩盖（lastError 恒为 unknown），属于功能阻断级缺陷。

**Independent Test**: 输入此前失败的两个 mid（3690981392124599、278761367）尝试订阅，可成功添加并拉到投稿列表；断网/风控场景下提示含真实错误码的可读文案。

**Acceptance Scenarios**:

1. **Given** 网络正常，**When** 用户输入此前失败的 mid 订阅，**Then** 查询 UP 信息接口遇风控时自动重试/降级（含 card 兜底），多数情况最终成功并展示 UP 主昵称与头像。
2. **Given** 全部接口路径均失败，**When** 流程终止，**Then** toast 展示真实失败原因（含错误码），不再是"unknown"或恒定的"请稍后重试"。
3. **Given** 接口返回非 JSON 风控页，**When** 解析失败，**Then** 该错误纳入重试降级链（重置 buvid、退避后重试），而非一次即中断。

---

### User Story 2 - 音频流式边下边播（Priority: P1）🎯 MVP

用户点播未缓存曲目时，应用解析 CDN 直链后直接流式开播（边下边播），无需等待整段音频下载完成；已缓存过的曲目仍优先本地秒播；切歌/重播时重新获取新直链（规避 URL 过期）。

**Why this priority**: 当前"整段下载完才播"导致首播延迟等于整个音频下载时长，是体验最大短板；PiliPlus 调研已确认鸿蒙 AVPlayer 原生支持带 Referer/UA 请求头的流式播放，实现风险可控。

**Independent Test**: 清除缓存后点播一首较长音频，出声时间从"整段下载时长"缩短到"秒级缓冲"；播放中 seek 立即生效；播放过的缓存曲目再次点播瞬时开播。

**Acceptance Scenarios**:

1. **Given** 曲目无本地缓存，**When** 用户点播，**Then** 解析直链后流式开播，状态行显示缓冲状态（无整段下载百分比），数秒内出声。
2. **Given** 曲目已有有效本地缓存文件，**When** 用户点播，**Then** 直接本地播放（保持现有秒播能力）。
3. **Given** 流式播放中，**When** 用户拖动进度条 seek，**Then** 播放器按需拉取对应数据段，seek 生效。
4. **Given** 直链打开失败（网络抖动/CDN 拒绝），**When** 播放器报错，**Then** 自动重试；彻底失败时提示用户且队列与其他状态不被破坏。

---

### User Story 3 - 播放页主题色接入与留白消除（Priority: P1）

用户在设置页切换主题色后，播放页所有着色元素（进度条、播放键底色与阴影、封面光晕、面板选中态、加载指示、底部操作行激活态）即时跟随新主题色，深浅色模式下均正确；信息区内容间距拉开分布，消除中部大片空白。

**Why this priority**: 播放页是应用核心界面，当前主题色系统对其完全失效（全部用编译期固定粉色资源），属于上一轮重设计的视觉收尾缺口；留白问题是用户对重设计布局的直接负面反馈。

**Independent Test**: 在设置页六色板间切换，播放页即时整体变色；目测播放页信息区内容分布均匀、无大片空白。

**Acceptance Scenarios**:

1. **Given** 播放页打开，**When** 用户在设置页切换主题色并返回，**Then** 播放页进度条/播放键/光晕/阴影/激活态文字/加载元素全部跟随新色。
2. **Given** 深色模式，**When** 重复上述操作，**Then** 衍生透明色（光晕梯度、阴影）在深色下观感正确。
3. **Given** 信息区内容高度小于可用空间，**When** 播放页展示，**Then** 封面/标题/UP行/统计行间距拉开、内容自然分布，无集中顶部的大片空白；内容超出时仍可滚动。

---

### User Story 4 - 播放页控件图标化与详情交互修正（Priority: P2）

播放页所有文字按钮改为图标（上一首/下一首、播放/暂停主键、倍速/播放模式/定时、封面角"播放视频"），图标不表意处允许"图标+极简文字"组合；标题行展开箭头与点击热区加大；详情 Sheet 手势下滑开始时箭头即时反转；播放队列抽屉移除「完成」按钮（关闭仍走遮罩点击）。

**Why this priority**: 图标化统一视觉语言（参考 PiliPlus 与系统应用规范）；箭头热区过小与反转延迟是交互打磨项。

**Independent Test**: 播放页目测无纯文字控制按钮；点按各图标按钮功能与此前文字按钮完全一致；下滑关闭详情时箭头随手势即时转回。

**Acceptance Scenarios**:

1. **Given** 播放页，**When** 目视检查控制区，**Then** 上一首/下一首/播放暂停主键/倍速/模式/定时/播放视频均为图标呈现（倍速等可图标+短文字），按压动画与置灰逻辑保留。
2. **Given** 详情 Sheet 打开（箭头朝上），**When** 用户手势下滑开始关闭，**Then** 箭头立即开始反转，不等关闭动画结束。
3. **Given** 标题行，**When** 用户点击箭头附近区域，**Then** 热区明显大于此前约 20×20vp 的范围，点按容易命中。
4. **Given** 播放队列抽屉打开，**When** 目视检查顶栏，**Then** 无「完成」按钮；点击遮罩仍可正常关闭抽屉。

---

### User Story 5 - 播放键缓冲弧线动画（Priority: P2）

缓冲/解析期间，播放按钮外圈出现弧线旋转动画（颜色跟随主题色）；加载完成后弧线淡出为低透明度完整圆环，作为播放键的常驻装饰。

**Why this priority**: 加载过程当前只有状态行一个 20×20 小菊花，缺乏品质感；弧线围绕核心操作按钮是参考应用的标志性视觉。

**Independent Test**: 点播未缓存曲目，观察播放键外圈弧线旋转；出声后弧线变为常驻淡色圆环；再次缓冲（如 seek 后）弧线动画重现。

**Acceptance Scenarios**:

1. **Given** 曲目开始解析/缓冲，**When** isPreparing 为真，**Then** 播放键外圈弧线持续旋转（不确定进度指示），颜色跟随主题色。
2. **Given** 缓冲完成开始播放，**When** isPreparing 结束，**Then** 弧线过渡为低透明度完整圆环常驻显示。
3. **Given** 播放中再次缓冲，**When** isPreparing 重新为真，**Then** 弧线旋转动画重现。

---

### User Story 6 - 详情实时拉取简介（Priority: P2）

打开详情 Sheet 时若当前曲目简介为空（订阅源未播放过的曲目），应用后台调用 API 拉取视频简介并即时刷新到简介区；拉取失败时静默保留"暂无简介"占位。

**Why this priority**: 简介块已存在但订阅源曲目常为空，用户感知为"详情里没有简介"。

**Independent Test**: 选一首从未播放过的订阅源曲目打开详情，简介区先显示占位、数秒内自动填充真实简介。

**Acceptance Scenarios**:

1. **Given** 当前曲目 desc 为空，**When** 用户打开详情 Sheet，**Then** 后台拉取简介，成功后简介区从"暂无简介"更新为真实内容。
2. **Given** 拉取失败（网络异常），**When** 拉取流程结束，**Then** 静默保留占位文案，无报错弹窗。
3. **Given** 当前曲目 desc 已有值，**When** 打开详情，**Then** 直接展示，不发起拉取。

---

### User Story 7 - 独立"更多"页与首页右上角直达（Priority: P2）

新建独立"更多"页面，收纳"设置 / 播放历史 / 关于"入口；首页右上角按钮加大，点击不再弹三行菜单而是直接进入"更多"页。

**Why this priority**: 弹菜单层级冗余且按钮过小；独立更多页为后续功能扩展提供挂载点。

**Independent Test**: 点首页右上角按钮直接进入更多页；更多页三个入口分别可达设置/播放历史/关于；返回链路正常。

**Acceptance Scenarios**:

1. **Given** 首页，**When** 点击右上角按钮，**Then** 直接导航进入"更多"页（无弹窗菜单），按钮热区明显大于此前 34×34。
2. **Given** 更多页，**When** 依次点击 设置/播放历史/关于，**Then** 分别到达对应界面（历史与关于行为与此前菜单入口一致）。
3. **Given** 从更多页进入下级页后，**When** 逐级返回，**Then** 返回到更多页、再返回到首页，链路完整。

---

### User Story 8 - 播放历史背景与详情页一致（Priority: P3）

播放历史面板的背景观感与播放页详情 Sheet 一致（同样的半透明毛玻璃质感与遮罩层级），消除浅色模式下两者背景观感割裂。

**Why this priority**: 视觉一致性收尾项，观感差异仅在浅色模式明显。

**Independent Test**: 浅色模式下分别打开播放页详情与播放历史，目测两者背景质感一致。

**Acceptance Scenarios**:

1. **Given** 浅色模式，**When** 分别打开详情 Sheet 与播放历史面板，**Then** 两者背景（颜色/毛玻璃/遮罩）观感一致。
2. **Given** 深色模式，**When** 重复对比，**Then** 观感同样一致且不劣于现状。

---

### User Story 9 - 启动行为默认值与文案清理（Priority: P3）

「启动时自动播放」默认值改为关闭（仅影响从未手动设置过的用户）；去掉"已恢复上次进度，点击播放继续"的状态文案。

**Why this priority**: 默认自动续播打扰大于便利；恢复进度提示文案冗余。

**Independent Test**: 全新安装（或未设置过的用户）启动应用不自动出声；恢复进度后状态行无该文案，点击播放仍从上次进度继续。

**Acceptance Scenarios**:

1. **Given** 用户从未修改过"启动时自动播放"设置，**When** 应用启动且有可恢复进度，**Then** 不自动播放，状态行不显示"已恢复上次进度，点击播放继续"。
2. **Given** 用户手动开启自动播放，**When** 应用启动，**Then** 保持现有自动续播行为不变。
3. **Given** 进度恢复完成，**When** 用户点击播放，**Then** 仍从上次进度位置继续（恢复能力本身不受影响）。

---

### Edge Cases

- 流式播放中网络中断：自动重试失败后给出可读提示，播放队列与订阅数据不受影响。
- 既有本地缓存文件与流式并存：缓存文件存在即本地播放，不做额外校验升级；缓存目录既有文件保持可用。
- 主题色为浅色系（如浅粉）时：浅色模式下光晕/阴影透明度观感不刺眼、不消失（衍生色透明度策略需验证）。
- "更多"页在 Navigation 返回栈中的位置：从更多页进设置再进历史等深层路径下返回顺序正确。
- 自动播放默认值变更对老用户的影响：曾手动设置过的用户不受影响（已持久化的值优先于默认值）。
- 订阅重试风暴：风控重试有轮次上限与退避间隔，不无限循环。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 查询 UP 主信息接口（acc/info）遇风控（错误码 -352/-412 或非 JSON 风控页响应）时，系统 MUST 执行多轮"重置 buvid + 退避"重试，并保留 card 接口兜底，重试策略与现有投稿列表接口同级健壮。
- **FR-002**: 全部查询/刷新路径失败时，系统 MUST 在提示中透出真实错误码或原因（修复 lastError 永不更新导致提示"unknown"的缺陷）。
- **FR-003**: 非 JSON 风控页响应 MUST 纳入重试降级链（触发重试），而非一次即中断流程。
- **FR-004**: 播放未缓存曲目时，系统 MUST 解析 CDN 直链并以携带 Referer/User-Agent 请求头的流式模式边下边播，不等待整段下载。
- **FR-005**: 曲目存在本地缓存文件时，系统 MUST 优先本地播放，保持既有秒播能力。
- **FR-006**: 切歌或重播时系统 MUST 重新获取直链（不持久化远程 URL）；流式 seek 由播放器内核按需分段拉取。
- **FR-007**: 流式打开失败时系统 MUST 自动重试；彻底失败时给出可读提示且不破坏播放队列状态。
- **FR-008**: 缓冲期间 UI MUST 呈现缓冲状态指示，不再展示整段下载百分比。
- **FR-009**: 播放页全部着色点（进度条、播放键底色/阴影、封面光晕、面板选中态、加载指示、激活态文字）MUST 运行时跟随用户主题色选择（含深浅色两套），衍生透明色由主题色运行时计算。
- **FR-010**: 播放页信息区内容间距 MUST 拉开分布以消除中部大片空白，内容超出可滚动能力保留。
- **FR-011**: 播放页全部文字控制按钮 MUST 改为图标呈现（倍速/模式/定时允许"图标+极简文字"组合），既有按压动画、置灰门控、点击行为不变。
- **FR-012**: 标题行展开箭头 MUST 加大图标与点击热区。
- **FR-013**: 详情 Sheet 手势下滑开始时箭头 MUST 即时反转，不等关闭动画结束。
- **FR-014**: 打开详情时若简介为空，系统 MUST 后台拉取并刷新简介区；失败时静默保留占位；已有简介不重复拉取。
- **FR-015**: 解析/缓冲期间播放键外圈 MUST 显示弧线旋转动画（跟随主题色）；完成后过渡为低透明度完整圆环常驻装饰；再次缓冲时弧线动画重现。
- **FR-016**: 系统 MUST 提供独立"更多"页面收纳 设置/播放历史/关于 入口；首页右上角按钮加大且点击直达更多页，移除弹菜单。
- **FR-017**: 播放历史面板背景观感 MUST 与详情 Sheet 一致（半透明毛玻璃质感），深浅色模式均满足。
- **FR-018**: 「启动时自动播放」默认值 MUST 为关闭；已手动设置过的用户不受影响。
- **FR-019**: "已恢复上次进度，点击播放继续"状态文案 MUST 移除；进度恢复与手动续播能力保持不变。
- **FR-020**: 播放队列抽屉顶栏的「完成」按钮 MUST 移除；抽屉关闭能力（遮罩点击）保持不变。

### Key Entities *(include if feature involves data)*

- **音频播放源（AudioSource）**: 播放数据源的统一抽象——本地缓存文件 或 远程直链+请求头（Referer/UA）+缓冲策略；由播放编排层按缓存存在性择一，播放器层透明消费。
- **主题色衍生色**: 由用户主题色（六色板之一）运行时派生的透明度变体（光晕梯度、阴影、装饰圆环、弧线），深浅色模式各一套观感。
- **订阅查询上下文**: UP 主查询流程的重试状态（轮次、buvid、错误累积），用于风控降级与最终错误透出。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 此前订阅失败的 mid（3690981392124599、278761367）可成功完成订阅并拉取投稿列表；仍失败时提示含真实错误码。
- **SC-002**: 未缓存曲目点播到出声时间 ≤ 10 秒（视网络），不再等于整段音频下载时长；已缓存曲目点播到出声 ≤ 2 秒。
- **SC-003**: 六色板逐一切换后，播放页全部着色元素 100% 跟随变色，无残留固定粉色元素（深浅色模式均验证）。
- **SC-004**: 播放页目测无纯文字控制按钮；全部按钮功能与改版前等价（按压动画/置灰/点击行为零回退）。
- **SC-005**: 详情下滑开始到箭头完成反转的延迟 ≤ 100ms（手势触发即时）。
- **SC-006**: 未播放过的订阅曲目打开详情，简介自动填充成功率（正常网络下）≥ 90%。
- **SC-007**: 首页右上角点击到更多页呈现 ≤ 1 次导航；新旧用户启动行为符合 FR-018/FR-019。
