# Feature Specification: v0.5-part3（订阅详情交互打磨 + 反馈完善与登记）

**Status**: Draft
**Input**: 用户 8 项新需求（订阅详情/多选交互打磨）+ part3 登记集并入（播放出错提醒、历史容量 300、充电视频条件项）

## Overview

本轮合并两条线：①订阅详情页与多选交互打磨——历史/订阅源补齐整行拖选（双向）、多选悬浮按钮左右进退与透明度动画、页头信息改造（封面对齐/名称与 UP 主/类型标签）、时长角标加大、合集标题「合集·」前缀剥除；②part3 登记集清账——播放出错提醒与日志、历史容量 300 与列表尾提示。

## User Scenarios & Testing

### User Story 1 - 历史/订阅源整行拖选（双向）与边缘滚动 (Priority: P1)

历史面板与订阅源详情中，我长按任一行进入多选并预选该行，不抬指继续拖动，途经行被连续选中；从已选中的行起拖，途经行被连续取消。拖到屏幕上/下边缘时列表自动滚动继续选择，滚到列表尽头即停。订阅源列表拖选中触底时照常加载更早剧集，加载出的新行可继续拖选。

**Why this priority**: 多选效率核心交互，队列已在 part2 落地，本轮补齐另两个高频场景，达成三场景交互一致。

**Independent Test**: 在历史面板与订阅源详情各做一轮长按拖选（含边缘滚动、订阅源触底续载），全程不抬指完成跨屏多选。

**Acceptance Scenarios**:

1. **Given** 历史面板 ≥5 行, **When** 长按行 A 不抬指拖至行 C, **Then** A 至 C 连续选中，复选框状态同步
2. **Given** 已选中行 B, **When** 从 B 起拖至行 D, **Then** B 至 D 连续取消选中
3. **Given** 列表未到尽头, **When** 拖动驻留屏幕底缘, **Then** 列表自动滚动续选；**When** 滚至尽头, **Then** 自动停止
4. **Given** 订阅源剧集超过一页, **When** 拖选驻留底缘触发加载更早, **Then** 新加载行可被继续拖选

---

### User Story 2 - 多选悬浮按钮左右进退与透明度动画 (Priority: P2)

订阅源进入多选时，底部两个悬浮按钮（标记已看完/加入队列）改为从左右两侧滑入，退出时滑出；按钮禁用↔启用状态切换（如选中数为 0 时禁用）的透明度变化带过渡动画，不再瞬跳。

**Why this priority**: 进出场方向与状态过渡决定多选动效的顺滑度，视觉直接可感。

**Independent Test**: 进入/退出订阅源多选观察按钮进退方向；增删选中观察禁用态透明度过渡。

**Acceptance Scenarios**:

1. **Given** 订阅源非多选态, **When** 长按进入多选, **Then** 双按钮分别自左右两侧滑入
2. **Given** 多选中选中数为 0, **When** 选中一条, **Then** 按钮透明度 0.4→1.0 平滑过渡；反向同理

---

### User Story 3 - 订阅详情页头信息改造 (Priority: P2)

订阅源详情页头重排：封面左缘与下方剧集行封面左缘对齐（现状页头封面更贴屏幕边框）；页头以更大文字显示订阅当前名称；合集/系列显示所属 UP 主，UP 订阅与收藏夹只显示名称不显示 UP 主；订阅类型（UP/收藏夹/合集/系列）以标签形式显示于页头（参照 bilirss 的标签样式）。

**Why this priority**: 页头是订阅详情第一屏信息密度最高的区域，对齐与信息完整性直接决定观感与辨识度。

**Independent Test**: 分别打开 UP/收藏夹/合集/系列四类订阅详情，核对页头对齐、名称、UP 主显示规则与类型标签。

**Acceptance Scenarios**:

1. **Given** 合集订阅详情, **When** 打开, **Then** 页头封面左缘与剧集行封面左缘对齐，显示合集名称与所属 UP 主，类型标签「合集」可见，名称字号大于现状
2. **Given** 收藏夹订阅详情, **When** 打开, **Then** 显示收藏夹名称，不显示 UP 主，类型标签「收藏夹」可见
3. **Given** UP 订阅详情, **When** 打开, **Then** 类型标签「UP」可见

---

### User Story 4 - 合集标题「合集·」前缀剥除 (Priority: P2)

合集订阅标题以「合集·」开头的（B 站自动命名），在所有展示位剥除该前缀：订阅列表条目、详情页头、导航标题。剥除后为空或仅剩标识的兜底标题保留原样。

**Why this priority**: 类型标签已表意，前缀冗余；在数据层做一次规范化，全展示位生效。

**Independent Test**: 订阅一个标题带「合集·」前缀的合集，核对订阅列表、详情页头、导航标题三处均无前缀。

**Acceptance Scenarios**:

1. **Given** 合集订阅标题「合集·XXX」, **When** 查看任一展示位, **Then** 标题显示为「XXX」
2. **Given** 兜底命名的合集标题（取不到名称时）, **When** 查看, **Then** 保留原样

---

### User Story 5 - 剧集行时长角标加大 (Priority: P3)

订阅源详情剧集行横版缩略图右下角的时长角标字号 11→13，介于现状与右侧标题字号之间。

**Why this priority**: 可读性微调，改动极小。

**Independent Test**: 打开订阅源详情观察角标字号。

**Acceptance Scenarios**:

1. **Given** 剧集行含时长角标, **When** 查看, **Then** 角标字号为 13，与周边元素无重叠溢出

---

### User Story 6 - 播放出错提醒与日志 (Priority: P2)

播放链路出错（取流失败/解码错误/网络中断等）时，用户看到明确的出错提醒（形式设计阶段定：轻提示或播放层错误态）；错误同时写入日志（debug 可查），含错误类型与上下文（视频标识/错误码/出错阶段），出错可追溯。

**Why this priority**: 现状出错无任何可见反馈、日志无痕，用户与开发者双盲；属稳定性基础设施。

**Independent Test**: 构造一次播放失败（如断网取流），验证用户可见提醒与日志记录。

**Acceptance Scenarios**:

1. **Given** 播放中网络中断, **When** 取流失败, **Then** 用户看到出错提醒，日志含错误类型与视频标识
2. **Given** 任意播放错误路径, **When** 出错, **Then** 日志有记录，无静默吞错

---

### User Story 7 - 历史容量 300 与列表尾提示 (Priority: P3)

播放历史本地保留上限 200→300（最新在前，超限截断）；历史列表尾恒显居中小字提示「仅保留最近 300 条播放记录」。提示不可交互、多选/删除后仍在队尾、空列表不显示、提示数字与上限同源（调整上限只改一处）。既有 ≤200 条数据无缝兼容。

**Why this priority**: 登记项清账，独立且小。

**Independent Test**: 播放积累历史后打开历史面板，核对尾注提示与容量截断。

**Acceptance Scenarios**:

1. **Given** 历史 300+ 条, **When** 新增播放记录, **Then** 最早记录被截断，总数不超 300
2. **Given** 历史非空, **When** 打开历史面板, **Then** 列表尾显示「仅保留最近 300 条播放记录」，不可点选
3. **Given** 历史为空, **When** 打开历史面板, **Then** 不显示提示

### Edge Cases

- 整行拖选与既有复选框区扫选手势触发区分离，同一手势序列不互相抢占
- 拖选中数据源变化：订阅源加载新页、历史被并发删除时，选中集与行映射不错乱
- 边缘滚动的尽头判定：顶部零偏移与底部最大偏移均须停滚，避免无限空转
- 历史面板整行拖选与列表既有滑动滚动的手势边界
- 播放连续出错时的提醒去重（不连环轰炸），形式与频控设计阶段定
- 历史上限常量被随机/快进跳转栈复用，一升俱升，是否拆分常量设计阶段定
- 合集标题剥除后为空/纯标识的兜底保留

## Requirements

### Functional Requirements

- **FR-001**: 历史面板与订阅源详情列表每一行 MUST 支持长按进入多选并预选本行（沿用既有预选机制）
- **FR-002**: 多选中整行拖动 MUST 按起点行选中状态双向连选/连取消（起点未选→途经行加选；起点已选→途经行取消）
- **FR-003**: 拖动驻留屏幕上/下边缘带内 MUST 触发列表自动滚动；滚至列表尽头 MUST 自动停止
- **FR-004**: 订阅源多选拖选中触底 MUST 照常触发加载更早剧集，加载出的行可继续拖选
- **FR-005**: 整行拖选 MUST 与复选框区扫选手势并存，触发区域分离互不抢占
- **FR-006**: 订阅源多选悬浮双按钮进出 MUST 改为左右两侧滑入/滑出
- **FR-007**: 悬浮按钮禁用/启用透明度切换 MUST 带过渡动画
- **FR-008**: 订阅详情页头封面左缘 MUST 与剧集行封面左缘对齐
- **FR-009**: 页头 MUST 显示订阅当前名称（字号大于现状）；合集/系列 MUST 显示所属 UP 主——数据路径：UP 二级视图订阅合集/系列时 MUST 写入 upperName；按 ID 订阅与存量订阅打开详情页时经 ownerMid → fetchUpInfo（acc/info→card 降级链）回填并持久化（合集/系列剧集接口上游不返回作者，剧集缓存/刷新回填不可行）；UP 订阅与收藏夹 MUST NOT 显示所属 UP 主
- **FR-010**: 订阅类型（UP/收藏夹/合集/系列）MUST 以标签形式显示于页头
- **FR-011**: 合集标题以「合集·」开头时 MUST 在全展示位（订阅列表/详情页头/导航标题）剥除前缀；剥除后为空或纯标识的兜底标题保留原样
- **FR-012**: 剧集行横版缩略图时长角标字号 MUST 升至 13
- **FR-013**: 播放链路出错 MUST 向用户呈现可见提醒（形式设计阶段定）
- **FR-014**: 播放错误 MUST 写入日志（debug 可查），含错误类型与上下文（视频标识/错误码/出错阶段）
- **FR-015**: 播放链路静默吞错点 MUST 全量梳理，错误路径不得无痕失败
- **FR-016**: 播放历史本地保留上限 MUST 升至 300（新记录超限截断、最新在前），既有数据无缝兼容
- **FR-017**: 历史列表尾 MUST 恒显居中提示「仅保留最近 300 条播放记录」（列表非空；不可交互；多选/删除后仍居队尾；空态不显示；提示数字与上限同源）
- **FR-018**:（已移出：见 spec/charging-archive.md）
- **FR-019**:（已移出：见 spec/charging-archive.md）
- **FR-020**: 队列整行拖选中残留的宽屏门禁（对应多列布局已移除）MUST 梳理：确认为死逻辑则摘除且行为不变；若承担实际手势冲突职责则保留并登记原因

### Key Entities

- **订阅（Subscription）**: 类型（UP/收藏夹/合集/系列）、名称、所属 UP 主——页头展示规则的核心载体；合集标题剥除「合集·」前缀
- **播放历史（PlayHistory）**: 本地保留上限 300，最新在前；上限常量与随机/快进跳转栈复用
- **播放错误事件**: 错误类型、视频标识、错误码、出错阶段——提醒与日志的最小信息单元

## Success Criteria

### Measurable Outcomes

- **SC-001**: 历史/订阅源拖选全程不抬指可完成 ≥20 行跨屏连选（含边缘滚动；订阅源含触底续载一段）
- **SC-002**: 四类订阅详情页头信息完整（对齐/名称/UP 主规则/类型标签），「合集·」前缀在三个展示位均不可见
- **SC-003**: 播放错误路径抽样 100% 有用户可见提醒且日志可查
- **SC-004**: 历史上限 300 生效、尾注提示显示、既有数据零丢失
- **SC-005**:（已移出：见 spec/charging-archive.md）

## Assumptions

- 双向拖选仅推广至历史/订阅源；队列维持现状单向（用户决议）
- 出错提醒形式（轻提示 vs 播放层错误态）与频控去重策略 Phase 2 设计定
- 类型标签视觉形态以 bilirss 为参照，具体样式 Phase 2 设计定
- 历史上限常量被随机/快进跳转栈复用，一升俱升；是否拆分 Phase 2 定
- 兜底命名的合集标题（无「合集·」前缀语义）不剥除
- 历史/订阅源行结构与队列不同，拖选手势的挂载与行定位方案 Phase 2 设计定

## Open Questions

- 播放出错提醒的具体形式与连续错误频控（每次都提示 vs 会话内去重）
- 类型标签的视觉细节（尺寸/圆角/配色是否与现有 NEW/已播徽标族一致）
- 队列宽屏门禁摘除后平板宽屏下拖选手感是否受影响（需宽屏验证）
