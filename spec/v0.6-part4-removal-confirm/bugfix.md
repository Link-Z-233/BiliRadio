# bugfix

## 1. 平板竖屏播放页按钮钉底、中上部大片空白

**现象**：平板竖屏下播放浮层控制按钮区被推到屏幕最底端，封面/标题与按钮区间空隙达数百 vp，中上部大片空白；手机上同一布局节奏正常。

**根因**：播放层主内容列撑满全屏高度，滚动信息区 `minHeight:'100%'` + `SpaceBetween` 拉伸铺满（空隙 = 屏幕高 − 内容高，屏幕越高空隙越大），固定底栏内部间距为固定小值（12/14vp）、整体钉死主内容列底部 = 屏幕底。间距全部绝对值，平板竖屏（约 800×1280vp）下信息区空隙失控而底栏依旧紧贴，对比失衡。

**修复（三轮迭代）**：
- 第一版：宽屏下播放块限高 900vp 居中——真机观感「都挤在中间」，用户否决，已回退。
- 终版（相对间距）：`PlayerOverlay` 根 Stack 加 `onAreaChange` 维护本地 `isWide` 断言（宽 ≥600vp，与 Index 媒体查询同口径）与 `overlayHeightVp`；宽屏下底栏内部间距改相对浮层高度比例——五键行上边距 `PLAYER_WIDE_CTRL_GAP_RATIO`（0.05）、操作行上边距 `PLAYER_WIDE_ACTION_GAP_RATIO`（0.03）、底栏整体上抬 `PLAYER_WIDE_BOTTOM_GAP_RATIO`（0.02，叠加导航条避让 padding），均大于原固定间距且小于信息区 SpaceBetween 间距；窄屏走原固定间距不变，限高居中方案全部移除。真机反馈追加：删除播放页统计行（播放量 · 发布时间，详情 sheet 内保留同数据），避免信息区冗余。统计行删除后 `SpaceBetween` 末位子项（UP 行）被钉到滚动区底部、紧贴进度条，信息列补底部留白修复（宽屏复用 `PLAYER_WIDE_CTRL_GAP_RATIO`）。
- 泄漏修正：统计行删除与信息列底部留白最初为无条件改动，窄屏（手机）也被波及——`SpaceBetween` 末位从统计行变为 UP 行，真机截图实测标题下坠约 71vp、UP 行下坠约 143vp、统计行消失，违反「窄屏逐像素不变」约定。修正为均仅宽屏生效：窄屏恢复统计行（`!isWide` 条件渲染）、信息列底部留白窄屏归零，手机路径还原原版；平板维持去统计行 + 比例间距不变。
- 统计行终态（用户决策：手机也删统计行，两设备一致）：窄屏不再渲染可见统计行，改为隐藏占位（`Visibility.Hidden`，不绘制仍占布局位）保持 `SpaceBetween` 分布与原版逐像素一致——标题/UP 原位不动，仅统计文字消失；宽屏无统计行亦无占位，维持已验收的比例间距现状。信息列底部留白仍仅宽屏生效。

**验证**：arkts_check 2 文件零错误；devecocli build 成功。UI 验证按用户指示停在真机前，待真机自查（间距比例 0.05/0.03 可按观感调 `Constants.ets`）。
