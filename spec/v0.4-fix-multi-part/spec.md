# Feature Specification: 多分P 视频播放支持（v0.4-fix-multi-part）

**Created**: 2026-10-14  
**Status**: 第二轮（UX 反馈轮）spec 更新  
**Input**: 第一轮：用户描述 "播放器不支持多分p视频"（方案 C 定案）；第二轮：真机体验反馈——同视频分P 条目在队列/历史中扁平铺开，期望视觉归组（历史对齐 B 站形态、队列加分组头，用户逐项选定）

## Overview

多分P 视频当前永远只播 P1：识别层丢弃 `?p=N` 参数，取流层只读视频级 cid（P1），播放层每次起播都覆盖回 P1，其余分P 无任何途径触达。**第一轮（已交付）**将分P 作为一等公民：多P 视频入队时展开为独立队列条目，自动连播、独立进度、独立去重；队列条目身份从 `bvid` 扩展为 `bvid + 页号`，本地历史/续播/去重精确到分P，与 Pre-update 分支云同步「按 cid 上报/续播」设计天然对齐。

**第二轮（本轮）**为展示形态 UX 反馈轮：扁平分P 条目在长列表中视觉割裂，按用户选定对齐两处面板——**历史面板对齐 B 站官方形态**：同视频全部分P 历史归并为一行（一视频一行，显示最新播放分P 状态，点行续播该分P，删除以视频为单位）；**队列面板加视频级分组头**：同视频相邻分P 条目上方插入可点击的视频标题头（点按播放该视频续播点，无历史则 P1）。存储、身份键、续播逻辑零变化——归并/分组均为纯展示层。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 粘贴多P 视频链接，全部分P 展开入队连播 (Priority: P1) ✅ 已交付

用户粘贴一个多分P 视频链接（BV 号 URL / av 号 URL / 分享短链，不带 p 参数）到「添加订阅」查询框：系统识别视频后拉取其分P 列表，将每个分P 作为独立队列条目入队（标题「视频标题 · Pn 分P名」，时长/分P 标识各自独立），并自动从 P1 开始连续播放，P1 播完自动切 P2，直至全部分P 播完。单分P 视频保持现状：一条队列条目，行为完全不变。

**Why this priority**: 本轮核心价值闭环——多P 视频第一次变得「可完整收听」，播客式自动连播贴合应用定位。

**Independent Test**: 粘贴一个已知多P 视频链接，队列应出现与分P 数相同的条目并从 P1 自动连播；粘贴单P 视频链接，行为与改造前一致。

**Acceptance Scenarios**:

1. **Given** 播放队列为空，**When** 粘贴 10 分P 视频链接提交，**Then** 队列出现 10 个条目（标题含分P 名），自动从 P1 起播
2. **Given** P1 正在播放且自然播完，**When** 完播事件触发，**Then** 自动切到 P2 继续播放
3. **Given** 单P 视频链接，**When** 粘贴提交，**Then** 队列 1 个条目，标题无 Pn 缀，行为与现状一致
4. **Given** 队列非空且正在播放其他内容，**When** 粘贴多P 视频链接，**Then** 全部分P 追加到队列末尾，不打断当前播放

---

### User Story 2 - 带 p 参数链接只入队指定分P (Priority: P1) ✅ 已交付

用户粘贴带 `?p=N` 参数的视频链接（含短链解析后目标带 p 参数的形态）：系统只将第 N 个分P 作为一条队列条目入队（追加不打断，或空队列时起播）。p 参数是入队定位意图，不改变其他分P 的可达性（再次粘贴不带 p 的整视频链接仍可展开全部分P）。

**Why this priority**: 与 US1 同层构成识别层闭环——用户从 B 站复制来的链接天然带 p 参数，须精确响应。

**Independent Test**: 粘贴 `?p=3` 链接，队列应只新增 1 个条目且标题为 P3 的分P 名，播放的是 P3 内容。

**Acceptance Scenarios**:

1. **Given** 任意队列状态，**When** 粘贴 `?p=3` 的 10 分P 视频链接，**Then** 仅新增 P3 一条，起播内容为 P3
2. **Given** p 参数越界（如 `?p=99` 超出分P 数）或非法（非正整数），**When** 粘贴提交，**Then** 按 P1 处理（宽松兜底），不报错
3. **Given** av 号 URL 带 p 参数（`/video/av123?p=2`），**When** 粘贴提交，**Then** 只入队该视频 P2

---

### User Story 3 - 每个分P 独立进度与去重 (Priority: P1) ✅ 已交付

同一视频的不同分P 互不干扰：每个分P 有独立的续播进度、完播标记与历史条目；队列去重、随机播放轨迹、队列条目点选/删除均以「bvid + 分P」为身份粒度。听到 P3 中途退出，重新入队该视频全部分P 后，P3 从原位置续播，P1/P2/P4 从头播。

**Why this priority**: 分P 展开后的完整性保障——若无独立进度，多P 专辑的续听体验退化为「每次都从头」或「互相覆盖」。

**Independent Test**: 分别将同一视频的 P1、P2 听到不同中途位置，重新入队后两分P 应各自从原位置续播；历史面板应出现两条独立记录。

**Acceptance Scenarios**:

1. **Given** P1 已听完（完播）、P2 听到一半，**When** 查看历史面板，**Then** 出现两条独立条目（分P 标题区分），进度状态各自正确
2. **Given** P2 在队列中，**When** 再次粘贴整视频链接展开入队，**Then** P2 被去重跳过，其余分P 正常追加/保留
3. **Given** 随机播放模式，**When** 在多个分P 条目间切换，**Then** 随机轨迹记录到分P 粒度，回溯/前进行为与现有单视频条目一致
4. **Given** 历史面板点播一条分P 历史，**When** 起播，**Then** 播放的是该分P 且从其历史进度续播

---

### User Story 4 - 订阅列表点播多P 视频时展开入队 (Priority: P2) ✅ 已交付

用户在订阅源详情页（SourcePage，覆盖 UP 投稿/收藏夹/合集/系列四类）点播一个多分P 视频：系统拉取该视频分P 列表并全部分P 展开入队（复用既有「点单集入队不打断当前播放」语义），从 P1 起播。列表行保持视频级展示不变，不做静态分P 展开。

**Why this priority**: 订阅源是多P 内容（课程、播客专辑、音乐合集）的主要入口，但入口交互形态已由用户定案（点播时展开），实现路径与 US1 共用展开机制。

**Independent Test**: 在订阅详情页点播一个已知多P 视频行，队列应新增该视频全部分P 且不打断当前播放。

**Acceptance Scenarios**:

1. **Given** 订阅详情页含多P 视频，**When** 点播该视频行，**Then** 全部分P 追加入队，当前播放不被打断，随后自动连播至该视频 P1
2. **Given** 订阅详情页含单P 视频，**When** 点播，**Then** 行为与现状一致（单条目入队）

---

### User Story 5 - 全 UI 面分P 标题展示 (Priority: P2) ✅ 已交付

分P 条目在所有呈现面显示分P 粒度标题：队列面板、历史面板、播放页（大标题/迷你播放器）、系统媒体会话（锁屏/控制中心）。显示名规则：分P 名非空且与视频标题不同时为「视频标题 · Pn 分P名」；分P 名为空或与视频标题相同时仅显示「视频标题」（P1 常见）。

**Why this priority**: 分P 展开后若 UI 仍显示视频级标题，队列/历史中同视频多条目无法区分，展开的价值被抵消。

**Independent Test**: 展开一个多P 视频入队，队列面板中每个条目标题应含分P 名；锁屏控制中心显示当前分P 标题。

**Acceptance Scenarios**:

1. **Given** 队列含某 10 分P 视频的全部条目，**When** 打开队列面板，**Then** 各条目标题以分P 名区分，可辨识当前播到哪个分P
2. **Given** 正在播放某分P，**When** 查看锁屏/控制中心，**Then** 显示该分P 标题

---

### User Story 6 - 历史面板按视频归并（B 站形态） (Priority: P1) 🆕 第二轮

历史面板中同视频的全部分P 记录归并为一行（一视频一行）：主行显示视频标题，副行显示「相对时间 · 看到Pn · 剩余时长」（时间在最前；分P 名不展示——第三轮定案；已听完的分P 显示「已听完」；无进度/时长未知时按既有规则降级）。列表排序按该视频最近一次播放时间倒序。点行续播「看到」的那个分P（该分P 历史进度）。左滑删除与多选删除均以视频为单位：一行 = 删该视频全部分P 历史。单P 视频行不显示「看到Pn」段，形态与现状一致。

**Why this priority**: 扁平分P 条目在历史长列表中刷屏（10P 视频占 10 行），视觉割裂；B 站官方历史即视频级去重形态，对齐后与云端历史语义同构（Pre-update 云同步合并铺路）。

**Independent Test**: 听完某 10P 视频的 P1、听到 P2 一半后打开历史面板：该视频仅占一行，显示「看到P2 · 剩余时长」；点行从 P2 断点续播；左滑删除后该视频全部分P 记录消失。

**Acceptance Scenarios**:

1. **Given** 某 10P 视频的 P1 已听完、P2 听到一半（3 小时前），**When** 打开历史面板，**Then** 该视频一行：主行视频标题，副行「3 小时前 · 看到P2 · 剩 12:34」
2. **Given** 历史面板含归并行，**When** 点击该行，**Then** 续播 P2 且从其历史进度（非 P1、非从头）
3. **Given** 历史面板含归并行，**When** 左滑删除并确认，**Then** 该视频 P1/P2 全部分P 历史一并删除，不再出现
4. **Given** 多选模式，**When** 勾选归并行删除，**Then** 删除单位为视频（该 bvid 全部分P）；全选以归并行计数
5. **Given** 单P 视频历史，**When** 查看，**Then** 无「看到Pn」段，行形态与第一轮交付一致

---

### User Story 7 - 队列面板视频级分组头 (Priority: P1) 🆕 第二轮

队列面板中同视频相邻（≥2 条）的分P 条目上方渲染视频级分组头：显示视频标题的可点击行。点分组头播放该视频的续播点——存在历史则播最新播放的分P（该分P 历史进度），无历史则播 P1；目标分P 条目在队列内时直接跳播该条目，不在队列内时插播构造该分P 条目。分组头为非条目标签：不参与多选、不可左滑删除、不占队列身份。单P 条目与随机播放打散后不相邻的同视频条目不渲染分组头。条目级操作（点击跳播/左滑删除/多选）语义不变。

**Why this priority**: 队列中同视频 N 个分P 条目靠标题前缀辨识归组太弱；分组头以最低成本补上视觉归组，且点击续播点提供了「从组头快速续听」入口。

**Independent Test**: 队列含某 10P 视频全部条目时，面板在该组上方出现视频标题分组头；点分组头播放该视频上次听到的分P（无历史则 P1）；随机播放打散后分组头消失，条目行为不变。

**Acceptance Scenarios**:

1. **Given** 队列含某 10P 视频全部条目（相邻），**When** 打开队列面板，**Then** 组上方渲染视频标题分组头，组内条目保持分P 标题与全部操作
2. **Given** 该视频 P2 有历史进度（听到一半），**When** 点击分组头，**Then** 跳播队列中的 P2 条目并从历史进度续播
3. **Given** 该视频无任何历史，**When** 点击分组头，**Then** 跳播 P1（从头）
4. **Given** 随机播放模式打散队列，**When** 查看面板，**Then** 同视频条目不相邻时不渲染分组头（条目行为不变）
5. **Given** 多选模式，**When** 操作队列，**Then** 分组头不参与勾选/删除（仅条目可勾选）

---

### User Story 8 - 队列两级呈现与组级交互 (Priority: P1) 🆕 第三轮

队列多P 分组升级为两级呈现：组首渲染视频头行（封面 + 视频标题 + 共 nP，独占一行），组内条目渲染分P 窄行（Pn + 分P 标题 + 时长，无封面，左缩进对齐头行标题）；单P/孤立条目保持原有整行。头行交互升级：非多选点击仍为整组续播（D13 两段判定，US7 语义不变）；多选态头行前置换 Checkbox 支持整组切换；组首 ListItem 左滑为整组移除（确认弹窗标注分P 数，走既有批量移除链路含自动切播）。组内管理收敛头行（D15-Trim，用户定案）：分P 窄行无勾选框/无左滑，点击切播，多选点击与长按均为整组语义，滑动范围选组感知——**组为最小管理粒度**（单个分P 不可单独删/勾，需微调时整组移除后重新入队指定 `?p=N`）。

**Why this priority**: 平铺行下同封面重复、视频名在合成标题里重复三遍，纵向占位大；两级呈现一图胜千言。组首左滑整组移除补上「一键移除整个多P 视频」入口（原崩溃复现路径）。管理收敛头行砍掉单分P 粒度的删除/勾选代码，消除「部分选中显示未选」的歧义态。

**Independent Test**: 队列含某多P 视频全部分P：组首上方为封面+标题+共 nP 头行，其下为 Pn+分P 标题窄行；点窄行切播该分P；左滑组首确认后整组消失；长按任意分P 进多选且整组选中；多选态点头行 Checkbox 或分P 行均整组切换。

**Acceptance Scenarios**:

1. **Given** 队列含某多P 视频相邻 ≥2 条分P，**When** 打开队列面板，**Then** 组首渲染视频头行（封面+标题+共 nP），组内条目为分P 窄行（无封面）
2. **Given** 多选模式，**When** 点视频头行 Checkbox，**Then** 整组复合键一次勾选/取消
3. **Given** 非多选模式，**When** 左滑组首条目（含头行）并确认，**Then** 该视频全部分P 一次移除，队列不崩溃、其余条目不受影响
4. **Given** 组内条目被删至仅剩 1 条，**When** 查看，**Then** 头行消失，该条目回退原有整行形态
5. **Given** 单P 视频条目，**When** 查看，**Then** 整行形态与操作与本轮改造前一致
6. **Given** 多选模式，**When** 查看分P 窄行，**Then** 无勾选框、无左滑；点击分P 行或长按分P 行均为整组切换/整组选中；滑动范围选跨组时按组补齐

### Edge Cases

- **p 参数越界/非法**（`?p=0`、`?p=99`、`?p=abc`）：按 P1 处理，不报错（宽松兜底）
- **分P 数极大**（百级以上）：全部分P 展开入队，不设上限（队列列表懒加载可承受；实测性能不达标再议上限）
- **view 接口无 pages 字段 / pages 为空 / 分P 字段缺失**：回退视频级 cid，按单分P 处理（现状行为）
- **旧持久化数据**（队列文件/历史文件中改造前的条目，无分P 字段）：视为 P1，读取/续播/展示不崩溃、不丢数据
- **识别层清洗**：分享文案抽取、短链逐跳解析后的目标 URL 必须保留 query 参数（`?p=N` 不被截断）
- **同一分P 重复入队**：队列已有该 bvid+cid 条目时去重跳过，提示语义与现状一致
- **分P 完播后重播**：该分P 从头播放（沿用现有「-1 重播从头」语义），其他分P 不受影响
- **单P 视频**：全链路（识别/入队/播放/历史/UI）行为与本轮改造前一致（回归约束）
- 🆕 **归并行最新分P 为旧数据占位**（page 归一后仍无有效 cid）：按 P1 对待，展示与续播不崩溃
- 🆕 **分组头下条目被删至仅剩 1 条或 0 条**：分组头自动消失（头为派生物，仅相邻 ≥2 条时渲染）
- 🆕 **历史归并后「清空历史/清空已播」**：语义不变（清空仍为全量/按已播集合，与行归并展示无关）
- 🆕 **同视频分P 历史时间跨度大**（P1 三天前、P2 刚刚）：归并行按最新（P2）状态显示，列表位置按最新时间排序
- 🆕🆕 **组首左滑命中头行还是组首分P**：头行与组首分P 同属一个 ListItem，swipeAction 挂 ListItem——组首左滑一律整组移除（确认弹窗标注数量防误触），组首分P 的单删走多选
- 🆕🆕 **多选滑动范围选跨窄行**：ITEM_HEIGHT（68）估算对窄行（约 36）偏高，滑动选计数偏保守，仅影响多选效率不影响正确性
- 🆕🆕 **需要单独删/勾组内某个分P**：不支持（组为最小管理粒度）；绕行路径 = 整组移除后重新入队指定 `?p=N`

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 识别层 MUST 解析视频链接（BV URL / av URL / 短链解析后目标）中的 `?p=N` 参数作为入队定位意图，并在分享文案抽取与短链解析链路中保留该参数；p 越界或非法时按 P1 兜底 ✅ 已交付
- **FR-002**: 系统 MUST 解析视频信息接口响应中的分P 列表（分P 标识 cid、页号、分P 标题、时长），并 MUST 在无分P 列表或列表为空时回退视频级分P 标识（单分P，现状行为）✅ 已交付
- **FR-003**: 多P 视频入队时 MUST 将每个分P 生成为独立队列条目（各自持有分P 标识、页号、分P 标题、时长），不带 p 参数时全部分P 入队并自动连播，带 `?p=N` 时仅入队第 N 个分P；单P 视频保持单条目现状 ✅ 已交付
- **FR-004**: 队列条目身份 MUST 从 `bvid` 扩展为 `bvid + 分P 标识`：入队去重、随机播放轨迹、条目点选/删除均按分P 粒度 ✅ 已交付
- **FR-005**: 起播取流 MUST 使用队列条目自身的分P 标识（不得回退/覆盖为 P1），单P 与旧数据（无分P 字段）条目维持现有「拉取视频信息取 cid」路径 ✅ 已交付
- **FR-006**: 本地播放历史与续播 MUST 精确到分P（`bvid + 分P 标识` 粒度）：续播查询、完播标记、历史面板条目互不覆盖；历史键改造 MUST 保持与既有历史数据的向后兼容（旧条目视为 P1）✅ 已交付
- **FR-007**: 订阅详情页点播多P 视频时 MUST 展开全部分P 入队（复用既有追加不打断语义），列表行保持视频级展示 ✅ 已交付
- **FR-008**: 队列面板、历史面板、播放页、迷你播放器、系统媒体会话 MUST 按分P 显示名规则展示分P 条目标题（分P 名与视频标题相同/为空时省略）✅ 已交付
- **FR-009**: 单P 视频全链路行为 MUST 与改造前保持一致（回归约束）✅ 已交付
- **FR-010** 🆕: 历史面板 MUST 按视频归并展示：同 bvid 全部分P 历史合并为一行，主行视频标题，副行「相对时间 · 看到Pn · 剩余/已听完」（相对时间在最前，分P 名不展示；单P 与降级场景省略分P 段），行状态取该视频最新播放的分P，列表按视频最近播放时间倒序
- **FR-011** 🆕: 历史归并行点击 MUST 续播该视频最新播放的分P，并从该分P 的历史进度恢复
- **FR-012** 🆕: 历史行级删除（左滑单删/多选批删）MUST 以视频为单位：删除该 bvid 全部分P 历史；多选全选/计数以归并行为单位
- **FR-013** 🆕: 队列面板 MUST 为同视频相邻（≥2 条）的分P 条目渲染视频级分组头（视频标题）；分组头为非条目标签，不参与多选/左滑删除；单P 条目及不相邻条目无头
- **FR-014** 🆕: 分组头点击 MUST 播放该视频的续播点：存在播放历史时为最新播放分P（从其历史进度续播），无历史时为 P1（从头）；目标分P 条目在队列内时跳播该条目，不在队列内时插播构造该分P 条目
- **FR-015** 🆕: 历史存储、队列存储、身份键、续播逻辑 MUST 保持第一轮形态不变（归并与分组均为纯展示层，历史存储仍分P 粒度）；单P 视频与旧数据在归并/分组视图中表现正确（回归约束）
- **FR-016** 🆕🆕: 队列多P 分组 MUST 升级为两级呈现（修订 FR-013 形态）：组首渲染视频头行（封面+视频标题+共 nP 独占一行），组内条目渲染分P 窄行（Pn+分P 标题+时长，无封面，左缩进对齐头行标题）；单P/孤立条目保持原有整行
- **FR-017** 🆕🆕: 多选态视频头行 MUST 前置换 Checkbox 支持整组切换（组内全部复合键一次勾选/取消）；Checkbox 无半选态，部分选中显示未选；头行点击（多选态）同为整组切换
- **FR-018** 🆕🆕: 组首 ListItem 左滑 MUST 为整组移除：确认弹窗标注分P 数，确认后走既有批量移除链路（含当前条目自动切播）；其余条目保持单条左滑删除
- **FR-019** 🆕🆕: 队列增量删除后 MUST 强制重绑 LazyForEach 缓存条目闭包 index（删除后从最低删除位到末尾逐项 onDataChange）且分组派生函数 MUST 守卫 index 越界（根因见 bugfix.md ## 1.）
- **FR-020** 🆕🆕: 组内分P 条目 MUST NOT 提供独立管理（无左滑删除、无独立勾选框）；多选态点击/长按分P 均为整组语义（回溯组首），滑动范围选 MUST 组感知（区间碰到组内任一分P 补齐全组键）——组为最小管理粒度

### Key Entities *(include if feature involves data)*

- **分P（Part）**: 多P 视频的子单元，关键属性：分P 标识（cid）、页号（page）、分P 标题、时长；隶属唯一视频（bvid）✅ 已交付
- **队列条目**: 身份键 `bvid + 页号`；持有分P 页号/分P 标题 ✅ 已交付
- **播放历史条目**: 以 `bvid + 页号` 为续播/完播粒度 ✅ 已交付；🆕 展示形态新增两个**纯展示层**派生视图：历史归并行（视频级，派生自分P 历史）与队列分组头（派生自相邻同视频条目），均不落持久化

## Assumptions

- **基线**：两轮均在 master（v0.4）上开发；Pre-update 分支（v0.5 云同步）后续手动合并 ✅
- **t 参数不做**：URL 的 `&t=` 起播定位参数本轮不支持，继续忽略 ✅
- **分P 展开无数量上限** ✅
- **已听标记口径维持现状**（视频级宽松口径）✅
- **p 参数不持久化** ✅
- **单P 判定**：分P 列表缺失、为空或仅 1 项均视为单P ✅
- 🆕 **分组头视觉从简**：仅视频标题文字（弱化样式），不带「N 集」计数与展开控件；样式细节留实施轮按既有组件规范（列表行/空态）执行
- 🆕 **归并行显示最新分P**：「看到」的分P = 该 bvid 全部分P 历史中 viewAt 最新的一条；其进度/完播状态即行状态
- 🆕 **分组头点击的插播回退语义**：目标分P 不在队列时按既有历史点播路径（插播构造，播完回原当前条目）；在队列时跳播——两种路径复用既有机制，不引入新播放语义
