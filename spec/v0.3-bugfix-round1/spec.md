# Feature Specification: v0.3 Bug 修复第一轮

**Created**: 2026-10-11
**Status**: Draft
**Input**: 用户反馈 9 项（v0.3 真机实测）

## Overview

v0.3.0 发布后真机实测发现 9 处问题，覆盖播放控制异常（播放按钮呼吸浮动/状态抖动、MiniPlayer 周期变化、仅 Wi-Fi 开关误伤播放）、UX 噪音（全页面过冲文字、播放页状态行）、图标语义（倒序）、交互缺失（队列系统返回动画、多选模式退出）。本轮一次性修复，不引入新功能。

## User Scenarios & Testing

### User Story 1 - 播放按钮状态稳定（呼吸浮动 + 播放/暂停抖动 + MiniPlayer 周期变化）(Priority: P1)

用户在播放页按下播放按钮后，按钮出现呼吸浮动（光晕/缩放周期性变化），且播放/暂停图标在两者间来回切换；点开过一次播放页后，MiniPlayer 的播放按钮也出现周期性变化。期望播放/暂停切换是**一次点击一次明确状态变更**，无动画抖动、无状态回跳。

**Why this priority**: 播放核心控件状态不稳定直接影响使用，属最高优先级回归。

**Independent Test**: 播放页点播放→图标稳定为暂停态无浮动；多次点按状态逐一切换；回首页观察 MiniPlayer 按钮无周期变化。

**Acceptance Scenarios**:
1. **Given** 播放页打开且处于暂停态，**When** 点击播放按钮，**Then** 图标切换为暂停图标且保持，无呼吸浮动/缩放往复
2. **Given** 播放页已点开过（挂载过），**When** 返回首页观察 MiniPlayer，**Then** 播放按钮无周期性变化（与播放状态真实同步）
3. **Given** 播放中，**When** 连续点按播放/暂停多次，**Then** 每次点击状态恰好翻转一次，无抖动回跳

---

### User Story 2 - 移除全部页面「已经到顶了/已经到底了」文字提醒 (Priority: P2)

所有页面的边缘过冲提示文字（首页/订阅源页/设置页/播放历史面板/播放队列）在滚动到边界时弹出的「已经到顶了」「已经到底了」提示，用户认为属噪音，全部移除。

**Why this priority**: UX 噪音清理，不影响功能，P2。

**Independent Test**: 逐页滚动到顶/底，确认无文字提示出现。

**Acceptance Scenarios**:
1. **Given** 任意页面（首页/源页/设置页/历史面板/队列），**When** 滚动到顶或到底，**Then** 不再出现「已经到顶了/已经到底了」文字
2. **Given** 队列面板，**When** 拖拽过冲，**Then** 无文字提示（过冲回弹动画可保留）

---

### User Story 3 - 移除播放页最底层常驻状态行 (Priority: P2)

播放页最底部有一条常驻状态文字（如「在首页添加订阅，或到订阅源详情页播放节目」「已加载完成，处于暂停状态」等），用户要求整行移除。

**Why this priority**: 视觉噪音，播放页信息层级更干净。

**Independent Test**: 打开播放页，确认底部无状态文字行。

**Acceptance Scenarios**:
1. **Given** 播放页打开，**When** 观察页面底部，**Then** 无状态文字行（statusMsg 常驻底栏整行移除）
2. **Given** 播放状态变化（缓冲/错误/切歌），**When** 观察播放页，**Then** 仍无状态行（该提示通道整体关闭，不影响功能逻辑）

---

### User Story 4 - 倒序播放图标改为「顺序播放旋转 180°」 (Priority: P2)

当前倒序播放图标为系统 `reverse_order` 符号，语义不直观。采纳方案：使用顺序播放图标（`order_play`）旋转 180° 表达「倒序」——方向相反=倒序，更易理解。

**Why this priority**: 图标语义优化，纯 UX 调整。

**Independent Test**: 切换到倒序播放模式，观察图标为旋转 180° 的顺序播放样式。

**Acceptance Scenarios**:
1. **Given** 播放模式切到倒序（REVERSE），**When** 观察播放模式图标，**Then** 显示为旋转 180° 的顺序播放图标
2. **Given** 顺序/随机/单曲循环模式，**When** 观察图标，**Then** 维持原图标不变

---

### User Story 5 - 播放页内打开播放列表，系统返回退出有滑出动画 (Priority: P1)

在播放页内打开播放列表，按系统返回键直接关闭面板且**无动画**（面板瞬间消失）。期望与首页打开队列一致：先反向滑出动画再卸载。

**Why this priority**: 动画缺失造成交互突兀，属明显体验缺陷。

**Independent Test**: 播放页打开队列→按系统返回→面板先滑出动画再关闭。

**Acceptance Scenarios**:
1. **Given** 播放页打开且播放队列显示中，**When** 按系统返回键，**Then** 队列面板先滑出（250ms 动画）再卸载，与遮罩点击关闭行为一致
2. **Given** 队列关闭动画进行中，**When** 再次操作，**Then** 无重复触发/状态错乱

---

### User Story 6 - 「仅在 Wi-Fi 环境播放」开关正确拦截非 Wi-Fi 播放 (Priority: P1)

「仅在 Wi-Fi 环境播放」开关开启后，在流量（非 Wi-Fi）环境播放（起播/切歌/切集）应弹确认框「当前非 Wi-Fi 网络，在线播放会消耗流量，是否继续？」，未确认则取消本次播放。实测缺陷：流量环境播放中开启该开关后，后续切歌**不触发**该限制（开关不生效）。

**Why this priority**: 开关功能失效属功能性 bug，P1。

**Independent Test**: 流量环境播放中开启开关→切歌应弹非 Wi-Fi 确认框；确认后继续、取消则中止。

**Acceptance Scenarios**:
1. **Given** 开关开启且流量环境，**When** 播放新条目（起播/切歌/切集），**Then** 弹出非 Wi-Fi 确认框（「继续播放」/「取消」）
2. **Given** 确认框弹出，**When** 点「继续播放」，**Then** 本次播放正常发起
3. **Given** 确认框弹出，**When** 点「取消」，**Then** 本次播放被取消（statusMsg「当前非 Wi-Fi 网络，已取消播放」）
4. **Given** 开关开启且 Wi-Fi 环境，**When** 播放/切歌，**Then** 无确认框，直接播放
5. **Given** 开关关闭，**When** 流量环境播放/切歌，**Then** 无确认框，直接播放
6. **Given** 开关开启、流量环境正在播放，**When** 切歌时点「取消」，**Then** 不切换曲目——当前播放与 UI 保持原状（标题/封面/播放按钮不跳变、旧音频不中断）

---

### User Story 7 - 播放队列多选模式退出完整 (Priority: P1)

两处多选退出缺陷：① 队列处于多选模式时按系统返回，面板被直接关闭而非先退出多选（`onBackPress` 中 `selectMode` 分支排在 `showQueueSheet` 之后，先命中关面板）；② 关闭队列面板时未自动退出多选，重新打开仍处多选态。期望：系统返回优先退出多选；关闭面板自动退出多选。

**Why this priority**: 多选状态残留与返回行为错乱，直接影响操作正确性。

**Independent Test**: 队列多选态按返回→仅退出多选面板保留；关闭队列再开→无多选残留。

**Acceptance Scenarios**:
1. **Given** 队列多选模式激活，**When** 按系统返回，**Then** 退出多选（面板保持打开，无选中项）
2. **Given** 队列多选模式激活，**When** 再次按返回，**Then** 关闭队列面板
3. **Given** 队列多选模式激活，**When** 通过任意方式关闭面板（遮罩/返回/滑出），**Then** 多选状态复位，下次打开无残留

---

### Edge Cases

- 播放按钮在「缓冲中（isPreparing && playWhenReady）」状态：LoadingProgress 展示逻辑不受影响，仅动画/状态稳定性修复
- 队列面板在播放页实例（PlayerOverlay 内）与首页实例（Index 内）行为一致：均需滑出动画 + 多选退出
- 多选退出与「选中项删除中」并发：exitSelectMode 清空选中后 removeSelected 使用快照，无竞态
- 「仅在 Wi-Fi 环境播放」开关的拦截点为 `playIndex`（起播/切歌/切集统一路径）；暂停/续播等不重载音频的操作不经该路径、不受影响

## Requirements

### Functional Requirements

- **FR-001**: 播放页播放按钮 MUST 在单次点击后状态恰好翻转一次，无呼吸浮动/缩放往复/播放暂停回跳
- **FR-002**: MiniPlayer 播放按钮 MUST 与真实播放状态同步，无周期性抖动（与 FR-001 同源修复）
- **FR-003**: 所有页面（首页/源页/设置页/播放历史面板/播放队列）MUST 不再显示「已经到顶了/已经到底了」文字
- **FR-004**: 播放页 MUST 移除底部常驻 statusMsg 状态行（整行），播放逻辑状态通道保留但不再展示
- **FR-005**: 倒序播放模式图标 MUST 为顺序播放图标旋转 180°；其余模式图标不变
- **FR-006**: 播放页内打开播放队列后按系统返回 MUST 触发滑出动画再卸载（与首页实例一致）
- **FR-007**: 「仅在 Wi-Fi 环境播放」开关开启且非 Wi-Fi 时，播放（起播/切歌/切集）MUST 弹确认框；确认则继续、取消则中止本次播放（开关关闭或 Wi-Fi 环境不拦截）
- **FR-008**: 队列多选模式下按系统返回 MUST 优先退出多选（面板保持打开）
- **FR-009**: 队列面板关闭（任意方式）MUST 自动退出多选状态

### Key Entities

无新增数据实体；涉及现有：`PlayMode`（REVERSE 图标映射）、`Constants.KEY_WIFI_ONLY_DOWNLOAD`（开关语义边界）、`QueueSheet.selectMode` / `selectedBvids`（多选状态）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 播放页与 MiniPlayer 播放按钮在 10 次连续点按测试中零次状态回跳/抖动
- **SC-002**: 全部 5 处 EdgeHint 场景滚动边界零文字出现（代码层面全局检索「已经到顶了/已经到底了」零残留）
- **SC-003**: 播放页底部状态行零展示（全局检索状态行渲染分支已移除）
- **SC-004**: 播放页内队列返回 100% 走滑出动画路径（与首页实例行为一致）
- **SC-005**: 流量环境开关开启时，切歌/起播 100% 触发非 Wi-Fi 确认框；Wi-Fi 环境或开关关闭时零拦截
- **SC-006**: 多选模式退出路径（返回/关闭）全部复位，重开队列无多选残留

## Assumptions

- 播放按钮「呼吸浮动」根因包含 `updateGlow` 无限呼吸动画（`iterations: -1`）与 `popPlay` 缩放动画叠加、以及 `isPlaying` 广播时序导致的图标回跳——按「合并修复」处理两处（播放页 + MiniPlayer 同源）
- EdgeHint 组件本体可保留（过冲回弹动画等），仅移除文字提示渲染与赋值逻辑；若组件仅承载文字则整体移除
- 「仅在 Wi-Fi 环境播放」开关（内部键 `KEY_WIFI_ONLY_DOWNLOAD` 为历史遗留误导名，语义以 UI 文案为准）本轮**恢复**其非 Wi-Fi 播放确认拦截（原 T005 误删已回退）；拦截点为 `playIndex`
- 多选退出修复点在 `Index.onBackPress` 顺序调整 + `QueueSheet` 关闭路径复位

## Open Questions
