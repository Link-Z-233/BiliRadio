# Feature Specification: v0.6-part1 收藏夹归属显示与队列联动取消收藏

**Status**: Draft
**Input**: User description: "进v0.6，改为只有登录账号的up名不显示；登录账号的收藏夹取消收藏触发改为从播放列表发起：移除已看完视频时（清空已看完、多选移除、左滑移除等）若该视频来自个人收藏夹，二次询问是否取消收藏；设置页登录状态行移到账号设置组下方"；追加: "清除已播完时当前在播的已完成条目也一并移除"

## Overview

本轮解决三件事：① 修复数据缺口——队列条目从未在源头携带来源收藏夹标识（`folderIds` 只有传播与序列化代码，无填充点），导致播放层既有「取消收藏」对新入队条目实际不可用；② 在此基础上，队列移除视频时对「登录账号本人收藏夹来源」的条目联动提供取消收藏选项；③ 收藏夹详情页按归属差异化显示，并将设置页登录状态行移到账号组下方。

## User Scenarios & Testing

### User Story 1 - 队列移除联动取消收藏 (Priority: P1)

用户把收藏夹当播客歌单听，听完（✓ 标记）后从队列清掉。当被移除的视频来自登录账号本人的收藏夹时，移除动作触发一次二次询问：「同时取消收藏」则从 B 站对应收藏夹一并移除，「仅移除」则只清本地队列（与现状一致）。

**Why this priority**: 听完即清是播客核心循环的收尾动作；联动取消收藏让「听过的」在云端收藏夹同步变干净，订阅刷新后不再重复出现。

**Independent Test**: 登录后订阅自己的收藏夹 → 入队听完 → 队列「清除已看完」→ 弹出二次询问 → 选「同时取消收藏」→ 队列移除且刷新收藏夹后该视频消失。

**Acceptance Scenarios**:

1. **Given** 队列含多条来自本人收藏夹的已看完条目, **When** 清除已看完, **Then** 聚合弹出一次二次询问（不逐条弹），确认后全部从对应收藏夹移除
2. **Given** 队列含本人收藏夹来源条目, **When** 多选移除或左滑移除, **Then** 同样触发二次询问
3. **Given** 被移除条目来自别人的公开收藏夹、合集/系列/UP 源或本地内容，或未登录, **When** 任一移除路径移除, **Then** 不弹询问，行为与现状完全一致
4. **Given** 用户选择「仅移除」, **When** 确认, **Then** 仅本地队列移除，云端收藏夹不变
5. **Given** 取消收藏请求失败（网络/风控）, **When** 移除完成, **Then** 本地移除不受影响，失败以提示透出

---

### User Story 2 - 收藏夹详情页归属化显示 (Priority: P2)

收藏夹详情页按「收藏夹是否归属当前登录账号」切换显示：本人的夹子——页头不显示主人名（自己的夹子无意义），剧集行显示每集来源 UP 名（跨 UP 收藏时分辨每条来源）；别人的夹子（含未登录）——页头显示收藏夹主人名（知道在看谁的收藏），剧集行不显示来源 UP 名。

**Why this priority**: 提升收藏夹详情页的信息辨识度；数据（每集 ownerName）已在缓存链路就绪，纯展示规则改动。

**Independent Test**: 登录账号 A，订阅 A 的收藏夹与 B 的公开收藏夹，分别进入详情页核对页头与剧集行显示；换登账号 B 后重进，显示规则随新身份切换。

**Acceptance Scenarios**:

1. **Given** 登录账号与收藏夹归属一致, **When** 进入收藏夹详情页, **Then** 页头不显示主人名，剧集行显示每集来源 UP 名
2. **Given** 登录账号与收藏夹归属不一致（含未登录）, **When** 进入详情页, **Then** 页头显示收藏夹主人名，剧集行不显示来源 UP 名
3. **Given** 已在详情页后切换登录账号, **When** 重新进入详情页, **Then** 显示规则按新登录态重新判定，无需迁移任何数据
4. **Given** 归属信息（主人名）获取失败, **When** 非本人夹进入详情页, **Then** 页头降级不显示名字，其余功能不受阻

---

### User Story 3 - 设置页登录状态行移位 (Priority: P3)

设置页底部的登录操作状态行（`statusMsg`）移到账号设置组下方——状态发生在账号区，提示却在页面最底部看不见，移位后即时可见。覆盖式更新逻辑保留。

**Why this priority**: 独立小改动，修复提示可见性问题。

**Independent Test**: 登录/登出操作后，状态提示出现在账号设置组正下方而非页面底部。

**Acceptance Scenarios**:

1. **Given** 任一登录态, **When** 登录或登出操作产生状态更新, **Then** 状态文本渲染于账号设置组下方
2. **Given** 状态行已有旧提示, **When** 新的登录/登出操作完成, **Then** 新提示覆盖旧提示

---

### User Story 4 - 清除已播含当前在播已完成条目 (Priority: P1)（追加）

「清除已播」不再无条件保留当前在播条目：当前条目已看完（✓ 口径）或数据源异常（X 标记）时，与队列中其他已播条目一并无差别移除；移除当前条目沿用既有移除当前语义（停当前、自动切播后继条目；队列清空则整队重置停声）。修正 v0.3「当前条目永远保留」口径——已看完的当前条目保留无意义，用户清的就是「听过的」。

**Why this priority**: 追加修正既有口径，清除动作与用户意图（清掉听过的）对齐。

**Independent Test**: 重播一条已看完条目 → 队列「清除已播」→ 确认 → 当前条目被移除且自动切播下一条；队列仅剩当前一条已看完条目时清除 → 队列清空、播放停止。

**Acceptance Scenarios**:

1. **Given** 当前在播条目已看完, **When** 清除已播, **Then** 该条目随其他已播条目一并移除，自动切播后继未播条目
2. **Given** 队列仅剩当前一条已看完条目, **When** 清除已播, **Then** 队列清空、播放停止（沿用既有空队列重置链路）
3. **Given** 当前在播条目未看完且无异常, **When** 清除已播, **Then** 该条目保留（判定口径不变，仅放开已看完/异常命中的当前条目排除）

---

### Edge Cases

- 同一次移除命中多条来自不同本人收藏夹的条目：聚合询问一次，确认后按各自来源夹分别取消收藏
- 被移除条目含当前正在播放条目：本地移除沿用既有索引修正/后继播放语义，取消收藏仅是额外云端调用，不改变移除链路行为
- 取消收藏接口风控（-412 等）：失败提示真实错误，不无限重试
- 队列持久化旧数据无来源标识：视为无归属，不询问，行为同现状
- 换账号后队列残留旧账号收藏夹条目：按新账号判定为非本人，不询问
- 旧剧集缓存缺 ownerName（历史数据）：对应剧集行不显示 UP 名，刷新后补全，不阻塞

## Requirements

### Functional Requirements

- **FR-001**: 从收藏夹订阅入队/起播的条目 MUST 携带来源收藏夹标识（复用既有 `folderIds` 字段，在入队链路源头填充），并随队列持久化保留
- **FR-002**: 队列全部既有移除路径（清除已看完、多选移除、左滑移除）MUST 识别被移除条目中「登录账号本人收藏夹来源」的条目；无命中时 MUST NOT 弹出任何询问
- **FR-003**: 命中时 MUST 弹出一次聚合二次询问，提供「同时取消收藏」与「仅移除」两种选择；询问每次移除动作均出现（不做「不再询问」记忆，用户未要求）
- **FR-004**: 选择「同时取消收藏」时 MUST 对每条命中条目从其来源收藏夹发起 B 站取消收藏（复用既有 deal 接口链路）；任一失败 MUST 提示且 MUST NOT 回滚或阻塞本地移除
- **FR-005**: 本人收藏夹判定 MUST 基于当前登录态动态进行（操作时判定，不预存不迁移）；未登录或归属非本人 MUST NOT 询问
- **FR-006**: 收藏夹详情页显示规则：归属本人——页头 MUST NOT 显示主人名、剧集行 MUST 显示每集来源 UP 名；归属非本人（含未登录）——页头 MUST 显示主人名、剧集行 MUST NOT 显示来源 UP 名
- **FR-007**: 收藏夹归属数据路径（主人 mid/昵称）实施时 MUST 实测 `fav/resource/list` 的 `info` 字段并将结论补录 `BILI_NOTES.md` §3（现未覆盖）；实测不可行时以「我的收藏夹列表」比对为兜底
- **FR-008**: 设置页登录状态行 MUST 移至账号设置组下方渲染，覆盖式更新逻辑保持不变
- **FR-009**: 播放层既有「取消收藏当前条目」入口随 FR-001 打标修复后 MUST 对收藏夹来源条目恢复实际可用（现状因 `folderIds` 恒空而不可达）
- **FR-010**: 「清除已播」MUST 将命中的当前在播条目（已看完或数据源异常）与其他已播条目一并无差别移除，并 MUST 沿用既有移除当前语义（索引修正、自动切播、空队列重置）；当前条目未看完且无异常时 MUST 保留（追加，修正 v0.3「当前条目永远保留」口径）

### Key Entities

- **队列条目来源标识**: 条目来自哪个收藏夹（来源夹 ID 列表）；判定「个人收藏夹来源」与取消收藏目标夹的唯一依据
- **收藏夹归属**: 收藏夹主人的 mid 与昵称；与当前登录账号 mid 比对得出「本人/非本人」，驱动显示规则与询问触发
- **已听完标记（✓ 口径）**: 播放历史 `progress === -1`（播完自动或手动「标记已看完」写入）；「清除已看完」的既有判定基准，本轮不改动

## Success Criteria

### Measurable Outcomes

- **SC-001**: 本人收藏夹来源的已看完条目经队列任一移除路径均可一步联动取消云端收藏，全程最多一次弹窗
- **SC-002**: 非本人夹、未登录、非收藏夹来源条目的移除流程零新增打扰（无弹窗、无额外请求）
- **SC-003**: 收藏夹详情页按归属正确切换页头/剧集行显示，换账号后重进即按新身份正确显示
- **SC-004**: 登录/登出状态提示出现在账号设置组下方，账号操作完成后无需滚动即可见

## Assumptions

- 二次询问 UI 沿用项目既有确认弹窗规范；批量结果提示聚合为一条（逐条提示未要求）
- 归属判定数据源优先 `fav/resource/list` 的 `info` 归属字段（FR-007 实测定），失败降级「我的收藏夹列表」比对
- 剧集行来源 UP 名沿用剧集缓存既有 `ownerName` 数据；旧缓存缺字段时该行降级不显示
- 源页 ··· 菜单不新增「取消已观看收藏」入口（用户已改为队列侧触发方案，源页入口取消）
- 队列侧方案不改动收藏夹剧集缓存机制（「近期一页」语义不变，全量清理不在本轮范围）

## Open Questions

- `fav/resource/list` 的 `info` 是否含归属 mid/昵称（实施首日实测，结论补录 BILI_NOTES；不含则走 fetchMyFolders 兜底，功能不受损）
- 二次询问在「清除已看完」路径与既有二次确认弹窗（「清除 N 条已看完」类）的叠加次序：合并为一次带选项的弹窗还是先确认清除再询问取消收藏（实施时按既有弹窗规范取交互最少的一档）
