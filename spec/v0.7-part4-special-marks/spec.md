# Feature Specification: 特殊视频标记（充电专属/互动视频/付费内容/大会员）

**Status**: Draft
**Input**: User description: "新增特殊视频标记功能：充电视频/互动视频/大会员视频/付费内容四类列表级角标 + playurl 门禁码修复"

## Overview

为 BiliRadio 增加四类特殊视频的列表级标记（充电专属、互动视频、付费内容/课程、大会员），让用户在浏览源页列表、播放队列、播放历史时能一眼识别稿件特殊属性，避免「点了才发现看不了」或「不知道为什么有杂音/剧情树」的困惑。同时修复上一轮遗留的 playurl 门禁码误分类：87007/87008（充电专属）/87005（付费未购买）此前落入「瞬时失败」停等人工重试，本轮重分类为明确异常并直报原因。

真机反馈修订（本轮再优化）：① 入队标志保真修复——入队统一经详情链（web-interface/view）重建条目，原实现不解析付费/会员字段、充电字段读错位置（rights→顶层），致入队后标志丢失；② 课程（is_pugv）归类修正——B 站课堂课程是付费购买内容，从大会员类挪入付费类；③ 源页角标重做为封面右上角类型色底 pill（符号+文字）；④ 队列/历史标记挪标题前缀（大会员用「大」单字），与行尾 ✓/✗/! 状态标分位；⑤ 播放详情页（PlayerOverlay）不加标记——能播放即以队列提示；⑥ 收藏夹多选批量入队走详情链补全（仅 fav 源，并行拉详情有并发上限，单条失败降级原列表行）——fav 行数据源无任何标志字段，批量直入队列会致互动稿漏拦且无标识。

标记体系分两层（与上轮 v0.7-part3 的 X/异常双标记互补）：
- **列表级预标记**：从各数据链现有的属性字段/角标数据解析，纯展示，有数据就标、无数据不标
- **播放级失败标记**：播放鉴权失败后由门禁码触发明确异常分类（复用上轮异常标记体系）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 播放门禁码明确分类与直报（Priority: P1）

用户播放一个充电专属或付费视频（未充电/未购买）时，播放失败被归入明确异常分类，toast 直报原因（「需要充电」/「需要付费」类提示），不再落入「瞬时失败」停等人工重试的误分类；该视频在播放器标记体系中按明确异常处理（与 -104 大会员类同语义，区别于时长异常类的「不说明原因」）。

**Why this priority**: 上轮遗留的功能性 bug——门禁码误分类导致用户面对无限停等的播放重试，无任何原因提示；本轮修复使失败语义与官方错误码对齐。

**Independent Test**: 播放任一充电专属/付费稿件（未充电/未购买账号），观察 toast 与标记行为，不依赖列表角标实现。

**Acceptance Scenarios**:

1. **Given** 未充电账号播放充电专属稿件，**When** playurl 返回 87007 或 87008，**Then** 播放失败归入明确异常分类（非瞬时失败、非停等重试），toast 提示需要充电类原因，播放器按明确异常标记该视频
2. **Given** 未购买账号播放付费稿件，**When** playurl 返回 87005，**Then** 同上，toast 提示需要付费类原因
3. **Given** 播放门禁类失败，**When** 用户查看该视频所在列表/队列，**Then** 该视频呈现明确异常标记（复用上轮异常标记 UI 语义），与门禁原因分类一致
4. **Given** 门禁码返回其他未知错误码，**When** 播放失败，**Then** 维持现有分类行为不变（不误伤未知码）

### User Story 2 - 源页列表四类封面角标（Priority: P1）

用户浏览源页视频列表时，充电专属、互动视频、付费内容（含课程）、大会员类稿件在列表行**封面右上角**显示类型色底 pill 角标（符号 + 文字：「充电」「互动」「付费」「大会员」；大会员无符号，加粗大字即标识）；角标来自各数据链已有字段，有数据就标、无数据不标，不发起逐条补数请求。标志随入队路径经详情链保真（入队重建条目继承原标志）。

**Why this priority**: 核心展示价值——用户点开前的第一道信息；数据来源已实测确认（BILI_NOTES §3.12），实现风险低。

**Independent Test**: 订阅含充电专属稿件的 UP（如小约翰可汗），刷新源页，观察充电稿封面右上角「充电」pill 角标；不依赖 US1。

**Acceptance Scenarios**:

1. **Given** 源页列表含充电专属稿件（APP cursor 链 badges 含「充电专属」文案），**When** 列表渲染，**Then** 该行封面右上角显示「充电」pill 角标（类型色底 + 闪电符号 + 文字）
2. **Given** 源页列表含互动视频（互动标志字段为真），**When** 列表渲染，**Then** 封面右上角显示「互动」pill 角标
3. **Given** 源页列表含付费稿件或课程（付费/课程标志字段为真），**When** 列表渲染，**Then** 封面右上角显示「付费」pill 角标
4. **Given** 源页列表含大会员类稿件（会员标志字段为真），**When** 列表渲染，**Then** 封面右上角显示「大会员」pill 角标（无符号，加粗大字即标识）
5. **Given** 稿件无任何特殊标志或数据链不提供该字段（如合集/系列源无充电字段），**When** 列表渲染，**Then** 不显示任何角标（不补数、不猜测）
6. **Given** 同一稿件命中多类标志，**When** 列表渲染，**Then** 多角标并排显示，不互相覆盖
7. **Given** UP 源大会员专享稿件（如 BV1DH6nYSEUA）加入播放队列，**When** 队列渲染，**Then** 该条目保留会员标志（详情链 rights.pay 解析保真，入队不丢）
8. **Given** 收藏夹多选批量入队，**When** 确认执行，**Then** 选中条目先经详情链并行补全标志（并发上限走 Constants 令牌）再入队，队列条目带标志；单条详情失败降级用原列表行入队（该条无标志、互动不拦）

### User Story 3 - 互动视频入队拦截（Priority: P1）

用户对互动视频点播/添加到播放队列时，系统拦截并入队失败，提示原因（互动视频的剧情树对音频流无意义）；充电专属（有试听流）、付费（已购/试听）、大会员类不拦截——是否可播交给播放层鉴权（US1）。

**Why this priority**: 用户明确决策的拦截——互动视频音频流无意义是确定性判断，而其他三类是否可播放取决于用户账号状态，全拦会误伤已充电/已购/大会员用户。

**Independent Test**: 对任一互动视频执行加入队列/点播，观察拦截与提示；不依赖角标渲染。

**Acceptance Scenarios**:

1. **Given** 用户对互动视频执行点播或加入队列，**When** 拦截触发，**Then** 不入队、不发起播放，提示互动视频不支持播放类原因
2. **Given** 用户对充电专属视频执行同样操作，**When** 视频非互动类，**Then** 正常入队（是否可播由播放层鉴权，试听流可播则播）
3. **Given** 互动视频标志缺失（数据链未提供该字段），**When** 用户执行点播，**Then** 不拦截（有数据就标、无数据不拦，同角标原则）
4. **Given** 收藏夹多选批量入队含互动稿件，**When** 详情链补全后入队，**Then** 互动稿被过滤拦截（混合场景跳过、全互动返回 INTERACTIVE）；单条详情失败的条目按 AC3 原则不拦

---

### User Story 4 - 播放队列/历史图标角标（Priority: P2）

用户查看播放队列和播放历史时，特殊稿件行在**标题前缀**显示标记（充电⚡/互动岔路/付费卡图标、大会员「大」单字，类型色区分），与行尾 ✓/✗/! 状态标分位互不争位；与源页角标共用同一标志数据。

**Why this priority**: 增强性展示——队列/历史行空间紧凑，标记保持信息可见又不挤占布局；依赖 US2 的标志数据，故排后。

**Independent Test**: 含特殊稿件的队列/历史列表渲染后观察标题前缀标记；依赖标志数据解析（US2 数据层）但不依赖源页渲染。

**Acceptance Scenarios**:

1. **Given** 播放队列含充电专属/互动/付费/大会员稿件，**When** 队列渲染，**Then** 对应行标题前缀显示该类标记（充电⚡/互动岔路/付费卡图标、大会员「大」单字），不与行尾 ✓/✗/! 状态标争位
2. **Given** 播放历史含上述稿件，**When** 历史渲染，**Then** 同上
3. **Given** 稿件无标志，**When** 渲染，**Then** 标题前缀无标记

---

### Edge Cases

- 合集/系列源天然无充电字段（BILI_NOTES §3.12 实测）——充电角标在此类源不显示，接受盲区，不补数
- 旧缓存记录无新标志字段——不标（标志随下次刷新数据自然补齐）
- 充电判定依赖 badges 文案「充电专属」精确匹配——B 站未来改文案则漏标（漏标比误标安全，不损坏任何行为）
- 多标志并存（如付费+大会员）——全部显示，不做互斥优先级
- 未知门禁码（87007/87008/87005 之外）——维持现有分类，不猜原因
- 播放中的稿件标志数据与实际门禁不一致（预标记说可播、播放被拦）——以播放层鉴权结果为准，US1 异常标记覆盖预标记
- 收藏夹行数据源（新旧 API）无任何标志字段（BILI_NOTES §3.12 二十行实测+文档+PiliPlus 旁证）——收藏夹列表内角标不显示，接受盲区；仅批量入队时经详情链补全
- 课程标志 is_pugv 仅合集 cursor 链可得（详情链 view 响应无此字段）——课程稿经详情链入队时课程标志丢失，接受盲区（付费标志若 rights.ugc_pay 在位则保留）
- 收藏夹批量入队单条详情失败——降级用原列表行入队：该条无标志、互动不拦（「有数据就标、无数据不拦」一致性原则）
- 收藏夹批量入队属罕见入口+低频操作——并行详情补全的并发上限走 Constants 令牌，不为它做队列化基础设施

### Non-goals

- 播放详情页（PlayerOverlay）不加特殊标记——能播放即以既有队列提示呈现
- 收藏夹批量入队不做入队结果回写源页列表、不做互动跳过 toast 追加提醒——statusMsg 既有的「已跳过 N 个互动视频」通报已足够

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将 playurl 错误码 87007/87008 归类为「充电专属不可播」明确异常，87005 归类为「付费未购买」明确异常，toast 分别直报需要充电/需要付费类原因，不再进入瞬时失败重试流程
- **FR-002**: 系统 MUST 从各数据链解析四类特殊标志（充电专属/互动视频/付费内容/大会员），存入视频模型并随缓存持久化（已有充电专属字段沿用，互动/付费/大会员为新增）；详情链（view 响应）解析 MUST 覆盖 rights.pay（大会员，与充电互斥防双标）、rights.ugc_pay（付费）、顶层 is_upower_exclusive（充电，rights 兜底）、rights.is_stein_gate（互动）；课程（is_pugv）MUST 归入付费类而非大会员类
- **FR-003**: 源页列表行 MUST 在封面右上角显示类型色底 pill 角标（充电/互动/付费为符号+文字，大会员为加粗大字无符号），多标志并排，无标志不显示，不发起逐条补数请求
- **FR-004**: 播放队列与播放历史行 MUST 在标题前缀按同一标志数据显示标记（充电/互动/付费图标、大会员「大」单字），与行尾状态标分位
- **FR-005**: 系统 MUST 无条件拦截互动视频的点播与入队并提示原因；其他三类不拦截；收藏夹批量入队 MUST 经详情链补全后拦截（覆盖源页单击/「+」添加/UP 批量/合集批量/收藏夹批量全部入队路径）
- **FR-006**: 标志解析 MUST 遵循「有数据就标、无数据不标」——字段缺失/数据链不提供时置无标志，不猜测不补数
- **FR-007**: 门禁异常与列表预标记 MUST 在语义上分层——预标记纯展示不拦播放，门禁异常以播放层鉴权结果为权威
- **FR-008**: 收藏夹源多选批量入队 MUST 先并行拉取详情补全标志再入队（仅 fav 源；并发上限走 Constants 令牌；单条详情失败降级用原列表行入队）；UP 源/合集行自带标志不拉详情

### Key Entities *(include if feature involves data)*

- **视频模型特殊标志**（BiliVideo 扩展）：充电专属（已有字段沿用）、互动视频、付费内容、大会员/课程四个独立布尔标志；随缓存记录序列化持久化
- **播放器异常分类**（PlayerController 既有体系扩展）：门禁类异常作为明确异常的子类，携带原因文案（充电/付费），与瞬时失败、时长异常、大会员 -104 并列

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未充电/未购买账号播放门禁稿件时，100% 直报原因类 toast，0 次落入停等人工重试
- **SC-002**: 四类特殊稿件在源页列表（封面 pill）、队列、历史（标题前缀）中均有对应标记呈现，普通稿件 0 误标
- **SC-003**: 互动视频点播/入队 100% 被拦截并提示（含收藏夹批量经详情链补全路径）；非互动特殊稿件 0 误拦
- **SC-004**: 刷新源页不因标志解析新增任何逐条网络请求（请求数与上轮持平）

## Assumptions

- 主数据源为 APP 签名链（cursor/view），已实测字段可得（BILI_NOTES §3.12）；Web WBI 链解封与否（WbiSigner 修复后待真机验证）只影响补充数据源，不阻塞本轮
- 大会员类仅覆盖 rights.pay 专享 UGC 与 PGC 引用（识别层已拒收 PGC，实际进入列表者为 UGC）——B 站课堂课程（is_pugv）归付费类
- 角标样式沿用项目既有令牌体系（Constants/资源令牌）；pill 底色为类型色低饱和/半透明变体，新增 color 资源登记
- playurl 门禁码 87007/87008/87005 语义以官方客户端逆向确认为准（`接口调用学习笔记.md` §7.5）
- 上轮 X/异常标记语义（v0.7-part3 spec）不变，本轮仅新增门禁子类

## Open Questions

- 真机 Web 链解封验证结果（WbiSigner 修复后）——若解封，Web vlist 的充电/互动/付费字段成为第二数据源，spec 数据源设计可增强；不解封则维持 APP 链单源
- 付费稿件正样本（is_pay=1 行）未实测取得——付费角标依赖字段旁证（字段在位、官方客户端逆向确认），首轮真机验证需找付费样本复核
- 门禁码 87005/87007 真机实测需登录态+对应样本——toast 文案与异常标记的实际表现待真机验证
- Web view 响应 rights 形状未直测（PC 出口 412 风控，BILI_NOTES §3.12）——顶层 is_upower_exclusive 与 rights 表字段以文档旁证为准，真机日志验证解析命中
- 收藏夹批量入队的并发详情补全未做真机实测——并发上限令牌初值取保守值，真机验证请求耗时与成功率后校准
