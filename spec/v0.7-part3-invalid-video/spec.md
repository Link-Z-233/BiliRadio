# Feature Specification: v0.7-part3 队列失效视频识别与播放失败处理

**Input**: User description: "播放列表（队列）里的失效视频——连播撞上失效视频整个队列卡死，需要识别与处理" + 澄清轮：「重点是播放列表，订阅源侧（合集/系列过滤）本轮不纳入」「失效视频按必跳过处理，不设开关」「失效标记复用充电 X」「大会员内容可经收藏夹进入订阅列表（fav 源只滤 attr&1 失效、不滤会员稿）」「给无权限视频做一个新标记」+ 修正：「非会员用户收听大会员内容、未充电用户收听充电视频都是无权限。区别是大会员内容有官方接口提供内容可以识别内容，能直接提示无权限原因」+ 文案修正：「试听内容不报『完整版需充电』，因为只能判断源异常，不能判定是否是充电视频」+ 标记语义定稿：「X 只代表无法获取的视频。充电大会员这种无法获取完整的视频标为异常：大会员官方有明确接口，可以直接说是大会员视频；但充电的话仅靠本地自行判断，无法百分百确认，所以通知中不说明是充电视频」+ bug 报告：「播放异常时的处理也有问题，比如播放按钮不会切换至暂停态、手动切换切换到异常条目后重启会回到上一条之类的」+ 澄清轮：「风控/网络瞬时失败：停下等人工重试、文案分型，不自动重试（密集请求会升级风控）」+ 修订：「取消『异常源处理』开关，充电视频直接都跳过」（取代 v0.5-part5 FR-003/FR-004 的两档语义）+ 纳入：「playIntent 复位 bug 随本轮修复」+ 追问轮（现状核实）：「404 现状不暂停——手动切换撞 404 旧声音继续放（setPlaying 只改标志不 pause 播放器，旧 AVPlayer 到新流 open 成功才重建释放）」「现状异常源处理分路径不一致：时长异常跳过、404 停摆」「队尾无下一条可跳时持久化也必须解决：失败条目持久化为当前条目，重启不回退上一条」

## Overview

播放链路对取流失败按错误码分类处理，终结「连播撞上确定性失败条目整条队列卡死」。标记体系两类：**X（无法获取，不可恢复）**——视频不存在（-404 官方码，bvid 不复用），标 X + 必跳过自动连播；**异常标记（无法获取完整，可恢复，统一新标记）**——视频存在但未获完整流，两路判定写入同一标记集：大会员专限（playurl -104，官方接口明确识别，toast 直报「需要大会员」）、时长异常（流时长 < 元数据 × 0.5，仅靠本地判断、无法百分百确认为充电视频，toast 只报观测「音源异常」、不说明是充电视频）；跳过自动连播，成功播放完整内容自动摘标记（开通大会员 / 获得完整流两条恢复路径共用）。风控/网络瞬时失败不跳不标不自动重试、停下等人工重试，文案分型且不再外露原始错误码。异常处理状态一致性修复：playIndex 失败路径复位 playIntent（播放按钮状态正确）；失败路径持久化失败条目为当前条目（含队尾无法跳过场景），重启恢复至用户所在条目不回退上一条，已标记条目恢复后不自动重播；切换取流失败时旧播放器显式停声（杜绝「声音旧、界面新」错位）。既有 anomalySet 条目全部为 v0.5-part5 时长判定（失效视频到不了 prepared，从未入集），整体转为异常标记语义（零数据迁移），其视觉由 X 变更为异常标记形态；「异常源处理」开关废止，时长异常条目一律跳过。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连播撞上失效视频：识别与必跳过 (Priority: P1)

队列连播到已删除视频（view 或 playurl 回 -404）：该条目标 X（独立持久化标记，视觉沿用带圈 X）+ toast「视频已失效，已跳过」+ 自动连播下一首；条目保留在队列，可被「清除已播」一键清理。

**Why this priority**: 现状连播撞失效视频 playIndex 抛错后不前进不跳过，整条队列连播停摆，是本轮核心问题；-404 是确定性失败（bvid 不复用，重试无意义），跳过无争议。

**Independent Test**: 队列放入一个已删除的 BV，连播观察：toast 分型文案、自动跳到下一首、条目出现 X、条目仍在队列且计入「清除已播」。

**Acceptance Scenarios**:

1. **Given** 队列含失效视频，**When** 连播推进到该条目，**Then** toast「视频已失效，已跳过」+ 自动连播下一首 + 该条目标 X（持久化）
2. **Given** 失效条目已标 X，**When** 打开队列/历史/源页剧集行，**Then** 三处 X 显示（复用既有渲染链路）
3. **Given** 队列含失效（X）条目，**When** 点「清除已播」，**Then** 失效条目随已播条目一并移除（三处口径一致）
4. **Given** 失效视频，**When** 单独手动点播它，**Then** 同样提示失效并保持跳过语义，不进入死循环重试

---

### User Story 2 - 大会员专限视频：异常标记与官方原因直报 (Priority: P2)

收藏夹含大会员专限 UGC 视频（fav 源不滤会员稿，经订阅列表进入队列）：播放取流时 playurl 回 -104（官方接口明确识别），标异常标记 + toast「需要大会员，已跳过」+ 跳过自动连播下一首。

**Why this priority**: 经收藏夹进入订阅列表是真实可达路径（用户领域知识：收藏夹可收藏会员专限投稿，attr 不含会员标记）；-104 是官方信号，可直接说明是大会员视频；跳过+连播是「确定性失败必跳过」规则的落点。

**Independent Test**: 队列放入一个大会员专限 UGC 的 BV，播放观察：toast「需要大会员，已跳过」、自动连播、条目出现异常标记（非 X）。

**Acceptance Scenarios**:

1. **Given** 队列含大会员专限视频，**When** 连播推进到该条目，**Then** toast「需要大会员，已跳过」+ 自动连播下一首 + 标异常标记（持久化）
2. **Given** 被跳过的会员专限条目，**When** 查看队列/历史/源页剧集行，**Then** 三处显示异常标记（视觉区别于 X）
3. **Given** 用户开通大会员后重播该条目，**When** 取流成功正常播放，**Then** 自动摘除异常标记，无残留

---

### User Story 3 - 时长异常视频：异常标记、观测事实提示与开关废止 (Priority: P2)

时长异常视频（流时长 < 元数据 × 0.5，仅靠本地判断、无法百分百确认为充电视频——多为未充电取充电视频得试听流，但判定本身不说明原因）：标异常标记 + toast「音源异常，已跳过」（报可观测事实，不说明是充电视频；具体措辞 plan/评审可调）+ 跳过自动连播下一首。「异常源处理」开关废止：设置页移除该行，「照常播放」分支与试听 toast（TOAST_ANOMALY_TRIAL）移除，KEY_ANOMALY_SKIP 存量值不再读取，行为统一为跳过（取代 v0.5-part5 FR-003/FR-004 两档语义）。获得完整流重播 → 自动摘异常标记（恢复路径）。

**Why this priority**: 开关两档中「照常播放」价值低（1 分钟试听对照 20 分钟正片）且是分支复杂度来源；时长异常与大会员专限同属「无法获取完整」（用户分类），统一异常标记后开关失去存在意义；时长比较是唯一可用判据（充电状态 API 被风控不可用，v0.5-part5 已拍板）——判定只能建立「拉到的流与元数据时长不符」这一观测事实，充电视频这一原因不可百分百确认，通知不说明。

**Independent Test**: 播放队列存量充电稿，观察无条件跳过标异常标记、toast 只报音源异常（不提充电）；设置页无「异常源处理」行。

**Acceptance Scenarios**:

1. **Given** 队列含充电视频（用户未充电），**When** 连播推进到该条目，**Then** toast「音源异常，已跳过」（不说明是充电视频）+ 标异常标记 + 自动连播下一首（无论原开关存量值）
2. **Given** 设置页，**When** 查看，**Then** 无「异常源处理」行
3. **Given** 用户已充电后重播已标异常的条目，**When** 拉到完整流，**Then** 自动摘异常标记恢复正常
4. **Given** 视频元数据时长缺失（duration=0/未知），**When** 播放，**Then** 跳过时长检测照常播放（宁可漏判不误判，既有边界保留）

### User Story 4 - 播放异常处理状态一致性：瞬时失败分型、意图态复位、持久化与旧声停播 (Priority: P1)

四类修复合一（均为「播放异常处理状态不一致」问题群，用户实测报告 + 现状核实）：

**瞬时失败分型**：风控/网络类瞬时失败不跳过、不标任何标记、不自动重试（密集自动重试会升级风控），停在当前条目等人工重试；toast 按失败类型分型（网络类「网络异常，请检查网络后重试」/ 风控类「请求被拦截，请稍后重试」），不再一律「播放出错，请稍后重试」，不再把 `Bili API error -412` 原始串怼在状态栏。

**意图态复位**：playIndex 失败路径复位 playIntent——现状进门置 true、catch 不还原，播放按钮不会切换至暂停态（用户实测；对照：AVPlayer 运行时错误路径 onError 有复位而 playIndex catch 没有），修复后播放/暂停图标与实际状态一致，人工点播放即重试当前条目。

**持久化一致性**：playIndex 失败路径持久化当前失败条目为当前条目（含队尾确定性失败无法跳过的场景）——现状 savePlaylistFile 只在取流成功后写盘（:1049），失败条目从未持久化，重启回退上一条（用户实测）；修复后重启恢复至用户所在条目（已标记条目标记可见、不自动重播——结果已知等用户操作；未标记瞬时失败条目可自动重试），不回退上一条；确定性跳过推进后实际在播条目随成功起播持久化（既有 :1049 机制保留）。

**旧声停播**：手动切换取流失败时，旧播放器若仍在出声 MUST 显式停止——现状 playIndex 切换只改标志（setPlaying(false) 只写布尔值不调 player.pause()），旧 AVPlayer 要到新流 open 成功才整体重建释放（setStreamSource→recreatePlayer），404 死在取流阶段到不了重建点，旧声音继续放而界面已是新条目+「播放失败」、锁屏媒体信息也是旧的（声音/界面/锁屏三层错位）；修复后失败即停声，杜绝错位。

**Why this priority**: 状态不一致是用户实测报告的现行 bug 群（播放按钮状态错误、重启回退、切换失败旧声残留）；瞬时失败的人工重试语义依赖「按钮态正确 + 停留位置正确 + 声音状态正确」三个前提；密集自动重试升级风控（BILI_NOTES 实验 8）要求不自动重试。

**Independent Test**: 弱网/风控环境下播放失败，观察：播放键回正确状态、toast 分型文案、状态栏无原始错误码、条目无标记、队列未推进；正在播放 A 时手动切换到队尾失效条目 B，观察 A 声音立即停止、B 标 X、重启后恢复至 B（不回退）。

**Acceptance Scenarios**:

1. **Given** 取流遇网络失败，**When** 播放失败，**Then** toast「网络异常，请检查网络后重试」+ 播放键回正确状态 + 停在当前条目
2. **Given** 取流遇风控拦截（-412/-352 类），**When** 播放失败，**Then** toast「请求被拦截，请稍后重试」+ 不自动重试
3. **Given** 失败后用户手动点播放键，**When** 重试取流，**Then** 正常重试当前条目（网络恢复后可成功）
4. **Given** 瞬时失败，**When** 查看队列条目，**Then** 无 X、无异常标记、无跳过、无失效语义
5. **Given** 手动切换到失效条目触发跳过且下一条成功起播，**When** 重启应用，**Then** 恢复至下一条（实际在播条目），不回退到失效条目之前的条目
6. **Given** 任意播放失败路径，**When** 观察播放按钮，**Then** 按钮状态与实际播放状态一致（不出现卡暂停态/播放态假象）
7. **Given** 正在播放 A 时手动切换到失效条目 B，**When** B 取流 404，**Then** A 的声音立即停止；若 B 跳转到 C 成功则播 C，若 B 在队尾无法跳过则静默停在 B（标记可见）
8. **Given** 队尾确定性失败（无下一条可跳），**When** 失败发生，**Then** 失败条目持久化为当前条目；重启应用恢复至该条目，不回退上一条
9. **Given** 重启自动续播开启，**When** 恢复目标为已标记（X/异常）条目，**Then** 不自动重播（结果已知，等用户操作）

### User Story 5 - 添加失效 BV：分型提示不入队 (Priority: P2)

单视频添加（BV 输入）与分享解析入口撞失效视频：提示「视频不存在或已失效」，不加入队列（区分于通用「解析失败」提示，不再外露原始错误串）。

**Why this priority**: 现状报「解析失败: Bili API error -404」原始串，用户无法理解；入口拦截在入队前，比入队后再跳过更早止损。

**Independent Test**: 添加一个已删除的 BV 号，观察分型提示且队列未新增条目。

**Acceptance Scenarios**:

1. **Given** 单视频添加入口，**When** 输入已删除的 BV，**Then** 提示「视频不存在或已失效」，不入队
2. **Given** 分享/剪贴板解析入口，**When** 解析到失效 BV，**Then** 同样分型提示，不入队

---

### Edge Cases

- 连续失效/异常条目出现在队列：逐个跳过自动连播，toast 沿用既有去重窗（PLAYBACK_ERROR_DEDUP_MS）防刷屏，队列线性推进到队尾正常结束
- 整个队列均为确定性失败条目：逐个跳过至队尾后停止（线性推进，无循环风险）；失败路径逐条持久化，重启恢复至队尾失败条目（已标记、不自动重播）
- 队尾确定性失败条目（无法跳过）：失败条目持久化为当前条目，重启恢复至它（标记可见、不自动重播），不回退上一条
- 中间失败后跳到下一条成功：失败路径先写失败条目，下一条成功起播 ：1049 覆盖写——最终持久化状态正确，中间写盘无害
- 瞬时失败后重启：恢复至失败的当前条目（失败路径已持久化），自动续播开启时可自动重试；人工点播重试亦可
- 手动切换撞瞬时失败：旧声停止、停在新条目等人工重试（旧声停播与瞬时失败停留语义叠加）
- 异常标记两路判定点互斥：-104 死在取流（流未取得）、时长异常死在 prepared（流已取得比时长），同一视频同一时刻只落一路
- 异常标记的转变：先 -104 标记后视频转免费/用户开通大会员 → 重播成功自动摘；先时长判定标记后获得完整流（如充电）→ 重播自动摘
- 失效判定优先：曾标异常标记的视频后被删除（重播 -404）→ 标 X、摘异常标记（取流结果是最新事实）
- 渲染优先级：同一 bvid 同时命中 X 与异常标记时（防御性），X 优先显示
- 存量迁移：既有 anomalySet 条目（全部为 v0.5-part5 时长判定）整体转为异常标记语义，零数据迁移，视觉由 X 变更为异常标记形态
- 风控页伪装响应（非 JSON/空体）与 HTTP 异常：不算失效，走瞬时失败路径（宁可漏判不误判）
- 多P 视频：X 与异常标记均以 bvid 为粒度（视频级标记）
- 失效视频不可恢复（bvid 不复用），无需设计恢复路径
- 确定性跳过发生在出声前，被跳过条目不产生播放历史（既有机制天然覆盖）
- 视频元数据时长缺失（duration=0/未知）：跳过时长检测照常播放（v0.5-part5 既有边界保留）
- 原因说明分层：时长异常 toast 只报观测事实（音源异常），不说明是充电视频——本地推断无法百分百确认；失效（-404）与大会员专限（-104）toast 可说明原因——官方接口明确识别

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 取流阶段失败 MUST 按错误码分类：view/playurl 回 -404 判「失效」；playurl 回 -104 判「异常（大会员专限）」；其余（网络/风控/未知）判「瞬时失败」
- **FR-002**: 失效视频 MUST 标 X（独立持久化标记，视觉沿用带圈 X）+ toast「视频已失效，已跳过」+ 自动连播下一首；条目保留队列，纳入「清除已播」清理口径
- **FR-003**: 大会员专限视频 MUST 标异常标记 + toast「需要大会员，已跳过」（官方接口明确识别，可直报原因）+ 自动连播下一首
- **FR-004**: 时长异常视频（流时长 < 元数据 × 0.5）MUST 标异常标记 + toast「音源异常，已跳过」（报可观测事实，MUST NOT 说明是充电视频——本地推断无法百分百确认）+ 自动连播下一首（开关废止，无条件执行）
- **FR-005**: 异常标记 MUST 统一定义：两路判定（-104 官方识别 / 流时长 < 元数据 × 0.5 本地推断）写入同一 per-bvid 持久化标记集；与 X 同位置显示（队列条目/历史/源页剧集行）；视觉定稿：`sys.symbol.exclamationmark_circle` 感叹号 + 新增 `app.color.warning_amber` 警示橙（区别于 X 的 danger_red 红叉），MUST NOT 区分大会员/时长异常两路原因呈现（原因信息由 toast 分层承载——视觉区分等于常驻暗示充电嫌疑稿，违背「不说明是充电视频」定稿）；纳入「清除已播」清理口径（可清计数、确认弹窗、实际移除三处一致）；成功播放完整内容 MUST 自动摘除（开通大会员重播 / 获得完整流两条恢复路径共用此摘除）
- **FR-006**: 取消「异常源处理」设置项：设置页移除该行；「照常播放」分支与 TOAST_ANOMALY_TRIAL 移除；KEY_ANOMALY_SKIP 存量存储值不再读取，行为统一为跳过
- **FR-007**: 瞬时失败 MUST NOT 跳过、MUST NOT 标任何标记、MUST NOT 自动重试；toast 按网络类/风控类分型；停在当前条目等人工重试
- **FR-008**: playIndex 失败路径 MUST 复位播放意图态（playIntent），播放/暂停图标与实际状态一致（用户实测：播放按钮不会切换至暂停态；机理对照：onError 路径复位而 catch 不复位）；人工点播放即重试当前条目
- **FR-009**: 添加入口（单 BV 输入/分享解析）撞失效视频 MUST 提示「视频不存在或已失效」且不入队；MUST NOT 外露原始错误串
- **FR-010**: 连续跳过的 toast MUST 按既有去重窗去重，不刷屏
- **FR-011**: 失效判定 MUST 只认明确错误码 -404；风控页/空响应/HTTP 异常不算失效
- **FR-012**: 对用户的失败描述 MUST 分型展示，MUST NOT 把 `Bili API error -xxx` 原始串直接展示给用户
- **FR-013**: 存量迁移：既有 anomalySet 条目（全部为 v0.5-part5 时长判定）MUST 整体转为异常标记语义（零数据迁移），其显示视觉变更为异常标记形态；物理存储映射（既有集改语义 vs 数据搬迁）plan 轮决策
- **FR-014**: 持久化一致性：playIndex 失败路径 MUST 持久化当前失败条目为当前条目（含队尾确定性失败无法跳过的场景——用户拍板：队尾无下一条可跳时持久化也必须解决）；重启恢复至用户所在条目，MUST NOT 回退到失败条目之前（用户实测：手动切换到异常条目后重启回到上一条；机理：savePlaylistFile 仅成功路径写盘 :1049）；恢复后已标记（X/异常）条目 MUST NOT 自动重播（结果已知），未标记瞬时失败条目可自动重试；确定性跳过推进后实际在播条目随成功起播持久化（既有 :1049 机制保留）
- **FR-015**: 旧声停播：手动切换取流失败时，旧播放器若仍在出声 MUST 显式停止并同步媒体会话状态——MUST NOT 出现「声音是旧条目、界面是新条目（播放失败）」的错位（现状机理：playIndex 的 setPlaying(false) 只改标志不调 player.pause()，旧 AVPlayer 到新流 open 成功才重建释放，404 死在取流到不了重建点）

### Key Entities

- **X（无法获取）**: per-bvid 持久化标记，经 -404 判定，语义=「视频不存在，重试无意义」；不可恢复；视觉沿用带圈 X；失效视频到不了 prepared，与时长判定天然无交集
- **异常标记（新，无法获取完整）**: per-bvid 持久化标记，两路判定写入同一标记集——大会员专限（playurl -104，官方接口明确识别，toast 直报「需要大会员」）/ 时长异常（流时长 < 元数据 × 0.5，仅靠本地判断、无法百分百确认为充电视频，toast 只报观测「音源异常」、不说明是充电视频）；语义=「视频存在但未获完整流」；可恢复（成功播放完整内容自动摘除）；视觉：exclamationmark_circle 感叹号 + warning_amber 警示橙（区别于 X 的红叉），不区分两路原因
- **取流失败分类**: 三类——失效（-404，确定性、不可恢复）/ 异常（-104 或时长异常，确定性、可恢复）/ 瞬时失败（风控/网络/未知，可重试）
- **「异常源处理」设置（废止）**: 原枚举（跳过/照常播放）废止，行为统一为跳过；存量存储值不迁移不读取

## Success Criteria *(mandatory)*

- **SC-006**: 正常视频全流程零误标（大样本连播无 X/异常标记出现）
