# Feature Specification: 播放页重新设计（参考 PiliPlus 听音频页布局）

**Created**: 2026-10-04  
**Status**: Draft  
**Input**: User description: "参考 PiliPlus 项目的听视频播放器布局，给 app 重新设计播放页" + 补充约束："尽可能保留鸿蒙特色" + 多轮逐项确认的设计决策。

## Overview

重新设计 BiliRadio 的全屏播放页（PlayerOverlay）：布局结构参考 PiliPlus「听音频」独立播放页的沉浸式信息流布局（居中封面 → 标题/UP主信息 → 细进度条 → 时间行 → 控制栏），同时最大程度保留鸿蒙 ArkUI 原生特色（SymbolGlyph 图标、bindSheet 半模态、毛玻璃质感、下拉手势关闭、深浅色自适应资源）与现有播放页的动效（呼吸光晕、按压缩放动画）。

控制栏为传输五键 `[上一首][◀◀15s][播放/暂停][15s▶▶][下一首]`（微调固定 15 秒，不做步长配置）；倍速、播放模式、定时关闭以按钮形式置于控制栏下方的底部操作行（沿用现有选择面板），队列入口同在此行；顶栏仅剩收起按钮；详情入口为标题行最右侧小箭头；原视频按钮位于封面右下角。取消收藏入口、点赞/投币/收藏等互动按钮是否加入及位置、历史记录云同步，均留待后续轮次再议。本次为 UI 层重组加少量播放辅助方法，不改动既有服务层接口语义。

**最终布局蓝图**：

```
顶栏：  [▼收起]
信息区：  16:9 封面（呼吸光晕，居中）+ 封面右下角原视频按钮
        标题行：标题（≤2行）+ 最右侧小箭头（→详情Sheet）
        UP头像+名称 · 序号 n/total
        播放量 · 发布时间
进度区：  ——— 细进度条 ———
时间行：  当前时间                    总时长
控制栏：  [上一首] [◀◀15s] [播放/暂停] [15s▶▶] [下一首]
底部操作行：[倍速 1.25x] [播放模式] [定时] [☰队列]
```

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 沉浸式信息区布局（Priority: P1）

用户打开播放页后，看到居中展示的 16:9 封面（保留呼吸光晕与按压缩放动画，封面右下角为原视频跳转按钮），封面下方依次是：标题行（标题最多2行，行最右侧为小箭头详情入口）、UP主头像+名称+当前序号（n / total）、播放量与发布时间统计行。整页形成"听音频"式的沉浸浏览体验，替代现有的左对齐堆叠布局。

**Why this priority**: 布局重组是本次改版的核心目标与用户感知最强的变化，其他故事均依附于此布局骨架。

**Independent Test**: 播放任意曲目并打开播放页，即可看到新的信息流布局；即使后续故事未实现，页面仍可正常展示曲目信息。

**Acceptance Scenarios**:

1. **Given** 正在播放曲目，**When** 用户打开播放页，**Then** 显示居中16:9封面（带光晕呼吸动画与右下角原视频按钮）+ 标题行（含右侧小箭头）+ UP主行 + 统计行，且暂停/播放时光晕与封面缩放状态正确切换
2. **Given** 曲目无封面，**When** 打开播放页，**Then** 封面区显示现有的音符占位样式，布局不塌陷
3. **Given** 开启省流模式，**When** 打开播放页，**Then** 封面/头像按现有省流规则隐藏或占位
4. **Given** 点击标题行最右侧小箭头，**When** 箭头被点击，**Then** 打开曲目详情半模态（现有详情内容保留）
5. **Given** 点击封面右下角原视频按钮，**When** 按钮被点击，**Then** 按现有逻辑拉起浏览器打开 B 站原视频页

---

### User Story 2 - 细进度条与时间行重构（Priority: P2）

进度条改为参考样式的细条样式（视觉高度约 5vp、小圆点滑块直径约 12vp），当前时间与总时长从进度条两侧移到进度条下方、左右分列两端的独立时间行。拖拽进度的防回弹交互保持不变。

**Why this priority**: 进度控制是音频播放最高频操作，与控制栏同属核心操作区。

**Independent Test**: 播放中拖动进度条并松手，验证 seek 生效、时间行实时刷新、拖拽中不回弹。

**Acceptance Scenarios**:

1. **Given** 正在播放，**When** 用户拖动进度条，**Then** 滑块跟随手指且进度不回弹，时间行左侧显示拖拽中的时间
2. **Given** 拖动结束松手，**When** 播放器完成 seek，**Then** 播放从新位置继续，时间行与进度条同步
3. **Given** 曲目未加载完成（isPreparing），**When** 用户查看进度区，**Then** 显示加载指示且进度条不可用或显示占位

---

### User Story 3 - 传输五键控制栏（Priority: P2）

主控制区重组为传输五键控制栏，从左到右：上一首 | 后退15s | 播放/暂停（主按钮）| 前进15s | 下一首。上一首/播放/下一首保持经典传输簇相邻关系；±15s 微调键紧邻播放键（播客类 app 主流排布）；播放/暂停按钮保留现有按压动画，主次层级分明（播放键最大，其余四键次之）。

**Why this priority**: 控制栏是播放页操作中枢，与进度区共同构成核心操作区；传输簇完整性是误触率与肌肉记忆的关键。

**Independent Test**: 依次点击五个按钮，验证各自功能（切上一首、后退15s、播放/暂停、前进15s、切下一首）均正常。

**Acceptance Scenarios**:

1. **Given** 正在播放，**When** 点击播放/暂停主按钮，**Then** 播放状态切换且按钮图标同步（播放▶/暂停⏸）
2. **Given** 播放列表有多首曲目，**When** 点击上一首/下一首，**Then** 按现有播放顺序逻辑切换曲目
3. **Given** 任意状态，**When** 点击后退/前进 15s 键，**Then** 执行 User Story 7 的进度微调
4. **Given** 曲目未加载完成，**When** 点击切歌键，**Then** 遵循现有 isPreparing 下的切歌逻辑，不产生错误

---

### User Story 7 - 进度微调按钮（固定 ±15s）（Priority: P2）

控制栏播放键两侧提供"后退/前进"微调按钮：单击固定跳转 15 秒；快速连按可叠加累计跳转；跳转结果钳制在 [0, 总时长] 范围内。步长固定 15 秒，不做配置。曲目未加载完成时按钮禁用。

**Why this priority**: 纯听场景（讲座/播客类长音频）缺少画面拖拽定位，±15s 微调是刚需补充，与控制栏同属核心操作。

**Independent Test**: 播放中单击前进/后退按钮验证跳转 15 秒；连按验证叠加；边界验证钳制。

**Acceptance Scenarios**:

1. **Given** 正在播放，**When** 单击前进键，**Then** 播放位置前进 15 秒，进度条与时间行同步刷新
2. **Given** 正在播放，**When** 快速连按后退键 2 次，**Then** 累计后退 30 秒，不因频繁 seek 产生播放异常
3. **Given** 播放位置距结尾不足 15 秒，**When** 点击前进键，**Then** 位置钳制到结尾前，不越界
4. **Given** 曲目未加载完成（isPreparing），**When** 点击后退/前进键，**Then** 按钮无响应或置灰，不产生错误

---

### User Story 4 - 底部操作行（倍速/模式/定时/队列）（Priority: P3）

控制栏下方设底部操作行，从左到右四个按钮：**倍速**（显示当前值如 `1.25x`，点击弹出现有六档倍速选择）、**播放模式**（显示当前模式图标，点击弹出现有四模式选择：顺序/随机/单曲循环/倒序）、**定时**（显示未开启/剩余倒计时，点击弹出现有定时面板：15/30/60 分钟预设 + 自定义选择器）、**队列**（点击打开现有队列面板）。各选择面板沿用现有实现与持久化逻辑，仅入口位置从原次控制行迁至底部操作行。

**Why this priority**: 功能入口收纳是布局简化的一部分，但依赖控制栏（User Story 3）先落地。

**Independent Test**: 依次点击四个按钮，验证倍速/模式/定时/队列的选择面板打开，且选择后实际生效与持久化一致。

**Acceptance Scenarios**:

1. **Given** 点击倍速按钮，**Then** 弹出现有六档倍速选择（0.5/0.75/1.0/1.25/1.5/2.0）；选择后按钮显示值更新、倍速生效并持久化
2. **Given** 点击播放模式按钮，**Then** 弹出现有四模式选择；选择后按钮图标更新、模式生效并持久化；随机模式下上一首/下一首仍遵循现有历史栈逻辑
3. **Given** 点击定时按钮，**Then** 弹出现有定时面板（预设+自定义）；启动后按钮处显示剩余倒计时；到点暂停与提醒行为与现有一致
4. **Given** 点击队列按钮，**Then** 打开现有队列面板且当前曲目高亮
5. **Given** 任意选择面板打开，**When** 点击面板外区域，**Then** 面板正常关闭，播放不受影响

---

### User Story 5 - 顶栏精简与入口重排（Priority: P3）

顶栏精简为仅左侧"收起"按钮（无标题文字、无功能图标）。原次控制行（倍速/播放顺序/取消收藏/定时）移除，其中倍速/播放顺序/定时迁入底部操作行（User Story 4）。原视频按钮位于封面右下角（User Story 1）；详情由标题行最右侧小箭头打开。**取消收藏功能本轮不设入口**；点赞/投币/收藏等互动按钮是否加入及位置留待后续轮次再议。

**Why this priority**: 顶栏收纳与入口重排共同完成"功能不减少、入口更简洁"的目标，依赖新布局骨架。

**Independent Test**: 通过底部操作行打开倍速/模式/定时/队列；通过标题行小箭头打开详情；通过封面右下角按钮跳转原视频，验证功能可达。

**Acceptance Scenarios**:

1. **Given** 任意状态，**When** 查看顶栏，**Then** 仅显示收起按钮，无标题文字、无功能图标、无平铺次控制行残留
2. **Given** 点击标题行最右侧小箭头，**Then** 打开现有详情半模态（标题/播放数/发布时间/bvid/简介）
3. **Given** 点击封面右下角原视频按钮，**Then** 按现有逻辑拉起浏览器打开 B 站原视频页
4. **Given** 任意状态，**When** 浏览整页，**Then** 播放页内无取消收藏入口

---

### User Story 6 - 鸿蒙特色与既有体验保留（Priority: P1）

改版过程中必须保留的鸿蒙原生特性与既有体验：下拉手势关闭播放页（内容在顶部时）、SymbolGlyph 系统图标、bindSheet 半模态、毛玻璃按钮质感、深浅色双份颜色资源自动适配、状态提示文案（statusMsg）、加载指示（LoadingProgress）、空态引导页、后台播放与媒体通知不受影响。

**Why this priority**: "尽可能保留鸿蒙特色"是用户明示的核心约束，与布局重组同级，贯穿所有故事。

**Independent Test**: 深色/浅色模式分别打开播放页并执行下拉关闭、播放、打开弹窗等操作，验证视觉与交互正常。

**Acceptance Scenarios**:

1. **Given** 播放页内容滚动在顶部，**When** 用户下拉超过阈值，**Then** 播放页关闭（现有手势逻辑）
2. **Given** 系统切换深色/浅色模式，**When** 打开播放页，**Then** 全部颜色、毛玻璃、图标按现有深浅色资源正确渲染
3. **Given** 播放页打开且开始播放，**When** 退到后台/锁屏，**Then** 后台播放与媒体控制通知行为与改版前一致
4. **Given** 播放列表为空，**When** 打开播放页，**Then** 显示现有空态引导（BiliRadio/未在播放）

---

### Edge Cases

- 曲目无封面 / 无 UP 头像：沿用现有占位样式（音符占位、首字头像），布局不塌陷。
- 超长标题：最多 2 行并截断，详情半模态可看全文（现有行为）。
- 小屏 / 大字号：信息区可滚动（保留 Scroll），控制栏与进度条不被遮挡。
- isPreparing 加载中：显示加载指示，控制操作遵循现有 playWhenReady 逻辑；微调与切歌键禁用。
- ±15s 连按叠加：连续快速点击需合并/节流 seek，避免 seek 风暴；结果钳制在 [0, 总时长]。
- 定时关闭激活中切歌：剩余时间显示与到点暂停逻辑不受布局改版影响（沿用 SleepTimerController）。
- 播放列表仅 1 首：上一首/下一首行为遵循现有 PlayMode 逻辑，不因布局改变。
- 队列面板复用：QueueDrawer/QueueSheet 作为既有组件直接复用，不改其内部功能。
- 详情半模态打开状态下切歌：详情信息需跟随当前曲目刷新或关闭重开（实现择一，不显示错位旧数据）。
- 原视频跳转失败（无浏览器/网络异常）：沿用现有错误处理与提示，不影响播放。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 播放页布局 MUST 重组为自上而下的结构：顶栏（仅收起按钮）→ 居中信息区（16:9封面+光晕+右下角原视频按钮、标题行+详情箭头、UP主行、统计行）→ 细进度条 → 时间行 → 传输五键控制栏 → 底部操作行（倍速/模式/定时/队列）→ 底部安全边距。
- **FR-002**: 封面 MUST 保持 16:9 比例居中展示，并保留呼吸光晕动画与播放/暂停的缩放状态切换。
- **FR-003**: 信息区 MUST 展示：标题行（标题≤2行 + 行最右侧小箭头详情入口）、UP主头像+名称、当前序号 n/total、播放量与发布时间统计行；无数据时 MUST 使用现有占位样式。
- **FR-004**: 进度条 MUST 为细条样式（视觉轨道高度约 5vp、圆形滑块直径约 12vp），时间 MUST 分列于进度条下方左右两端；拖拽 seek 的防回弹逻辑 MUST 保持。
- **FR-005**: 主控制栏 MUST 为传输五键：上一首 | 后退15s | 播放/暂停（主，保留按压动画）| 前进15s | 下一首；上一首/播放/下一首 MUST 保持相邻的传输簇关系。
- **FR-006**: 底部操作行 MUST 包含四个按钮：倍速（显示当前值，弹出现有六档选择）、播放模式（显示当前模式，弹出现有四模式选择）、定时（显示未开启/剩余倒计时，弹出现有定时面板）、队列（打开现有队列面板）；选择 MUST 即时生效并沿用现有持久化。
- **FR-007**: 顶栏 MUST 仅包含收起按钮，无标题文字与功能图标。
- **FR-008**: 详情半模态 MUST 保留现有详情内容（标题/播放数/发布时间/bvid/简介滚动），由标题行最右侧小箭头打开；原视频按钮 MUST 位于封面右下角，按现有逻辑跳转 B 站原视频；取消收藏入口本轮 MUST NOT 出现在播放页（功能留待后续轮次，服务层能力保留不动）。
- **FR-009**: 改版 MUST 保留鸿蒙特色与既有交互：下拉关闭手势、SymbolGlyph 图标、bindSheet、毛玻璃质感、深浅色资源适配、状态提示、加载指示、空态引导。
- **FR-010**: 现有播放能力 MUST 全部不回退：播放/暂停/seek/±15s微调/倍速/播放模式/定时关闭/队列管理/详情/原视频/后台播放/媒体会话/启动恢复/流量保护等行为与改版前一致。唯一例外：取消收藏的播放页入口按用户决策本轮移除（服务层 unfavorite 能力保留，后续轮次回归）。
- **FR-011**: 播放服务层（PlayerController/AudioPlayer/MediaSession/SleepTimerController/BiliService）MUST NOT 改变既有接口语义；MAY 新增进度微调（seekBy 偏移量）所需的辅助方法。
- **FR-012**: 队列面板 MUST 继续复用现有 QueueDrawer/QueueSheet 组件，不在本次改版范围内修改其内部功能。
- **FR-013**: 进度微调 MUST 支持单击固定跳转 15 秒、快速连按叠加（合并/节流 seek）、结果钳制在 [0, 总时长]；步长固定 15 秒不可配置；曲目未加载完成时微调键 MUST 禁用。

### Key Entities *(include if feature involves data)*

本次为 UI 重组，不新增数据实体；复用既有实体：

- **BiliVideo**（曲目）: 提供封面、标题、UP主信息、播放量（view）、发布时间（pubdate）等展示字段。
- **PlayerController 状态快照**（isPlaying/isPrepared/currentTime/duration/playMode/playbackRate/trackIndex/playlistCount 等）: 播放页各区域的唯一数据来源（canUnfavorite 本轮无 UI 入口消费，状态保留）。
- **SleepTimerController 状态**（sleepTimerActive/sleepTimerRemaining）: 底部操作行定时按钮的展示来源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 打开播放页后 1 秒内完整呈现新布局（封面、信息区、进度条、控制栏一次到位，无错位闪烁）。
- **SC-002**: 除取消收藏（用户决策本轮移除入口）外，改版前列出的全部播放功能（播放控制、seek、±15s微调、倍速、播放模式、定时、队列、详情、原视频、后台播放）在新布局下 100% 可用，零功能回退。
- **SC-003**: 高频操作（播放/暂停、上下切歌、±15s微调、拖进度）均可在 1 次点击/拖拽内完成；次高频（倍速/模式/定时/队列/详情）不超过 2 次点击。
