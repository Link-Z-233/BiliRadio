# Feature Specification: B站链接识别与短链解析修复（KI-4 闭环）

**Created**: 2026-10-07  
**Status**: Draft  
**Input**: 用户需求：添加订阅输入框在所有判断前去除非链接内容（抽取 B 站链接）；经实测确认信息后扩大范围——本轮直接完成 PROJECT_NOTES.md KI-4 全部六条修复。

## Overview

「添加订阅」输入框目前无法处理 B 站客户端分享文案（标题与短链混排），且短链解析存在 KI-4 登记的六项缺陷。本轮在识别链路最前置环节增加「B 站链接抽取」，重写短链解析为「禁止跟随重定向、直读 Location」的正确实现，补齐解析目标的类型覆盖（含移动端形态），使「粘贴分享文案 → 自动到达正确目标」全程无需手工删改。完成后 KI-4 备忘录条目闭环。

**实测依据（2026-10-07，两条真实分享短链）**：

- b23.tv 短链以 302 + 绝对 Location 响应（视频 → `www.bilibili.com/video/BV…`；UP 空间 → **`m.bilibili.com/space/{uid}?…` 移动端形态**），不依赖正文；
- HarmonyOS `http.request` 默认自动跟随重定向，故现实现拿到的是落地页正文——这正是「误取随机视频 BV 号」风险的根源；修复采用禁跟随 + 直读 Location；
- 空间短链的 Location 为移动端形态，现有识别器不认该形态——目标覆盖必须补齐，否则空间分享文案修完仍不通。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 分享文案直达视频 (Priority: P1)

用户从 B 站客户端复制形如「【标题】 https://b23.tv/BV…」的视频分享文案，整段粘贴进「添加订阅」输入框并提交。

**Why this priority**: 分享文案是最高频的输入形态；视频是短链最主要的目标类型。

**Independent Test**: 粘贴用户提供的真实视频分享文案，预期不经任何手工删改直接开始播放对应视频。

**Acceptance Scenarios**:

1. **Given** 含 b23.tv 短链且路径带视频号的分享文案, **When** 提交, **Then** 抽取出的链接路径被识别出视频号，跳过网络解析直接播放该视频
2. **Given** 含 b23.tv 短链但路径不带视频号的分享文案, **When** 提交, **Then** 经短链解析取得视频页地址后播放对应视频

---

### User Story 2 - 分享文案直达 UP 订阅视图 (Priority: P1)

用户粘贴形如「【XX的个人空间-哔哩哔哩】 https://b23.tv/…」的 UP 空间分享文案并提交。

**Why this priority**: 用户提供的第二个真实场景；同时依赖 Location 读取与移动端空间地址识别，是本轮正确性的最关键验证点。

**Independent Test**: 粘贴用户提供的真实空间分享文案，预期进入该 UP 的详情订阅视图。

**Acceptance Scenarios**:

1. **Given** UP 空间分享文案, **When** 提交, **Then** 解析得到移动端空间地址并被识别为 UP 目标，进入该 UP 的详情订阅视图
2. **Given** 该 UP 已被订阅, **When** 提交, **Then** 行为与现状直接输入 UID 一致（进入详情视图，重复订阅仍被既有逻辑拦截）

---

### User Story 3 - 解析健壮性与可读失败 (Priority: P2)

覆盖 KI-4 #1/#3/#4/#6：大小写变体与双短链域名的判定、裸域名补前缀、多跳/相对 Location、错误分型提示、会话级缓存与专用超时。

**Why this priority**: 保证解析主链路在边界条件下不静默降级、不重复消耗网络。

**Independent Test**: 构造大小写变体/裸域名/重复提交等输入，观察请求日志与提示文案。

**Acceptance Scenarios**:

1. **Given** 大写域名（如 B23.TV）或 bili2233.cn 域名的短链文本, **When** 提交, **Then** 均进入短链解析，不再漏判
2. **Given** 无协议前缀的裸短链（如 `b23.tv/xxxx`）, **When** 提交, **Then** 自动补 https 前缀后正常解析
3. **Given** 同一短链在会话内第二次提交, **Then** 命中缓存，不再产生解析网络请求
4. **Given** 解析失败, **Then** 按网络失败/超出跳数/无有效目标/目标无法识别分别提示具体原因，而非统一「短链解析失败」

---

### User Story 4 - 目标类型覆盖扩展 (Priority: P2)

覆盖 KI-4 #5：短链解析结果与用户直接输入的收藏夹、合集、系列、av 号（URL 形态）目标都能正确分发到对应订阅/播放流程。

**Why this priority**: 「解析得到目标」与「识别目标类型」缺一不可；空间目标已由 US2 覆盖，本故事补齐其余类型。

**Independent Test**: 逐类粘贴目标 URL，确认分别进入对应订阅/播放分支。

**Acceptance Scenarios**:

1. **Given** 视频页的 av 号形态地址（如 `www.bilibili.com/video/av…`）, **When** 提交, **Then** 归一化为 BV 后播放对应视频
2. **Given** 收藏夹/合集/系列地址（含移动端形态）, **When** 提交, **Then** 进入对应的订阅流程，与现状桌面形态地址行为一致

---

### User Story 5 - 既有输入零回归 (Priority: P3)

所有既有直接输入形态行为不变；无 B 站链接的文本回退现状提示。

**Why this priority**: 防止抽取与清洗环节引入回归；保护既有七类输入的稳定行为。

**Independent Test**: 按回归清单逐项输入并与现版本行为比对。

**Acceptance Scenarios**:

1. **Given** BV 号 / 裸 av 号 / 纯数字 UID / 既有五类完整 URL, **When** 提交, **Then** 行为与现版本一致
2. **Given** 不含 B 站链接的任意文本, **When** 提交, **Then** 提示未识别（与现状一致），且不发起任何网络请求

---

### Edge Cases

- 分享文案中 URL 尾随中文标点（句号/感叹号/右括号等）→ 抽取时清除；
- 文本含多个 B 站链接 → 取第一个；
- Location 为相对地址 → 按短链域名补全为绝对地址后再跟进；
- 重定向链超过最大跳数（默认 3）→ 判定失败并按「超出跳数」提示；
- 短链响应非 302/无 Location → 走正文兜底解析，且兜底不得从非视频目标页面误取视频号（防误播）；
- 解析成功后输入框保留用户原文，不回写解析结果；
- 首尾带空格的输入（如 `" 123 "`）→ 经统一清洗后正常识别为 UID（顺带修复现非短链分支不 trim 的失配）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 链接前置抽取**: 系统必须在任何识别判断之前，从输入文本中抽取第一个 B 站域名（b23.tv、bili2233.cn、bilibili.com 及其子域名，忽略大小写，须带 http(s) 前缀）的链接，并清除尾随标点；未抽到时回退原始去空格文本；后续全部识别分支统一使用该清洗结果。
- **FR-002 短链判定**: 清洗结果为 b23.tv / bili2233.cn 域名（忽略大小写）的链接时进入短链解析；无协议前缀的裸短链域名自动补 https:// 后处理。
- **FR-003 Location 解析**: 短链请求必须禁止自动跟随重定向，读取响应 Location（支持绝对与相对地址），迭代跟进至非短链目标或达到最大跳数（默认 3）；最终目标须为 B 站域名，否则判定为无有效目标。
- **FR-004 视频号短路**: 短链路径本身含视频号时，跳过网络解析直接按视频目标处理。
- **FR-005 错误分型**: 解析失败必须至少区分网络失败、超出跳数、无有效目标、目标无法识别四类，并向用户展示对应可读原因。
- **FR-006 会话级缓存**: 同一短链的解析结果在应用会话内缓存（容量上限默认 50 条、LRU 淘汰），命中时不再发起网络请求。
- **FR-007 专用超时**: 短链解析使用独立超时参数，短于通用网络请求超时（具体值在方案阶段确定）。
- **FR-008 目标覆盖**: 识别器必须支持视频（BV 号与 av 号 URL 形态）、UP 空间（桌面形态与移动端形态）、收藏夹、合集、系列目标（含移动端形态）。
- **FR-009 兜底防误路由**: 无 Location 时的正文兜底解析不得从非视频目标页面误取视频号。
- **FR-010 输入保持**: 短链解析成功后不回写/覆盖输入框内容。
- **FR-011 备忘录闭环**: 验证通过后更新 PROJECT_NOTES.md 的 KI-4 条目为已修复（含登记行号漂移修正），本轮未纳入的新发现问题（系列默认类型歧义、BV 优先级遮蔽、fav 弱启发式、裸数字语义、动态/直播目标等）另行登记。

### Key Entities

- **短链解析结果**: 目标地址 + 结局（成功 / 网络失败 / 超出跳数 / 无有效目标 / 目标不识别），承载可读的失败原因。
- **解析缓存**: 短链 → 解析结果的会话级映射，有限容量、LRU 淘汰、不持久化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户提供的两条真实分享文案（视频/空间）粘贴即达正确目标（播放 / UP 订阅视图），无需手工删改，实机首次成功率 100%。
- **SC-002**: 同一短链会话内第二次提交产生零解析网络请求（日志可验证）。
- **SC-003**: 既有直接输入形态（BV / 裸 av / 纯数字 UID / 五类完整 URL）回归 100% 行为不变。
- **SC-004**: 各类解析失败均能展示具体原因，不再出现统一降级提示。

## Assumptions

- b23.tv / bili2233.cn 短链以 302 + Location 跳转（已实测两例均为绝对地址）；少数无 Location 场景走正文兜底。
- 解析缓存不持久化：短链目标长期稳定，应用重启后首次解析的代价可接受。
- 「添加订阅」输入框是本轮唯一改造入口；播放队列输入框（addByBv）不在本轮范围内。
- KI-4 登记行号已漂移（现为 AddSubscriptionSheet.ets L165 判定、BiliService.ets L935-966 resolveShortUrl），备忘录更新时一并修正。
- 收藏夹/合集/系列的短链 Location 形态暂无实测样本，覆盖按已知 URL 模式族设计。

## Open Questions

- 收藏夹/合集/系列短链的真实 Location 形态手中无样本（仅有视频与空间两条实测），按已知模式族设计、实机遇到再补，是否可接受？
- 缓存容量 50 条 / 最大跳数 3 / 独立超时取通用值一半，这三个默认值是否需要调整？
