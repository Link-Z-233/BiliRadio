## 4. 测试要点清单（供用户真机复测）

以下按 User Story 1-8 逐条列出「操作步骤 + 预期结果」，来自 `spec/v0.3-debt-cleanup/spec.md` 验收场景与 tasks.md 验证描述，叠加模拟器实测中发现的核对细节。复测时逐条打勾。

### US1 删除无图模式开关（4 条）

1. 打开设置页，查看「省流」分组 → **无「无图模式」开关行**
2. 任意页面查看封面渲染 → 缩略图、播放层大封面、系统播控封面均正常加载；Wi-Fi 大图档/非 Wi-Fi 省流档行为零回退
3. 代码检索 `KEY_DATA_SAVER`/`dataSaver`/「无图模式」→ 存储键、开关状态、生效分支、重发方法全部零残留
4. 老版本升级后启动 → 残留旧持久化值不被读取、无任何异常（不主动清理）

### US2 首页订阅列表左滑删除（4 条）

1. 首页订阅列表 ≥1 条，左滑任一行 → 右侧露出「删除」按钮，样式对齐播放历史删除按钮
2. 点击「删除」→ 该订阅退订（剧集缓存清理、持久化生效），列表即时移除该行
3. 左滑露出按钮后未点击，滚动列表或左滑其他行 → 滑动状态自然复位，无半开按钮残留
4. 首页既有交互（点击行进源页、新集徽标静默刷新）→ 行为零回归

### US3 链接识别修复（5 条）

1. 输入含 BV 参数的合集/收藏夹复合 URL → 识别为合集/收藏夹，不再误判为单视频
2. 输入纯 BV 号文本 → 仍识别为单视频（零回归）
3. 输入合法收藏夹 URL（网页版 `space.bilibili.com/{mid}/favlist?fid=`、移动端 `m.bilibili.com/space/{mid}/favlist`、播放页 `medialist/play`）→ 正确识别为收藏夹（收紧不得漏判）
4. 输入非收藏夹页面但文本含 fav/collection/favlist 字样 → 不再误判为收藏夹
5. 输入短链、av 号 URL、裸 UID → 分类结果与现状一致（零回归）

### US4 队列功能全量（7 条）

1. 播放页点队列按钮 → 底部弹出全宽面板（约 65% 屏高、顶部圆角），点遮罩或返回键滑出关闭；首页打开行为一致
2. 播放页封面高饱和时打开队列 → 条目文字清晰可读，无封面色穿透
3. 队列仅 1 条（未铺满）时按住列表向上/向下拖 → 分别露出「已经到顶了」/「已经到底了」，松手回弹消失
4. 条目 duration=0（合集/收藏夹入队未播过）→ 第二行只显示 UP 主名、无 00:00；已播过条目显示「UP主名 · mm:ss」
5. 队列 N≥2 条，左滑非播放中条目点删除 → 该条目消失、计数减一、播放不中断；长按多选与竖向连选手势不误触发
6. 清除已播三态：播放中部某条（前有已播）点魔棒清除 → 确认框「将移除当前条目之前的已播条目」→ 前缀移除、当前条目持续播放；当前条目播完未切时 → 确认框「将移除已播条目及已播完的当前条目」→ 连同移除且播放器保持暂停（队列减一、空态正确）；无可清条目时 → 仅 toast「没有可清除的已播内容」不弹框
7. 队列非空且播放条目 A 时，添加订阅面板输入单视频 B 提交 → B 追加队尾不打断、toast「已加入队列」；队列空时 → 直接播放 toast「开始播放」；重复提交 → toast「已在队列中」；输入框下方常驻「不打断」说明行（「支持分享文案、短链、BV 号、av 号、UP 主 UID」+「单视频将加入播放列表，不打断当前播放」）

## 5. 环境限制与遗留问题

1. **模拟器卡死**：T022/US7 即将开始时模拟器实例无响应，导致 US7/US8/T024/T025 无法继续。用户决策不再进行模拟器验证，改为真机实测。
2. **卡死前一次非崩溃回桌面事件**：US6 场景 4 验证时，点击坐标（640,2680）落入小白条热区触发系统 RecentExit 导航（非应用崩溃，日志无 jscrash/faultlog）；应用经 `devecocli run --skip-build` 重新拉起后恢复正常。**真机复测注意**：勿点击屏幕底部小白条区域。
3. **verify_ui 自动化不稳定**：US1/US4 均 3 次尝试用尽（[RETRY_LIMIT_EXCEEDED]），转 `devecocli ui` 手动验证后通过。已知坑：长 URL 输入截断（去 `https://` 前缀）、慢速按住触发长按多选、滚动 LazyForEach 列表 a11y bounds 不可靠（以 hilog 日志为 ground truth）、Toast 不在 a11y 树（用像素差分验证）。
