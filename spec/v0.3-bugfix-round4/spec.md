# Feature Specification: v0.3 真机反馈第四轮修复（清空队列闪现 / 胶囊退场时序 / 按压反馈重做 / 左滑等距）

**Created**: 2026-10-12  
**Status**: Draft  
**Input**: User R4 反馈四项（[turn_awwj6t] + [turn_1gpho3] 澄清：按压卡死为设置页全体行、设计级问题；左滑等距三处统一、左右等距方案）

## Overview

v0.3 第三轮修复后的真机反馈第四轮，四个视觉/交互 bug：①播放浮层内清空队列时，Index 层条件渲染二次挂载队列面板造成「突然出现一下然后无动画消失」的闪现；②从设置页返回时 MiniPlayer 胶囊压在设置页退场动画上层（R3 US3 修复无效——`onHidden` 实际在退场转场开始时即触发，与 R3 假设不符）；③设置页全体行的按压反馈（stateStyles pressed 背景加深）点击瞬间即卡死不消失，属按压反馈机制的设计级缺陷，需机制重做而非逐个修补；④三处左滑删除按钮停留位左右间距不对称（左侧 0 贴内容、右侧 16vp），统一改为左右等距。

## User Scenarios & Testing

### User Story 1 - 清空队列闪现修复（Priority: P1）

播放浮层内打开队列面板，点「清空」确认后：队列面板随播放浮层**一次性干净退出**，全程不在首页层闪现第二个队列面板实例、无瞬间卸载跳变。现状根因：`closeBothLayersNow()` 让队列走「滑出 + 260ms 延时卸载」、浮层立即收起；浮层卸载清掉队列实例的延时器但 `AS_SHOW_QUEUE_SHEET` 仍为 true，Index 层渲染条件（`showQueueSheet && !showPlayerOverlay`）瞬时满足，底部二次挂载新 QueueDrawer 滑入（闪现），随后被延时路径置 false 瞬间卸载（无动画消失）。

**Why this priority**: 破坏性操作（清空队列）的退出编排观感割裂，用户核心链路（听歌→管理队列→清空）必经。

**Independent Test**: 播放浮层内开队列→清空→确认→观察两层退出全程：无队列面板二次出现、无无动画跳变；浮层滑出转场完整。

**Acceptance Scenarios**:

1. **Given** 播放浮层 + 队列面板同开，**When** 清空队列并确认，**Then** 浮层滑出退出全程完整，队列面板不单独闪现、不无动画跳变
2. **Given** 首页直接打开队列面板（无浮层），**When** 清空并确认，**Then** 保持现状：面板滑出动画关闭（无回归）
3. **Given** 清空确认后，**When** 回到首页，**Then** 无残留队列状态（`AS_SHOW_QUEUE_SHEET` 复位 false，再点胶囊/队列按钮行为正常）
4. **Given** 清空过程，**When** 数据层延时清数据（现状 400ms 编排），**Then** 停声与清数据时序保持现状不回归

### User Story 2 - 设置页退场胶囊时序重修（Priority: P1）

从设置页返回首页：MiniPlayer 胶囊在设置页**退场转场完全播完后**才开始上浮，不再压在退场页面上层突然弹出。R3 US3 的修复依赖「`onHidden` 在退场转场播完后触发」的假设——真机实测该假设不成立（`onHidden` 在退场开始时即触发），本轮换机制重修。进入设置页时的即时隐藏行为保持。

**Why this priority**: 每次进出设置页都可见的观感瑕疵，且已历经一轮修复无效，用户二报。

**Independent Test**: 打开设置页→返回→慢放观察：退场滑出动画全程胶囊不可见，动画完全结束后胶囊才平滑上浮。

**Acceptance Scenarios**:

1. **Given** 首页胶囊可见，**When** 进入设置页，**Then** 胶囊即时平滑隐藏（现状保持）
2. **Given** 在设置页，**When** 返回首页，**Then** 退场动画期间胶囊零出现，动画播完后胶囊平滑上浮
3. **Given** 从设置页推入日志页，**When** 观察胶囊，**Then** 现状时序行为保持（仅后移，不产生新的压动画问题）
4. **Given** 快速连续进出设置页，**When** 观察胶囊，**Then** 显隐状态始终正确，无定时器竞态导致的错乱（该隐藏时隐藏/该显示时显示）

---

### User Story 3 - 按压反馈机制重做（Priority: P2）

设置页**全体行**（SettingsRow：含 toggle 行、开 sheet 行、开页面行、危险操作行等）的按压反馈改为可靠机制：按压时背景加深，松手/点击完成后**必然消失**，无一卡死。现状：`stateStyles({ pressed })` 背景加深在真机上点击瞬间即卡住不消失，属机制设计缺陷——用户确认设置页都有，需设计级重做。使用同款按压反馈模式的其他列表行（首页订阅行/队列行/播放历史行）同步换用新机制，保持全局一致。

**Why this priority**: 每次点按设置页都会触发的观感 bug，机制级缺陷随交互频率放大；但纯视觉、不影响功能正确性，列 P2。

**Independent Test**: 设置页逐行走查（点按每一类行）：按压加深、松手即消，无一残留；再抽查首页/队列/历史行同样表现。

**Acceptance Scenarios**:

1. **Given** 设置页任一行，**When** 按住，**Then** 行背景加深；松手后立即恢复原色，无残留
2. **Given** 点按后打开 sheet/页面/弹窗的行（播放历史/日志/关于/音质等），**When** 返回后观察该行，**Then** 无按压高亮残留
3. **Given** toggle 行/危险行（退出登录等），**When** 点按，**Then** 按压反馈同样松手即消
4. **Given** 按住行不放并滚动列表，**When** 手指移动触发滚动，**Then** 按压态取消（与系统列表行为一致）
5. **Given** 首页订阅行/队列行/历史行，**When** 按压，**Then** 新机制下按压反馈正常（加深、松手即消、不回归左滑与长按）

### User Story 4 - 左滑删除按钮左右等距（Priority: P3）

三处左滑删除按钮（首页订阅/设置页播放历史/队列）在左滑**停留位**（按钮完全露出的静止态）改为左右等距：现状按钮左侧 0 间距贴住行内容、右侧 16vp 距行缘，不对称（首页圆角卡片背景下最显眼）；改后按钮与两侧间距相等。触发交互（图标点击 + 滑过阈值 + 二次确认）保持不变。

**Why this priority**: 纯视觉对齐打磨，不影响功能。

**Independent Test**: 三处分别左滑到停留位：按钮与左侧行内容、右侧行缘间距目测相等；三处视觉一致。

**Acceptance Scenarios**:

1. **Given** 首页订阅行，**When** 左滑到停留位，**Then** 删除按钮左右间距相等
2. **Given** 设置页播放历史行 / 队列行，**When** 左滑到停留位，**Then** 同样左右等距，三处一致
3. **Given** 左滑露出按钮，**When** 点击按钮或滑过阈值，**Then** 二次确认弹窗照常弹出（交互不变）

### Edge Cases

- US1 清空时队列面板处于多选模式：面板关闭自动退出多选（既有 `@Monitor` 链路不回归）
- US1 清空确认后 400ms 内用户再开队列/浮层：新开行为正常，不被延时清数据打断出错（清数据幂等）
- US2 设置页退场转场时长无公开 API 可读，按系统默认转场时长定值（Phase 2 校准）；快速往返设置页的显隐竞态必须消解（后触发的翻转胜出）
- US3 新按压机制不得影响：行点击、左滑手势、长按菜单/长按多选、Toggle 开关、滚动取消按压
- US3 按压色沿用既有 `item_pressed_background`（深浅色资源不变），仅换触发机制
- US4 等距间距值复用既有令牌（TOKEN_SPACE_M 量级），不新增魔法数字；`SwipeActionItem` 已知平台行为（触发区延伸整行、多行互斥收起）保持现状不处理

## Requirements

### Functional Requirements

- **FR-001**: 播放浮层内清空队列确认后，两层退出全程 MUST NOT 在首页层出现第二个队列面板实例，且退出 MUST 经由完整转场（浮层滑出），无瞬间卸载跳变
- **FR-002**: 首页层队列实例（无浮层）清空行为 MUST 保持现状（面板滑出关闭）；清空后全局队列状态 MUST 复位（`AS_SHOW_QUEUE_SHEET` 为 false），后续开关正常
- **FR-003**: 从设置页返回首页时 MiniPlayer 胶囊 MUST 在设置页退场转场完全结束后才开始上浮；进入设置页的即时隐藏保持；从设置页推入其他页面时现状时序行为不回归
- **FR-004**: 设置页全体行的按压反馈 MUST 松手/点击完成后可靠消失（0 卡死），机制为设计级重做；按压中滚动列表 MUST 取消按压态
- **FR-005**: 使用同款按压反馈模式的列表行（首页订阅/队列/播放历史）MUST 同步换用新机制且点击、左滑、长按行为零回归
- **FR-006**: 三处左滑删除按钮停留位 MUST 左右等距且三处一致；触发与二次确认交互保持现状

### Key Entities

无新增持久化实体。涉及现有全局键：`AS_SHOW_QUEUE_SHEET`/`AS_SHOW_PLAYER_OVERLAY`（清空编排）、`AS_ON_SETTINGS_PAGE`（胶囊显隐）、`item_pressed_background`（按压色，沿用）；`SettingsRow`（设置页行组件，按压机制宿主）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 播放浮层内清空队列连续 10 次，0 次出现队列面板二次闪现或无动画跳变
- **SC-002**: 设置页往返 10 次（含快速往返），胶囊 100% 在退场动画结束后才出现，显隐状态零错乱
- **SC-003**: 设置页逐类行点按走查（≥8 类：toggle/开 sheet/开页面/危险行等），按压高亮 100% 松手即消；首页/队列/历史行抽查同样通过
- **SC-004**: 三处左滑删除按钮停留位左右间距相等，三处走查一致
- **SC-005**: `devecocli build` 通过（验证范围 Phase 3 定，默认 build-only）

## Assumptions

- US1 修复方向（Phase 2 细化）：浮层内实例清空时队列面板不再走「滑出 + 延时卸载」路径，随浮层一次性退出；数据层「停声先行 + 400ms 延时清数据」编排保持现状
- US2 不再依赖 `onHidden` 的触发时机假设，改用显式时序控制；具体机制（定值延时 vs 转场回调）Phase 2 定
- US3 新机制优先查证 ArkUI 既有能力（触摸态驱动/属性修改器等），不引入新依赖；按压色资源不变
- US4 等距间距值与既有令牌体系对齐，具体数值 Phase 2 定
- 四项均为纯 UI/交互修复，不动数据模型、持久化、播放链路

## R4 真机验收迭代记录（[turn_1ptr50] + [turn_1a6tx2]）

真机自测结果与修订：**US1（清空闪现）✅ 通过**；**US2（胶囊时序）❌ 回归**——从设置页退出后胶囊消失；**US3（按压反馈）❌ 全部失效**——hdsEffect 白色混合在浅色/深色模式均不可见（非模式问题，机制整体失效）；**US4（左滑等距）✅ 间距通过**，阴影需求撤销（用户决定不做，无改动）。

### 修订内容（覆盖对应原 FR/验收）

- **US2**（修订 FR-003）：胶囊「消失」回归根因——R4 实现中 `onWillDisappear` 取消了 `onHidden` 排定的复位定时器，`AS_ON_SETTINGS_PAGE` 卡 true。修订：复位定时器改由 **`onWillDisappear`** 排定（pop 退场与被覆盖两路径必触发），`onWillAppear`/`onShown` 置位前取消 pending 的竞态消解与补置位保留。验收追加：**退出设置页后胶囊 MUST 重新上浮出现**（不再消失）。
- **US3**（修订 FR-004/FR-005）：`hdsEffect.pressShadow(BLEND_WHITE)`（背景混 15% 白）浅色/深色均不可见，机制整体失效，作废。修订：改**可见背景加深**按压反馈，**手动触摸态驱动**（onTouch Down 置按压态 / Up、Cancel 清除 + 状态切换背景色），不依赖 stateStyles/hdsEffect 的平台按压状态机；恢复按压色资源 `item_pressed_background`（base `#12000000` / dark `#14FFFFFF`）。
- **US4**（FR-006）：等距修复真机验收通过，保持现状；「加阴影」需求撤销（无代码改动）。
- **US1**（FR-001/FR-002）：通过，无改动。
- **US5（新增，[turn_1vf34w]）**：播放页播放/暂停切换动画变长。根因：R3 将封面光晕从「无限呼吸」收敛为「一次性过渡」后，淡入时长沿用 `GLOW_FADE_IN_MS = 3200ms`——点按播放时图标即时切换，但光晕需 3.2s 才到峰值，切换反馈被拖长；v0.4.0 取色轮放大光晕后更显眼。修订：`GLOW_FADE_IN_MS` 3200 → **500ms**，与封面亮度（400ms）/缩放（350ms）动画同量级。**注意**：`PlayerOverlay.ets` 含 v0.4.0 在途未提交改动（取色/光晕放大/顶栏骨架），本项仅改该常量值一处，不触碰其他代码。
