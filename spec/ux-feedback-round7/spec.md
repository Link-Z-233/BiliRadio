# Feature Specification: UX 反馈第 7 轮（R7）

**Created**: 2026-10-09  
**Status**: Draft  
**Input**: User description: "第 7 轮 UX 反馈：① 平板上 UP 主订阅触底加载完全无反应（API 24 真机，手机 API 26 正常）；② 源页时间不显示年份；③ 日志查询页与设置页一样整页重写为 HarmonyOS 系统风格（原为半模态组件套薄壳，两行标题+底部留空，功能保留）；④ 播放历史拉到底背景分层＋顶部加到顶提醒＋移除下拉关闭（只留空白点击关闭）；⑤ 已播图标换回圆圈对号只改颜色为绿色；⑥ 设置页整体重写为 HarmonyOS 系统风格（吸收原「设置页色差」「设置页过冲提示」两项反馈，交互结构可重组，功能全部保留）；⑦ 首页新视频徽标打开源页后不消除；⑧ 首页无滚动过冲提醒；⑨ 排查中新发现：APP 接口取流稀疏（订阅列表缺约一半投稿）＋翻页窗口漂移致乱序，一并修复。首页视觉本轮不动（看完设置页重写效果再定）。"

## Overview

本轮修复用户在第 6 轮构建包实测中报告的功能与视觉缺陷：UP 主订阅触底加载在真机平板静默失效（根因已定位）、订阅取流稀疏与乱序、首页新视频徽标不消除、时间显示缺年份，并将设置页与日志查询页整页重写为 HarmonyOS 系统风格。核心目标：订阅内容完整、时序正确、加载永不静默，徽标行为符合直觉，设置与日志页面达到系统级视觉品质。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - UP 订阅触底加载永不静默 (Priority: P1)

用户在任意设备（含 API 24 平板）打开一个已缓存的 UP 主订阅源页，滚动到列表底部想听更早的节目。无论应用内部取流链路处于何种状态（APP 签名链游标存在/不存在、刷新曾否失败），触底都必须产生可见结果：加载出更早内容，或明确提示没有更多，或提示加载失败。绝不出现「完全无反应」。

**Why this priority**: 触底加载是核心收听路径（用户听完已缓存节目后获取更早节目的唯一方式），当前在真机平板上完全失效，属功能性阻断缺陷。

**Independent Test**: 在无 APP 游标状态下（冷启动且自动刷新走 Web 退避链）打开 UP 订阅源页，触底后应能通过 Web 翻页链路加载出更早内容。

**Acceptance Scenarios**:

1. **Given** UP 主订阅缓存 20 条（不足单页阈值）、APP 签名链游标不存在（如 APP 链被风控拒绝、或刷新失败），**When** 用户滚到列表底部继续上拉，**Then** 应用通过 Web 翻页链路加载更早视频并追加到列表，可见集数增加。
2. **Given** UP 主订阅确实已无更早投稿，**When** 用户触底过冲，**Then** 显示「没有更多了」提示。
3. **Given** 翻页请求失败（网络/风控），**When** 用户触底，**Then** 显示加载失败 toast，且 3 秒冷却后可重试（既有行为保持）。

---

### User Story 2 - 订阅列表内容完整且时序正确 (Priority: P1)

用户订阅一位高产 UP 主（如罗翔说刑法，周更 2-3 条），期望源页列表包含该 UP 主的全部公开投稿，按发布时间从新到旧排列，不缺失、不乱序。当前 APP 接口取流约隔条缺失（罗翔 9-19、9-13、8-28、8-22 等真实视频不在列表中），且翻页追加偶发把时间序更晚的条目拼到列表尾部（9 月视频出现在 3 月视频之后）。

**Why this priority**: 播客订阅的内容完整性是产品根基——缺失一半投稿意味着用户漏听节目，乱序破坏「新在上」的浏览语义，均属数据正确性缺陷。

**Independent Test**: 打开罗翔说刑法源页，列表应包含其 9 月中旬的投稿（如 9-19、9-13），且任意相邻两条的时间序均为降序。

**Acceptance Scenarios**:

1. **Given** 订阅罗翔说刑法并完成刷新，**When** 用户浏览列表，**Then** 9-19、9-13 等当前缺失的投稿出现在列表中且位置符合时间降序。
2. **Given** 触底加载追加多页内容，**When** 追加完成，**Then** 全列表仍严格按发布时间降序排列（跨链路合并不产生乱序）。
3. **Given** 追加页返回的条目与现有列表全部重复，**When** 追加处理完成，**Then** 列表内容与顺序不变，且下一次触底继续尝试后续页（不重复卡死在同一页）。

---

### User Story 3 - 时间显示往年带年份 (Priority: P1)

用户浏览源页列表，期望时间戳能区分历史年份：当天的节目显示 `HH:mm`，当年的节目显示 `M-d HH:mm`，往年（含跨年翻页加载的旧节目）显示 `YYYY-M-d HH:mm`。当前所有条目一律 `M-d HH:mm`，往年节目（如 2025-12-15）与当年混淆。

**Why this priority**: 触底加载打通后用户会频繁浏览跨年旧内容，年份缺失直接造成时间误读，且改动小收益大。

**Independent Test**: 罗翔源页翻页加载到 2025 年 12 月的节目，时间应显示如「2025-12-27 10:40」。

**Acceptance Scenarios**:

1. **Given** 节目发布于今天，**When** 列表渲染，**Then** 时间显示 `HH:mm`。
2. **Given** 节目发布于今年但非今天，**When** 列表渲染，**Then** 时间显示 `M-d HH:mm`。
3. **Given** 节目发布于往年，**When** 列表渲染，**Then** 时间显示 `YYYY-M-d HH:mm`（如 2025-12-27 10:40）。

---

### User Story 4 - 首页新视频徽标可靠清除 (Priority: P1)

用户在首页看到某订阅的未读数字徽标，点进该订阅源页后返回，徽标应清除。当前徽标经常不消除：打开应用后后台自动刷新尚在进行时（多订阅逐个刷新耗时数秒），用户立即点进源页，源页已记录「已读时间」；但首页后台刷新回调会把内存中的陈旧「已读时间」写回持久化存储，覆盖刚更新的值，导致返回首页后徽标复活，且跨重启持续存在。

**Why this priority**: 未读徽标是用户决定打开哪个订阅的核心信号；「看了却不消失」直接破坏信任，且随启动刷新必然触发，属高频确定性缺陷。

**Independent Test**: 打开应用后立即点进带徽标的订阅再返回，徽标清除且重启应用后不再出现。

**Acceptance Scenarios**:

1. **Given** 首页后台自动刷新进行中，某订阅带未读徽标，**When** 用户点进该源页后返回首页，**Then** 徽标清除。
2. **Given** 徽标清除后用户重启应用，**When** 首页渲染，**Then** 该徽标不再出现（除非确有更新的投稿）。
3. **Given** 后台刷新期间用户在源页内停留，**When** 刷新全部完成，**Then** 已读时间的更新不被任何回写覆盖。
4. **Given** 新增订阅触发的自动刷新回调执行，**When** 用户同时访问过其他源页，**Then** 其他订阅的已读状态同样不被覆盖。

---

### User Story 5 - 日志查询页整页重写为 HarmonyOS 系统风格 (Priority: P2)

用户从设置页进入「日志查询」，期望获得与重写后设置页一致的 HarmonyOS 系统风格整页体验。当前页面是历史包袱：最初（第 3 轮）作为设置页内的半模态组件实现（sheet 布局自带标题行与操作按钮），第 6 轮仅套了一个导航薄壳变成二级页，布局原封未动——导致顶部两行标题（导航标题+组件自带标题）与底部大片留空。本轮整页重写：独立整页布局，风格与新设置页统一；既有功能全部保留——日志列表（时间、类别标签、摘要、结果）、导出日志文件、清空内存日志、空态提示、大数据量流畅滚动。

**Why this priority**: 日志页是排障关键入口，当前布局缺陷（两行标题、底部留空）是原项目布局残留的直接暴露；与设置页同期重写可共享设计语言，边际成本低。

**Independent Test**: 进入日志查询页，呈现整页新布局（单标题、内容到底），列表/导出/清空/空态功能可用。

**Acceptance Scenarios**:

1. **Given** 用户从设置页进入日志查询，**When** 页面渲染，**Then** 呈现 HarmonyOS 系统风格整页布局，标题区单行，与新设置页视觉语言一致。
2. **Given** 日志条目足够多，**When** 列表渲染，**Then** 内容延伸到底部，无异常留空，滚动流畅。
3. **Given** 用户点击导出，**When** 系统保存器完成，**Then** 日志文件导出成功（行为与重写前一致）。
4. **Given** 用户点击清空，**When** 操作完成，**Then** 列表清空并显示空态提示（仅清内存缓冲，不影响业务数据——行为与重写前一致）。

---

### User Story 6 - 播放历史面板交互与视觉修复 (Priority: P2)

用户打开播放历史面板（半模态），期望：① 到底继续下拉过冲时，过冲区域背景与列表背景一致（当前两层背景颜色不同产生「分层」断裂感）；② 拉到顶部继续下拉时出现到顶提醒提示（与源页一致的过冲提示）；③ 面板不支持下拉关闭手势（当前半模态默认下拉即关闭，易误触），仅保留点击面板外空白区域关闭。

**Why this priority**: 播放历史是高频回听入口，误触下拉关闭与视觉断裂直接打断操作流，但均有替代路径（重新打开面板），不阻断功能。

**Independent Test**: 打开播放历史面板，下拉过冲不关闭面板且显示到顶提醒；点击面板外空白区域可关闭。

**Acceptance Scenarios**:

1. **Given** 播放历史面板打开，**When** 用户在列表顶部继续下拉过冲，**Then** 面板不关闭，显示到顶提醒提示。
2. **Given** 播放历史面板打开且列表已到底，**When** 用户继续上拉过冲，**Then** 过冲区域背景与列表背景颜色一致，无分层断裂。
3. **Given** 播放历史面板打开，**When** 用户点击面板外的空白（蒙层）区域，**Then** 面板关闭。
4. **Given** 播放历史面板打开，**When** 用户在面板内按住列表下拉，**Then** 面板不因下拉手势关闭。

---

### User Story 7 - 已播图标回退为绿色圆圈对号 (Priority: P2)

用户在源页/历史中查看已播放标记，期望图标为圆圈对号轮廓样式（第 6 轮改动前样式），仅颜色改为绿色以示区分。当前第 6 轮实现改成了实心对号样式，用户要求换回。

**Why this priority**: 纯视觉偏好调整，不影响任何功能。

**Independent Test**: 播放过的条目图标显示绿色圆圈对号。

**Acceptance Scenarios**:

1. **Given** 某集已听完（进度哨兵 -1），**When** 列表渲染该条目，**Then** 图标为圆圈对号样式且颜色为绿色。

---

### User Story 8 - 设置页整页重写为 HarmonyOS 系统风格 (Priority: P2)

用户进入设置页，期望获得贴近 HarmonyOS 系统设置的观感：大标题、分组卡片、系统控件语言（开关、箭头行等），交互结构可重新组织（分组/层级/文案可调整）。现有设置页的全部功能项与入口必须保留且行为不变。本轮吸收原两项反馈：页面背景与底部系统条区域颜色一致（深浅模式均无色差）；列表顶部/底部过冲显示提醒提示。

**Why this priority**: 设置页是功能入口枢纽，视觉品质直接影响应用精致感；当前在原项目风格上演改多年积累出风格不纯、色差等问题，修补不如重写。但功能无损是硬约束。

**Independent Test**: 深浅两种模式下进入设置页，各功能项可达可用，无背景色差，过冲有提示。

**Acceptance Scenarios**:

1. **Given** 用户进入设置页，**When** 页面渲染，**Then** 呈现 HarmonyOS 系统风格（大标题、分组卡片、系统控件语言）。
2. **Given** 现有设置页任一功能项（登录、音质、主题、播放历史、睡眠定时、日志查询、关于等），**When** 用户在新设置页中定位并操作，**Then** 功能可达且行为与重写前一致。
3. **Given** 系统处于深色或浅色模式，**When** 用户进入设置页，**Then** 页面背景与底部系统小横条区域颜色一致，无色差分界。
4. **Given** 设置页滚动到顶部或底部边缘，**When** 用户继续拉拽过冲，**Then** 显示对应到顶/到底提醒提示。

---

### User Story 9 - 首页滚动过冲提醒 (Priority: P2)

用户在首页订阅列表滚到顶部或底部边缘继续拉拽时，期望出现与源页一致的过冲提醒提示（复用既有提示组件），替代当前系统默认的弹簧过冲效果。首页视觉风格本轮不动。

**Why this priority**: 与设置页/源页的过冲提示视觉语言统一，改动小；但首页本轮不改版，仅补齐交互反馈。

**Independent Test**: 首页顶部/底部过冲时分别显示到顶/到底提示文字。

**Acceptance Scenarios**:

1. **Given** 首页列表已滚到顶部，**When** 用户继续下拉过冲，**Then** 显示到顶提示。
2. **Given** 首页列表已滚到底部，**When** 用户继续上拉过冲，**Then** 显示到底提示。

---

### Edge Cases

- UP 主投稿总数不足一页（如新 UP 主只有 5 条投稿）时，触底应提示「没有更多了」而非反复发起无效请求。
- 翻页返回整页重复条目（跨链路窗口重叠）时，须推进页号避免死循环卡在同一页。
- Web 翻页链路被风控拦截（-352/-412）时，保持既有失败 toast + 3 秒冷却行为。
- 跨年翻页加载的旧条目时间显示须带年份；恰好跨年时刻（元旦附近）当天/当年判定按设备时区正确计算。
- 播放历史为空时打开面板：过冲提示、关闭交互仍应正常。
- 移除历史面板下拉关闭后，须保证仍有明确可达的关闭方式（蒙层点击），不产生「无法关闭」死角。
- 首页后台刷新与源页「已读」写入并发时，任何刷新回调都不得覆盖更新的已读时间。
- 日志为空时新日志页须正常显示空态；导出/清空行为与重写前一致（清空仅清内存缓冲）。
- 设置页/日志页重写后，「播放历史」入口进入的半模态面板保持既有行为与 R7 内其他修复结果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: UP 主订阅源页在缓存非空时即允许触底加载尝试，不得以缓存条数阈值或内存态游标存在与否作为唯一使能条件。
- **FR-002**: UP 主订阅触底加载在无 APP 游标时必须自动降级到 Web 翻页链路；Web 翻页页号必须与当前已展示条数对齐，不得跳过未展示的视频。
- **FR-003**: 触底加载在确认无更早内容后，过冲时必须显示「没有更多了」提示；失败时必须显示失败 toast 并保留冷却重试机制。
- **FR-004**: UP 主订阅列表必须包含该 UP 主接口可获取的全部公开投稿，不得因单一取流链路的稀疏窗口缺失约半数条目（验证案例：罗翔说刑法 9-19、9-13 投稿必须出现）。
- **FR-005**: 订阅列表（缓存与追加合并后）必须严格按发布时间降序排列；跨链路（APP 链/Web 链/翻页）合并的内容必须重排后再渲染。
- **FR-006**: 翻页返回条目与现有列表全部重复时，必须推进页号，保证后续触底继续尝试下一页，不得重复请求同一页。
- **FR-007**: 时间戳显示规则：当天 `HH:mm`；当年非今天 `M-d HH:mm`；往年 `YYYY-M-d HH:mm`。
- **FR-008**: 首页订阅行的未读徽标在用户进入对应源页后必须清除；清除后跨应用重启不得复现（除非确有更新投稿）。
- **FR-009**: 首页任何后台刷新或订阅变更回调写入订阅数据时，不得用陈旧的内存副本覆盖持久化存储中更新的「已读时间」字段。
- **FR-010**: 日志查询页必须整页重写为 HarmonyOS 系统风格（与新设置页视觉语言一致）：单行标题、内容延伸到底部、无异常留空。
- **FR-011**: 日志查询页重写必须保留既有功能且行为不变：日志列表展示（时间、类别标签、摘要、结果）、导出日志文件、清空内存日志（仅内存缓冲）、空态提示、大数据量懒加载流畅滚动。
- **FR-012**: 播放历史面板顶部过冲区域背景必须与列表背景颜色一致（深浅两种模式下均成立）。
- **FR-013**: 播放历史面板顶部过冲必须显示到顶提醒，底部过冲必须显示到底提醒（复用过冲提示组件）。
- **FR-014**: 播放历史面板必须移除下拉关闭手势；必须保留点击面板外空白区域关闭。
- **FR-015**: 已播放标记图标必须为圆圈对号样式，颜色为绿色（沿用主题色体系）。
- **FR-016**: 设置页必须整页重写为 HarmonyOS 系统风格：大标题、分组卡片、系统控件语言；交互结构（分组/层级/文案）允许重组。
- **FR-017**: 设置页重写必须保留重写前全部功能项与入口，且各项行为不变。
- **FR-018**: 设置页背景必须与底部系统条区域背景颜色一致，深浅两种模式下均无色差。
- **FR-019**: 设置页顶部/底部过冲必须显示对应提醒提示（复用过冲提示组件）。
- **FR-020**: 首页订阅列表顶部/底部过冲必须显示对应提醒提示（复用过冲提示组件），首页视觉风格本轮不变。

### Key Entities *(include if feature involves data)*

- **订阅源页列表（episodes）**: 缓存条目 + 触底追加条目的合并视图；本轮起须保证完整性与时间降序不变量。
- **UP 主翻页链路状态**: APP 签名链游标（内存态）与 Web 页号链路的分派关系；游标缺失不再是加载阻断条件。
- **订阅已读时间（lastSeenAt）**: 未读徽标的计算基准；源页进入时更新，任何后台回写不得覆盖更新的值。
- **时间格式化输出**: 按条目发布时间与当前时间的关系输出三态格式（当天/当年/往年）。
- **播放历史面板**: 半模态容器；本轮调整其关闭手势、过冲提示与背景一致性。
- **设置页 / 日志查询页**: 整页重写的目标载体；功能清单保持、视觉与交互结构重排。

## Assumptions

- B 站 APP 端点取流稀疏是服务端固有行为，客户端无法通过请求参数修正单页内容；完整性修复依赖链路选择或双链路合并补全（具体方案在架构设计阶段决定）。
- SEASON/SERIES/FAV 订阅的既有触底加载语义（门槛、短页终止规则）本轮不改动。
- 「移除下拉关闭」仅指列表内下拉手势不再触发半模态关闭；点击蒙层空白关闭与系统返回手势不受影响。
- 已播图标绿色沿用既有主题色 token（不新造硬编码色值）。
- 设置页与日志页重写沿用现有主题色/深浅模式体系与既有关键色 token；原 LogSheet 半模态组件可随重写退役合并（实现细节由架构阶段定）。
- 播放历史面板本轮仅应用各自修复项，不随设置页重写改版。
- 首页本轮仅修徽标缺陷与补过冲提示，视觉改版待设置页重写效果确认后另立轮次。
- 本轮不处理第 6 轮遗留的弃用 API 迁移（AlertDialog.show/showToast/matchMediaSync）。
