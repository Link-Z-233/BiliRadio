# Feature Specification: UX 反馈第 5 轮修复（订阅 / 播放 / 设置共 14 项）

**Created**: 2026-10-06  
**Status**: Draft  
**Input**: User description: "1.添加订阅源去掉'视频/UP主/收藏夹/合集/系列'长提示；2.'载入'改'查询'；3.添加订阅页动画缺失；4.纯数字输入行为；5.'省流量模式'改'无图模式'；6.退出设置页后播放胶囊延迟突现；7.'取消收藏历史'无用；8.播放历史点击条目后返回行为异常（需两次返回）；9.播放列表返回键退出无动画；10.多选按钮前后尺寸不一致；11.已播放/未播放格式差异；12.添加订阅封面不加载且默认封面不一致；13.订阅源列表改新上旧下+触底加载；14.无图模式下播放列表与系统播控仍有封面"

## Overview

本特性针对用户实测反馈的 14 项体验问题进行集中修复，覆盖四大区域：

1. **添加订阅半模态**：简化输入提示文案、查询按钮更名、支持 av 号输入、查询结果与二级视图补齐过渡动画、修复封面加载与统一默认占位。
2. **订阅源详情页**：内容列表对齐 B 站 UP 投稿列表交互（新上旧下、触底加载更早），已播放条目改用明确的已播标记。
3. **播放链路**：修复"播放历史 → 播放浮层"的返回键行为（一次返回退出播放页）、播放列表返回键退出补滑出动画、多选按钮尺寸统一、设置页返回后播放胶囊平滑出现。
4. **设置页**："省流量模式"更名为"无图模式"并扩展生效范围至播放列表与系统播控，彻底移除无用的"取消收藏历史"。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 订阅源列表对齐 B 站投稿列表交互 (Priority: P1)

用户打开订阅源详情页，希望像浏览 B 站 UP 主投稿列表一样：最新内容在最上方，向下滚动到底部时自动加载更早的内容；已播放过的条目显示一个明确的"已播"标记（取代目前仅标题变灰的做法），标题颜色与未播放条目一致。

**Why this priority**: 订阅源浏览是应用最高频的核心场景，排序方向与翻页方式直接决定基础体验。

**Independent Test**: 打开任一已有缓存的订阅源即可完整验证排序、触底加载与已播标记，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 订阅源已有缓存内容, **When** 打开订阅源详情页, **Then** 列表第一条为最新发布的内容（新上旧下）
2. **Given** 列表已展示当前缓存内容, **When** 滚动至列表底部, **Then** 自动加载更早一页内容并无缝追加在下方
3. **Given** 某条目存在于播放历史中, **When** 查看列表, **Then** 该条目显示明确已播标记，且标题颜色与未播放条目一致
4. **Given** 订阅源详情页, **When** 点击右上角手动刷新, **Then** 刷新成功后列表回到最新内容（既有功能不回归）
5. **Given** 订阅源内容不足一页, **When** 滚动到底, **Then** 不出现重复加载或异常

---

### User Story 2 - 添加订阅：输入识别与文案优化 (Priority: P1)

用户在添加订阅输入框输入内容：提示文案不再罗列"视频/UP主/收藏夹/合集/系列"长串（显示不全），改为简短提示；查询按钮由"载入"改为"查询"；输入带 av 前缀的视频号（如 av10）时识别为视频并播放；纯数字输入视为 UP 主 UID 进行查询。既有 BV 号、各类链接、短链识别行为不变。

**Why this priority**: 添加订阅是应用的入口能力，输入识别准确性与文案清晰度影响新用户上手。

**Independent Test**: 打开添加订阅面板，分别输入 av 号、纯数字、BV 号、链接逐一验证，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 添加订阅面板打开, **When** 查看输入框, **Then** 提示文案为简短提示（不再包含"视频/UP主/收藏夹/合集/系列"长串）
2. **Given** 查询按钮, **When** 面板任意状态, **Then** 按钮文案显示"查询"（加载中状态照旧显示加载指示）
3. **Given** 输入 `av10`（大小写均可）, **When** 点击查询, **Then** 识别为视频号 av10 并加入播放
4. **Given** 输入纯数字, **When** 点击查询, **Then** 作为 UP 主 UID 查询（成功显示 UP 信息，失败保持现有错误提示）
5. **Given** 输入 BV 号或任意支持的链接/短链, **When** 点击查询, **Then** 识别与订阅/播放行为与现状一致（不回归）

---

### User Story 3 - 添加订阅：动效与封面修复 (Priority: P1)

用户在添加订阅面板查询后，UP 信息等查询结果以过渡动画出现而非瞬间弹出；进入"我的收藏夹"、UP 的合集/系列列表等二级视图时，有进出双向的层级转场动画。查询到的 UP 头像与合集/系列封面正常加载显示；无封面内容显示统一的默认占位样式（不因订阅类型不同而不同）。

**Why this priority**: 动效缺失与封面不加载是用户直接感知的"粗糙感"来源，且封面不加载影响订阅确认判断。

**Independent Test**: 打开添加订阅面板，查询一个 UP 主并进入其合集列表即可验证动效与封面，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 已输入有效 UID, **When** 查询成功, **Then** UP 信息区域以过渡动画出现（非瞬间弹出）
2. **Given** 查询成功显示 UP 信息, **When** 进入合集/系列二级列表, **Then** 二级视图以层级转场滑入；返回一级视图时有对应滑出转场
3. **Given** 已登录账号, **When** 打开"我的收藏夹"二级视图, **Then** 同样具备进出双向层级转场
4. **Given** 查询到的 UP/合集/系列含头像或封面 URL, **When** 结果展示, **Then** 头像/封面正常加载显示
5. **Given** 任一订阅类型无封面数据, **When** 结果展示, **Then** 显示统一风格的默认占位（不同类型占位样式一致）

---

### User Story 4 - 播放历史 → 播放浮层的返回行为修复 (Priority: P1)

用户在设置页打开播放历史面板，点击某条历史记录开始播放：播放浮层弹出，播放历史面板保持打开（位于浮层之下）。此后按一次系统返回键即退出播放浮层、回到播放历史面板；再按返回才关闭历史面板回到设置页。退出播放页不再需要按两次返回。

**Why this priority**: 返回键行为混乱是导航层缺陷，直接影响操作直觉，且修复范围独立明确。

**Independent Test**: 设置页 → 播放历史 → 点击条目 → 逐次按返回键验证层级关闭顺序，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 设置页播放历史面板已打开, **When** 点击某历史条目, **Then** 播放浮层弹出开始播放，历史面板保持打开状态
2. **Given** 播放浮层打开（历史面板在其下）, **When** 按一次返回键, **Then** 播放浮层关闭，回到播放历史面板（面板仍打开）
3. **Given** 已回到播放历史面板, **When** 再按返回键, **Then** 历史面板关闭，回到设置页
4. **Given** 其他入口（首页胶囊、队列等）打开的播放浮层, **When** 按返回, **Then** 既有关闭行为不回归

---

### User Story 5 - 无图模式：更名与全链路生效 (Priority: P2)

用户在设置页看到"省流量模式"更名为"无图模式"；开启后，播放列表中的条目封面与系统播控组件（锁屏/媒体控制中心）的封面均不再加载/显示，与播放胶囊、播放页的既有省图行为一致；关闭后恢复。

**Why this priority**: 命名与实际行为不符（开了仍见图）损害设置可信度，但属于既有功能的补全而非新能力。

**Independent Test**: 开关无图模式后分别检查播放列表封面与系统播控封面，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 设置页, **When** 查看该选项, **Then** 选项名显示"无图模式"
2. **Given** 无图模式开启, **When** 打开播放列表, **Then** 条目不加载封面，显示占位样式
3. **Given** 无图模式开启, **When** 播放内容并查看锁屏/系统媒体控制中心, **Then** 系统播控不显示封面
4. **Given** 无图模式关闭, **When** 播放列表与系统播控, **Then** 封面恢复正常加载显示
5. **Given** 切换无图模式开关, **When** 播放胶囊/播放页在播, **Then** 既有即时刷新行为不回归

---

### User Story 6 - 设置页清理与播放胶囊显隐修复 (Priority: P2)

用户不再在设置页看到无用的"取消收藏历史"选项（入口、面板及底层记录一并移除；播放页的"取消收藏"功能本身保留）。从设置页返回首页时，播放胶囊随返回过程即时、平滑地出现，不再"过一段时间后突然蹦出"；设置页在前台时胶囊仍保持隐藏。

**Why this priority**: 无用选项清理是减法改动风险低；胶囊突现是视觉瑕疵，两者都局限在设置页相关链路。

**Independent Test**: 进入/退出设置页观察胶囊出现时机与动画，检查设置项列表与播放页取消收藏功能，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 设置页, **When** 查看选项列表, **Then** 不存在"取消收藏历史"入口及对应面板
2. **Given** 播放页正在播放内容, **When** 执行取消收藏操作, **Then** 功能正常（仅历史记录展示被移除，不回归）
3. **Given** 正在播放且已进入设置页（胶囊隐藏）, **When** 返回首页, **Then** 播放胶囊随返回转场即时平滑出现（带过渡，无延迟突现）
4. **Given** 设置页在前台, **When** 播放状态任意, **Then** 胶囊保持隐藏（现状不回归）

---

### User Story 7 - 播放列表交互打磨 (Priority: P3)

用户通过系统返回键退出播放列表时，播放列表以滑出动画退出（与点击遮罩退出一致），不再瞬间消失；进入/退出多选模式时，操作行按钮尺寸前后一致，不发生跳变。

**Why this priority**: 纯体验打磨，功能无缺陷，优先级最低。

**Independent Test**: 打开播放列表，分别用返回键/遮罩退出对比动画；切换多选模式观察按钮尺寸，不依赖其他故事。

**Acceptance Scenarios**:

1. **Given** 播放列表打开, **When** 按系统返回键, **Then** 列表以滑出动画退出（与遮罩点击退出动画一致）
2. **Given** 播放列表普通模式, **When** 进入多选模式, **Then** 操作行按钮尺寸与普通模式一致（无高度跳变）
3. **Given** 多选模式, **When** 退出多选模式, **Then** 按钮尺寸同样保持一致
4. **Given** 播放列表打开, **When** 点击遮罩退出, **Then** 既有滑出动画不回归

### Edge Cases

- 订阅源内容不足一页或已到最早内容时，触底不触发重复加载、无死循环请求
- 触底加载请求失败时，给出可恢复的提示（重试或静默保持现状），不破坏已加载内容
- av 号对应的视频不存在时，沿用现有"添加失败"提示路径，不崩溃
- 纯数字 UID 查询触发 B 站风控（-352/-412）时，保持现有"疑似风控，建议登录"提示
- 播放浮层打开时从历史面板点击另一条目，应切换播放而不产生浮层叠加或返回栈异常
- 无图模式开启时添加订阅查询，UP 头像仍按 US3 正常加载（添加订阅场景不省图）
- 移除"取消收藏历史"后，旧的本地历史数据文件可遗留不读（无功能影响），不要求迁移清理

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 添加订阅输入框提示文案 MUST 简化为简短提示，不再罗列"视频/UP主/收藏夹/合集/系列"
- **FR-002**: 主操作按钮文案 MUST 由"载入"改为"查询"，点击行为与加载中状态不变
- **FR-003**: 系统 MUST 识别 av 前缀视频号（不区分大小写，如 av10）并播放对应视频
- **FR-004**: 纯数字输入 MUST 视为 UP 主 UID 进行查询，查询结果与错误提示沿用现有逻辑
- **FR-005**: 查询结果内容（UP 信息等）出现时 MUST 带过渡动画，不得瞬间弹出
- **FR-006**: 添加订阅一级视图与二级视图（我的收藏夹、UP 合集/系列列表）之间切换 MUST 带双向层级转场动画
- **FR-007**: 添加订阅场景中 UP 头像、合集/系列封面 MUST 正常加载显示
- **FR-008**: 各订阅类型在无封面数据时 MUST 显示统一风格的默认占位（不同类型占位一致）
- **FR-009**: 订阅源详情列表 MUST 按发布时间新→旧排列（新上旧下）
- **FR-010**: 订阅源详情列表滚动到底部时 MUST 自动加载更早一页内容并无缝追加
- **FR-011**: 已播放条目 MUST 显示明确已播标记，标题颜色 MUST 与未播放条目一致
- **FR-012**: 设置项"省流量模式" MUST 更名为"无图模式"，相关分组标题同步调整
- **FR-013**: 无图模式开启时播放列表 MUST NOT 加载/显示条目封面（显示占位）
- **FR-014**: 无图模式开启时系统播控组件（锁屏/媒体控制中心）MUST NOT 显示封面
- **FR-015**: "取消收藏历史"设置项、对应面板及底层记录逻辑 MUST 彻底移除；"取消收藏"功能本身 MUST 保留
- **FR-016**: 从设置页返回时播放胶囊 MUST 随返回过程即时平滑出现（带过渡动画），无延迟突现
- **FR-017**: 播放浮层打开且历史面板在其下时，按一次返回键 MUST 仅关闭播放浮层并回到历史面板（面板保持打开）
- **FR-018**: 播放列表经系统返回键退出时 MUST 播放与遮罩点击一致的滑出动画
- **FR-019**: 播放列表多选模式开启/关闭前后操作行按钮尺寸 MUST 保持一致
- **FR-020**: 既有功能（BV/链接/短链识别、订阅刷新、NEW 徽标、队列多选操作、其他返回路径）MUST NOT 回归

### Key Entities *(include if feature involves data)*

- **Subscription**: 既有订阅实体；其详情列表的展示排序与分页方向调整（新→旧），缓存结构是否随之调整为实现细节
- **封面占位（CoverThumb 占位形态）**: 无封面或无图模式时统一展示的默认样式，全类型一致
- **UnfavoriteRecord（移除）**: 原"取消收藏历史"记录实体随功能一并移除，不再读写
- **播放历史面板与播放浮层**: 两者层级关系固定为"浮层在上、面板在下"，返回键按层级从上至下逐层关闭

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户反馈的 14 项问题全部修复，且验收清单中所有"不回归"条目验证通过
- **SC-002**: 打开订阅源详情页即可见最新内容；触底后 2 秒内完成更早一页的加载追加
- **SC-003**: 从播放历史发起播放后，单次按返回键即退出播放页
- **SC-004**: 无图模式开启后，播放列表与系统播控均无封面网络请求/展示
- **SC-005**: 添加订阅的所有二级视图进出均有可感知的层级转场动画

## Assumptions

- 输入框新提示文案为简短形式（如"粘贴链接 / UP 主 UID / av 号"，最终措辞实现时确定）
- 设置页原"省流量设置"分组标题同步改为与新名称匹配的标题；选项副标题按新语义微调
- 多选按钮统一后的具体尺寸取值由实现决定，以视觉前后一致为准
- 无图模式本轮扩展范围仅限用户点名的播放列表与系统播控；首页订阅行、订阅源详情页、添加订阅页的封面不在生效范围（保持现状）
- "拉到底刷新"按 B 站投稿列表惯例理解为触底自动加载更早内容；顶部手动刷新按钮保留
- 已播标记的具体形态（✓ 图标/角标）由实现决定，要求"明确可见"且取代灰色标题差异
- av 号播放复用现有 BV 添加并播放链路
- 移除"取消收藏历史"后遗留的本地数据文件不要求清理，应用不再读取即可

## Open Questions

- 无（14 项需求及处理方式均已通过澄清确认）
